#### Запишется ли новое имя пользователя в БД?
```java
@Transactional
public void doUser(id) {
    User user = userRepository.findById(id).orElseThrow();
	user.setName("NewName");
    // Метод завершается без исключения
    // Что будет? Запишется ли в БД user.name("NewName"); ???
}
```

#### Что произойдет: 
Да, новое имя запишется в базу данных автоматически.
Вам **не нужно** вызывать `userRepository.save(user)`.

#### Почему:
Вот как это работает под капотом (механизм называется **Dirty Checking** — проверка «грязных» объектов):

1. **Открытие транзакции:** При входе в метод прокси Spring открывает транзакцию и создает Persistence Context (кэш первого уровня Hibernate).    
2. **Переход в состояние Managed (Управляемый):** Когда вы вызываете `userRepository.findById(id)`, Hibernate делает `SELECT` в базу данных, достает данные, создает объект `User` и помещает его в свой Persistence Context. Теперь этот объект находится под наблюдением Hibernate. Hibernate делает скрытый «снимок» (snapshot) его первоначального состояния.    
3. **Изменение в памяти:** Вызов `user.setName("NewName")` просто меняет поле у Java-объекта в оперативной памяти.    
4. **Завершение метода:** Метод завершается без исключений. Прокси Spring начинает процедуру `commit` (фиксацию транзакции).    
5. **Flush и Dirty Checking:** Прямо перед коммитом Hibernate автоматически делает `flush`. Он берет все объекты из Persistence Context и сравнивает их текущее состояние с их первоначальным «снимком».    
6. **SQL UPDATE:** Hibernate видит, что поле `name` изменилось. Он автоматически генерирует SQL-запрос `UPDATE ... SET name = 'NewName' WHERE id = ?` и отправляет его в базу.    
7. **Commit:** Транзакция успешно фиксируется в БД.
