#### Кейс 4: Замороженный прототип (*Магия контекста Spring*)

#### Будут ли создаваться **новые** объекты?
```Java
@Component
@Scope("singleton")
public class WorkerManager {
	
    @Autowired
    private TaskWorker taskWorker; // Этот бин имеет @Scope("prototype")
	
    public void doWork() {
        System.out.println(taskWorker.hashCode());
    }
}
```

#### Что произойдет:
Если вы вызовете `workerManager.doWork()` десять раз, в консоль выведется **десять одинаковых хэш-кодов**. Бин `TaskWorker`, несмотря на скоуп `prototype` (*который должен создавать новый объект при каждом обращении*), будет вести себя **как синглтон**.

#### Почему:
1. Spring собирает зависимости на этапе создания бина.    
2. Когда создается `WorkerManager` (*а он синглтон, создается один раз при старте контекста*), Spring видит зависимость `TaskWorker`.    
3. Spring создает _один_ новый экземпляр `TaskWorker` и внедряет его в `WorkerManager`.  
4. Внедрение произошло один раз. При каждом вызове метода используется та самая единственная ссылка, внедренная при старте. Чтобы получить реальное поведение прототипа, нужно использовать `@Lookup` над геттером или инжектить `ObjectProvider<TaskWorker>`.
