### Будет-ли сохранен новый `User`?
```java
@Transactional
public void testSaveWithErrorHandling() {
    try {
        User user = new User("Алексей", 25);
        session.save(user); // Объект в кэше
        
        throw new RuntimeException("Ошибка!"); // Исключение
    } catch (Exception e) {
        // Проглотили
        System.out.println("Ошибка перехвачена, но мы ее съели");
    }
    // Метод завершается
    // Spring вызовет commit() -> flush() -> INSERT выполнится!
}
```
**В БД появится новый пользователь!** Потому что:
1. Ошибка перехвачена.    
2. Транзакция не откатилась.    
3. `flush()` при коммите выполнил INSERT.

---
### 1. Spring не видит ошибку

Механизм `@Transactional` работает через прокси. Spring решает, делать `commit` или `rollback`, **только на основании того, вылетело ли исключение за пределы метода**. Поскольку вы перехватили `RuntimeException` внутри блока `catch` и не пробросили его дальше (`throw e`), прокси Spring видит, что метод завершился успешно (штатно возвратил управление).

### 2. Транзакция не помечена как `rollback-only`

В отличие от вашего предыдущего примера (где была ошибка `constraint violation`), в этом коде база данных и сам Hibernate не столкнулись ни с какими проблемами. `RuntimeException`, который вы выбросили искусственно, никак не взаимодействует с внутренностями Hibernate. Поэтому флаг «только для отката» на транзакции не ставится.

### 3. Штатный коммит

Раз метод завершился без ошибок и метки `rollback-only` нет, Spring Proxy запускает процедуру успешного завершения транзакции:

1. Вызывается `commit()`.    
2. Под капотом происходит `flush()` кэша первого уровня.    
3. Hibernate видит, что в Persistence Context лежит новый, еще не сохраненный объект `User`.    
4. Генерируется и выполняется SQL-запрос `INSERT`.    
5. Данные фиксируются в БД.

> **Ключевое правило:** Spring откатывает транзакции по умолчанию только при **неперехваченных** (uncaught) `RuntimeException` или `Error`, которые долетели до самого прокси-объекта. Если вы «съели» ошибку внутри метода — для Spring её никогда не существовало.
