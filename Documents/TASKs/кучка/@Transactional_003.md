#### Кейс 3: Внутренний предатель (*Прокси-ловушка*)

#### Отработает ли откат транзакции?
```Java
@Service
public class UserService {
	
    public void processUserRegistration() {
        // Какая-то предварительная логика...
        saveToDb(); 
    }
	
    @Transactional
    public void saveToDb() {
        userRepository.save(new User("Иван"));
        throw new RuntimeException("Что-то пошло не так!"); // Имитация ошибки
    }
}
```

#### Что произойдет:
Данные **будут сохранены в БД**, несмотря на выброшенное исключение и аннотацию `@Transactional`. Никакого отката **не произойдет**.

#### Почему:
1. Spring управляет транзакциями через **AOP-прокси**.    
2. Когда внешний класс вызывает метод бина, он обращается к прокси-объекту, который открывает транзакцию, вызывает реальный метод, а затем коммитит или откатывает её.    
3. В этом примере метод `processUserRegistration()` (*без аннотации*) вызывает `saveToDb()` (*с аннотацией*) **внутри одного и того же класса** (*по ссылке `this`*).    
4. Вызов через `this` идет напрямую, минуя прокси-объект Spring. Механизм транзакций просто **не включается**.
