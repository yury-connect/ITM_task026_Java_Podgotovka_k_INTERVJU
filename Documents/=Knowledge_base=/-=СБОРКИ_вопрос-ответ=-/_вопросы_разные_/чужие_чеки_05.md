### ⚖️ 1. Comparable и Comparator

- 🏷️ **`Comparable<T>`:**
    
    - Задает **естественный порядок (Natural Ordering)** сортировки объекта.
        
    - Реализуется **внутри** самого класса через метод `compareTo(T o)`.
        
    - _Пример:_ `String`, `Integer` уже реализуют `Comparable`.
        
- ⚙️ **`Comparator<T>`:**
    
    - Задает **кастомную внешнюю стратегию** сортировки.
        
    - Реализуется в виде отдельного класса, анонимного класса или лямбды через метод `compare(T o1, T o2)`.
        
    - Поддерживает комбинацию правил через `thenComparing()`.
        

### 🛑 2. Главные минусы Comparable

1. 🔒 **Единственность стратегии:** Класс может иметь только один вариант естественной сортировки через `compareTo()`.
    
2. 🧱 **Жёсткая связность (Tight Coupling):** Нарушает принцип Open/Closed (SOLID) — чтобы изменить правила сортировки, нужно вносить изменения в исходный код бизнес-класса.
    
3. 🚫 **Невозможность модификации чужого кода:** Нельзя добавить `Comparable` к классам из сторонних библиотек или системных JAR-файлов, если разработчики библиотеки этого не сделали заранее.
    

### 🧩 3. Какие бывают функциональные интерфейсы

Функциональный интерфейс — интерфейс с **ровно одним абстрактным методом** (SAM). Основные типы из пакета `java.util.function`:

- 🔄 **`Function<T, R>`:** Принимает $T$, возвращает $R$ (метод `R apply(T t)`).
    
- 🎯 **`Predicate<T>`:** Принимает $T$, возвращает `boolean` (метод `boolean test(T t)`).
    
- 📥 **`Consumer<T>`:** Принимает $T$, ничего не возвращает `void` (метод `void accept(T t)`).
    
- 📤 **`Supplier<T>`:** Ничего не принимает, возвращает $T$ (метод `T get()`).
    
- ⚡ **Примитивные модификации:** `IntFunction`, `ToDoubleFunction`, `LongPredicate` (для исключения автоупаковки).
    
- 👥 **Бинарные версии:** `BiFunction<T, R U,>`, `BiPredicate<T, U>`, `BiConsumer<T, U>`, `UnaryOperator<T>`, `BinaryOperator<T>`.
    

### 🗺️ 4. Отличие map от flatMap

- 🟢 **`map(Function<T, R>)`:** Преобразование **1-в-1**. Применяет функцию к каждому элементу и возвращает `Stream<R>`.
    
- 🟣 **`flatMap(Function<T, Stream<R>>)`:** Преобразование **1-ко-многим**. Применяет функцию, которая возвращает стрим для каждого элемента, а затем «сплющивает» (flatten) получившиеся вложенные стримы в один плоский `Stream<R>`.
    

### 🌊 5. Методы стримов

- 🛠️ **Промежуточные (Intermediate / Lazy):** `filter()`, `map()`, `flatMap()`, `peek()`, `distinct()`, `sorted()`, `limit()`, `skip()`, `takeWhile()`, `dropWhile()`.
    
- ⚡ **Терминальные (Terminal / Eager):** `collect()`, `forEach()`, `reduce()`, `count()`, `findFirst()`, `findAny()`, `allMatch()`, `anyMatch()`, `noneMatch()`, `toArray()`, `min()`, `max()`.
    

### 🗺️ 6. Как сделать HashMap из стрима

Используется терминальный собиратель `Collectors.toMap()`:
```Java
Map<Long, User> userMap = users.stream()
    .collect(Collectors.toMap(
        User::getId,                                // Key mapper
        user -> user,                              // Value mapper
        (existing, replacement) -> existing        // Merge function (для разрешения конфликтов одинаковых ключей!)
    ));
```

### 🔒 7. Отличие Mutex от Semaphore

- 🔑 **Mutex (Mutual Exclusion):** Двоичный флаг. Обладает **концепцией владения (Ownership)**: разблокировать (release/unlock) мьютекс имеет право **только тот поток**, который его ранее заблокировал.
    
- 🚦 **Semaphore:** Имеет счетчик разрешений ($N$ permits). Не обладает концепцией владения: **любой поток** может вызвать `release()` и увеличить счетчик разрешений, взятых другим потоком.
    

### ⚛️ 8. Зачем нужны атомики и какие они бывают

Атомики обеспечивают **Lock-free потокобезопасность** на уровне аппаратной инструкции процессора **CAS (Compare-And-Swap)**, исключая переключение контекста ОС и блокировку потоков.

**Основные типы (`java.util.concurrent.atomic`):**

- 🔢 **Примитивные:** `AtomicInteger`, `AtomicLong`, `AtomicBoolean`.
    
- 🔗 **Ссылочные:** `AtomicReference`, `AtomicStampedReference` (решает ABA-проблему через штамп версии), `AtomicMarkableReference`.
    
- 📚 **Массивы:** `AtomicIntegerArray`, `AtomicReferenceArray`.
    
- 🚀 **Сумматоры при высокой конкуренции:** `LongAdder`, `DoubleAdder`, `LongAccumulator`.
    

### ⚠️ 9. Проблема стримов при Long и Double

1. 🐘 **Оверхед на автоупаковку (Autoboxing):** Использование `Stream<Long>` или `Stream<Double>` оборачивает каждый примитив в объект-обертку, что забивает Heap и нагружает GC.
    
    - _Решение:_ Использовать примитивные стримы `LongStream` и `DoubleStream`.
        
2. 🧮 **Потеря точности с плавающей точкой:** Операции `sum()` или `reduce()` над `DoubleStream` накапливают погрешность округления с плавающей точкой.
    
    - _Решение:_ Для точных финансовых расчетов использовать `BigDecimal` с `Stream<BigDecimal>`.
        

### 🪞 10. Рефлексия в Java (Reflection API)

Механизм, позволяющий исследовать и изменять структуру классов, полей, методов и конструкторов **во время выполнения приложения (Runtime)** без компиляционной проверки типов.

### 🔍 11. Что можно получить с помощью рефлексии

- Метаданные класса (имя, модификаторы, суперкласс, интерфейсы).
    
- Список полей и их значения (включая `private` через `field.setAccessible(true)`).
    
- Список методов и возможность их выполнения (`method.invoke()`).
    
- Конструкторы и возможность динамического создания объектов (`constructor.newInstance()`).
    
- Аннотации с политикой удержания `@Retention(RUNTIME)`.
    

### 💡 12. Как получить имя класса: есть ли метод getClass().getClassName()?

**Это вопрос-ловушка!** 🪤 У объекта `Class` **нет метода `getClassName()`**.

**Правильные способы:**
```Java
String fullName = obj.getClass().getName();        // com.example.MyClass
String simpleName = obj.getClass().getSimpleName();  // MyClass
String canonical = obj.getClass().getCanonicalName(); // com.example.MyClass
```

### 🧬 13. Ковариантность, контравариантность и инвариантность

Определяют, как наследование базовых типов влияет на наследование контейнеров/обобщений:

- 📐 **Инвариантность:** Дженерики в Java по умолчанию **инвариантны**. `List<Integer>` **не является** подтипом `List<Number>`, хотя `Integer` наследует `Number`.
    
- ⬆️ **Ковариантность (`? extends T` / PECS - Producer Extends):** Позволяет читать данные из контейнера. Массивы в Java ковариантны по умолчанию (`Integer[]` является подтипом `Number[]`), что исторически является источником Ошибок `ArrayStoreException`.
    
- ⬇️ **Контравариантность (`? super T` / PECS - Consumer Super):** Позволяет записывать данные в контейнер.
    

### 🧱 14. Отличие композиции от агрегации

Оба понятия описывают отношение **«has-a»** (содержит):

- 💥 **Композиция (Сильная связь):** Дочерний объект **не может существовать без родительского**. Родитель сам создает и контролирует жизненный цикл дочернего объекта.
    
    - _Пример:_ `Car` (Машина) и `Engine` (Двигатель). Если уничтожить экземпляр `Car`, уничтожится и `Engine`.
        
- 🤝 **Агрегация (Слабая связь):** Дочерний объект создается снаружи и передается родителю. Он **может продолжать жить независимо** от родителя.
    
    - _Пример:_ `Department` (Отдел) и `Teacher` (Учитель). Если расформировать отдел, учителя останутся жить в системе.
        

### 📜 15. Виды стейтментов в JDBC

1. 📄 **`Statement`:** Для простых статических SQL-запросов. Уязвим к SQL-инъекциям, не компилируется заранее.
    
2. 🛡️ **`PreparedStatement`:** Для запросов с параметрами (`?`). Защищает от SQL-инъекций, компилируется СУБД заранее (быстрее в циклах).
    
3. ⚙️ **`CallableStatement`:** Наследуется от `PreparedStatement`. Служит для вызова хранимых процедур и функций БД (`CALL my_proc(?, ?)`).
    

### 📥 16. Как получить данные из БД в JDBC
```Java
String sql = "SELECT id, name FROM users WHERE age > ?";
try (Connection conn = dataSource.getConnection();
     PreparedStatement stmt = conn.prepareStatement(sql)) {
    
    stmt.setInt(1, 18);
    try (ResultSet rs = stmt.executeQuery()) {
        while (rs.next()) {
            long id = rs.getLong("id");
            String name = rs.getString("name");
        }
    }
}
```

### 🔄 17. Отличие Iterator от ListIterator

- ➡️ **`Iterator`:**
    
    - Работает для любых коллекций (`Collection`).
        
    - Движется **только вперед** (`hasNext()`, `next()`).
        
    - Позволяет только удалять элементы (`remove()`).
        
- ⇄ **`ListIterator`:**
    
    - Работает **только для списков (`List`)**.
        
    - Движется **в обоих направлениях** (`hasPrevious()`, `previous()`).
        
    - Позволяет получать индексы (`nextIndex()`), модифицировать (`set()`) и добавлять элементы (`add()`).
        

### 🚨 18. Отличие Fail-Fast от Fail-Safe итераторов

- 💥 **Fail-Fast:** Мгновенно выбрасывает **`ConcurrentModificationException`**, если структура коллекции была изменена сторонним методом во время итерирования. Работает по внутреннему счетчику `modCount` (`ArrayList`, `HashMap`).
    
- 🛡️ **Fail-Safe (Weakly Consistent):** **Не выбрасывает исключений**. Итерируется по копии данных или использует атомарные механизмы (`CopyOnWriteArrayList`, `ConcurrentHashMap`).
    

### 🌲 19. Сложности алгоритмов в TreeMap

В основе `TreeMap` лежит **Красно-Черное дерево** (самобалансирующееся дерево поиска):

- Поиск (`get`), вставка (`put`), удаление (`remove`), проверка наличия (`containsKey`): **$O(\log N)$**.
    
- Обход всех элементов коллекции в отсортированном порядке: **$O(N)$**.
    

### ⚖️ 20. Отличие красно-черного от бинарного дерева

- 🌲 **Обычное бинарное дерево поиска (BST):** Не имеет механизмов балансировки. При вставке заранее отсортированных данных может выродиться в обычный односвязный список с деградацией операций до **$O(N)$**.
    
- 🔴⚫ **Красно-черное дерево:** Самобалансирующееся BST. Инварианты цвета узлов гарантируют, что самый длинный путь от корня к листу не более чем в 2 раза длиннее самого короткого. Это гарантирует строгое время операций **$O(\log N)$** в худшем случае.
    

### 🔀 21. Какие бывают сортировки в Java

- 🔢 **Для массивов примитивов (`Arrays.sort`):** Используется алгоритм **Dual-Pivot Quicksort** (Быстрая сортировка с двумя опорными элементами). Сложность $O(N \log N)$ в среднем.
    
- 📦 **Для массивов объектов и коллекций (`List.sort` / `Collections.sort`):** Используется алгоритм **Timsort** (гибрид сортировки слиянием Merge Sort и сортировки вставками Insertion Sort). Сложность $O(N \log N)$, стабильная (Stable) сортировка.
    

### 🫧 22. Сортировка пузырьком (Bubble Sort)

Самый простой алгоритм: последовательно сравнивает соседние элементы и меняет их местами, если порядок неверен.

- ⏱️ **Временная сложность:** В худшем и среднем случае **$O(N^2)$**, в лучшем (с флагом обмена) — $O(N)$.
    
- 💾 **Пространственная сложность:** $O(1)$ (In-place, устойчивая).
    

### 🚚 23. Класслоудеры (ClassLoaders)

Компоненты JVM, загружающие байт-код `.class` файлов в память Metaspace.

**Модель делегирования (Delegation Principle):**

Загрузчик сначала перенаправляет запрос родительскому загрузчику, и только если родитель не нашел класс, ищет его сам.

**Иерархия:**

1. **Bootstrap ClassLoader:** Базовый загрузчик на C++. Загружает фундаментальные классы JDK (`java.lang.*`).
    
2. **Platform ClassLoader:** Загружает модули и расширения платформы.
    
3. **Application / System ClassLoader:** Загружает классы вашего приложения и библиотеки из `classpath`.
    

### 🛠️ 24. JDK, JRE, JVM

- ⚙️ **JVM (Java Virtual Machine):** Исполнительная среда. Читает и выполняет байт-код на конкретной ОС.
    
- 📦 **JRE (Java Runtime Environment):** **`JVM + Стандартные библиотеки`**. Минимальный набор для _запуска_ готовых Java-приложений.
    
- 🧰 **JDK (Java Development Kit):** **`JRE + Инструменты разработчика`** (компилятор `javac`, отладчик `jdb`, архиватор `jar`). Набор для _написания и компиляции_ кода.
    

### 🌍 25. Зачем нужна JVM

1. 🌐 **Кроссплатформенность (WORA - Write Once, Run Anywhere):** Код компилируется один раз в независимый байт-код, а JVM транслирует его под конкретную ОС.
    
2. 🧹 **Автоматическое управление памятью:** Сборка мусора (GC) избавляет от утечек и ручного `free()`.
    
3. 🔒 **Безопасность:** Проверка байт-кода (Bytecode Verifier) и изоляция исполнения.
    
4. 🚀 **JIT-компиляция (Just-In-Time):** Динамическая трансляция горячего байт-кода в нативный код процессора прямо во время работы.
    

### 🔌 26. Ключевое слово native

Указывает на то, что метод реализован на нативном языке (C/C++) и подключен через механизм **JNI (Java Native Interface)**.

- У такого метода в Java-коде **нет тела**:
```Java
    public native int hashCode();
```


### 💻 27. Можно ли в Java исполнить (написать) код на Assembler?

- ❌ **Прямо в файле `.java` написать код Ассемблера нельзя** — синтаксис языка Java не поддерживает inline-вставки ассемблерного кода.
    
- ✅ **Косвенно исполнить можно:**
    
    1. Написать код на Ассемблере (или C с inline-ассемблером), скомпилировать его в динамическую библиотеку (`.so` / `.dll`) и вызвать из Java через **JNI**.
        
    2. Использовать современные механизмы Java 22+ **Foreign Function & Memory API (Project Panama)** для вызова нативных функций.
