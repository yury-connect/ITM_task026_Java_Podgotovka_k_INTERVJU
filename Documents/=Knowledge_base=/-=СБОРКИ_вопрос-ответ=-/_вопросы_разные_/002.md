### 1. Виды операций в Stream API и ленивость (Lazy Evaluation)

Операции над стримами делятся на две категории:

1. **Промежуточные (Intermediate):** `filter()`, `map()`, `flatMap()`, `sorted()`, `distinct()`.
    
    - **Ленивость (Lazy Evaluation):** Промежуточные операции не выполняются моментально при вызове. Они лишь конструируют конвейер (pipeline) обработки. Реальный проход по данным начинается только тогда, когда вызывается терминальная операция.
        
2. **Терминальные (Terminal):** `collect()`, `forEach()`, `reduce()`, `findFirst()`, `count()`.
    
    - Запускают выполнение всего цепочки промежуточных операций и закрывают стрим.
        

Также существуют специализированные примитивные стримы: `IntStream`, `LongStream`, `DoubleStream` (для предотвращения оверхеда на автоупаковку/распаковку).

### 2. Отличие `map` от `flatMap`

- **`map(Function<T, R>)`:** Преобразует каждый элемент типа $T$ в один элемент типа $R$ (трансформация **1-в-1**). Возвращает `Stream<R>`.
    
- **`flatMap(Function<T, Stream<R>>)`:** Преобразует каждый элемент типа $T$ в _целый стрим_ элементов типа $R$, а затем «сплющивает» (flatten) полученные вложенные стримы в один единый плоский `Stream<R>` (трансформация **1-ко-многим**).
    

### 3. Две способы создания параллельных стримов

1. Вызовом метода `.parallelStream()` у любой коллекции:
    
    Java
    
    ```
    List<String> list = List.of("a", "b", "c");
    Stream<String> parallel = list.parallelStream();
    ```
    
2. Преобразованием обычного стрима вызовом `.parallel()`:
    
    Java
    
    ```
    Stream<Integer> parallel = Stream.of(1, 2, 3).parallel();
    ```
    

### 4. Runnable vs Callable

- **`Runnable`:** Метод `run()`, не возвращает результат (`void`), не может выбрасывать Checked Exceptions. Выполняется в `Thread` или `ExecutorService`.
    
- **`Callable<V>`:** Метод `call()`, **возвращает значение** типа `V`, может выбрасывать Checked Exceptions (`throws Exception`). Исполняется через `ExecutorService.submit()` и возвращает `Future<V>`.
    

### 5. Виртуализация

**Виртуализация** — технология, позволяющая запускать несколько изолированных операционных систем (гостевых ОС) на одном физическом сервере.

- Работает с помощью **гипервизора** (Type 1: ESXi/KVM, Type 2: VirtualBox).
    
- Гипервизор полностью эмулирует физическое аппаратное обеспечение (CPU, RAM, Disk, Network) для каждой виртуальной машины.
    

### 6. Контейнеризация

**Контейнеризация** — легкий способ изоляции приложений на уровне **ядра операционной системы** (использует возможности Linux: `cgroups` для лимита ресурсов и `namespaces` для изоляции процессов/сети).

- **Отличие от виртуализации:** Контейнеры **не содержат отдельную гостевую ОС**, а делят единое ядро хостовой ОС. За счет этого контейнеры стартуют за миллисекунды и потребляют минимум ресурсов.
    

### 7. Docker Image (Образ Docker)

**Docker Image** — это неизменяемый (read-only) шаблон с инструкциями для создания Docker-контейнера.

Состоит из слоев (layers) и содержит отчуждаемый снимок файловой системы: скомпилированный код приложения, его зависимости, системные библиотеки и переменные окружения.

### 8. Как реализовать сериализацию в Java

1. Имплементировать маркерный интерфейс `java.io.Serializable`.
    
2. Объявить поле `private static final long serialVersionUID` для контроля версий класса.
    
3. Сериализовать/десериализовать через `ObjectOutputStream` и `ObjectInputStream`.
    
4. Поля, которые не нужно сохранять (пароли, ссылки на соединения), помечаются ключевым словом **`transient`**.
    

_(Альтернативный вариант — интерфейс `Externalizable`, требующий ручной реализации методов `writeExternal` и `readExternal`)._

### 9. Цикл сборки мусора (GC Cycle)

Процесс работы традиционного сборщика мусора состоит из 3 этапов:

1. **Mark (Маркировка):** Обход графа объектов начиная от GC Roots (стек, статика, живые потоки) и пометка всех доступных ("живых") объектов.
    
2. **Sweep (Очистка):** Сканирование памяти и освобождение блоков, занятых немаркированными (недостижимыми) объектами.
    
3. **Compact (Уплотнение/Сжатие):** Перемещение выживших объектов в одну непрерывную область памяти для устранения фрагментации.
    

### 10. Уровни кэша процессора (L1, L2, L3)

Аппаратные сверхбыстрые области памяти внутри процессора для минимизации обращения к медленной RAM:

- **L1 Cache:** Самый быстрый и маленький (~32–64 КБ на ядро), встроен прямо в ядро CPU.
    
- **L2 Cache:** Чуть медленнее L1, но больше по объему (~512 КБ–1 МБ на ядро).
    
- **L3 Cache:** Самый большой (десятки МБ), но более медленный. **Общий** для всех ядер одного процессора.
    

### 11. `Thread.join()`

Метод `join()` останавливает и **блокирует текущий поток** до тех пор, пока поток, у которого был вызван `join()`, полностью не завершит свое выполнение (или пока не истечет указанный таймаут).

Используется для синхронизации и ожидания результатов работы параллельных потоков.

### 12. Для чего метод `hash()` в HashMap

Метод `hash(Object key)` в `HashMap` берет исходный `key.hashCode()` и выполняет дополнительное битовое перемешивание (добавляет сдвиг старших бит в младшие): `h ^ (h >>> 16)`.

**Цель:** Снизить количество коллизий при отображении хэша на бакеты массива, компенсируя плохо написанные пользовательские функции `hashCode()`.

### 13. PriorityQueue

Структура данных "Очередь с приоритетом", реализованная на базе **неограниченной двоичной кучи (Binary Min-Heap)**.

- Элементы извлекаются в порядке приоритета (естественного через `Comparable` или заданного через `Comparator`), а не по FIFO.
    
- Сложность: вставка и удаление элемента за $O(\log N)$, получение элемента с наивысшим приоритетом — за $O(1)$.
    
- **Не потокобезопасна** (в многопоточке используется `PriorityBlockingQueue`).
    

### 14. Raw типы (Raw Types)

**Raw Type** — это использование универсального класса (Generic) без указания типа-параметра (например, `List list = new ArrayList()`).

- **Почему это плохо:**
    
    1. Теряется проверка типов компилятором (Type Safety).
        
    2. Требуется ручное приведение типов (`Explicit Casting`).
        
    3. Риск получить `ClassCastException` во время выполнения приложения.
        
- Существуют исключительно для обратной совместимости с Java 1.4.
