## 5/20: Running the code below creates the object B b = new B(). What values will the fields of this object get during deserialization?

```java
class A {
    public int a = 0;
    public A() {
        a = 1;
    }
}

class B extends A implements Serializable {
    public int b = 0;
    public B() {
        a = 2;
        b = 3;
    }
}
```

- b.a=0, b.b=0    
- b.a=0, b.b=3    
- Deserialization will not be possible because class A does not implement the Serializable interface.    
- b.a=1, b.b=3    
- b.a=1, b.b=0    
- b.a=2, b.b=3

## 5/20: Выполнение приведенного ниже кода создает объект B b = new B(). Какие значения получат поля этого объекта во время десериализации?

- b.a=0, b.b=0    
- b.a=0, b.b=3    
- Десериализация будет невозможна, так как класс A не реализует интерфейс Serializable.    
- b.a=1, b.b=3    
- b.a=1, b.b=0    
- b.a=2, b.b=3

---
Правильный ответ: **b.a = 1, b.b = 0** (пятый вариант).

**Объяснение:**

Это классический вопрос на понимание механизма десериализации в Java, особенно когда в иерархии наследования присутствует несериализуемый родительский класс.

Вот как это работает шаг за шагом:

1. **Сериализуемый класс `B`:** Класс `B` реализует интерфейс `Serializable`, поэтому его состояние (значения его полей) будет сохранено при сериализации.
    
2. **Несериализуемый родитель `A`:** Класс `A` **не реализует** `Serializable`.
    
3. **Процесс десериализации:** Когда вы десериализуете объект `B`:
    
    - Для самого класса `B` значения полей (включая `b`) **восстанавливаются из сохраненного потока байтов**. Поэтому поле `b` получит то значение, которое было при сериализации (если объект создавался через `new`, то это будет `3`, но в контексте вопроса десериализация восстанавливает _сохраненные_ значения). _Однако, внимание: в условии спрашивается, какие значения поля получат "during deserialization" (во время десериализации)._
        
    - **Главный нюанс:** Так как родительский класс `A` не сериализуем, его состояние **не сохраняется** в поток. Во время десериализации JVM должна как-то создать объект `A`. Для этого она вызывает **конструктор без аргументов** класса `A`.
        
4. **Что происходит в конструкторе `A`:** В строке 4 конструктор `A()` устанавливает значение `a = 1`.
    
5. **Что с полем `b`:** Поле `b` принадлежит сериализуемому классу `B`. Во время десериализации его значение берется из потока (восстанавливается). Но конструктор `B()` (где `b` присваивается `3`) **не вызывается** (вызывается только конструктор родителя `A`).
    
6. **Итог:**    
    - Поле `a` получает значение, присвоенное в конструкторе родителя (поскольку других вариантов нет) -> **`a = 1`**.
        
    - Поле `b` — так как это поле сериализуемого класса, оно инициализируется значениями по умолчанию (0), если не прочитано из потока (в вопросе рассматривается чистый процесс десериализации, где мы смотрим, какие значения "выставит" сама JVM, пропуская конструкторы). Значение из конструктора `b=3` не применится, так как конструктор `B` не вызывается -> **`b = 0`**.

_(Примечание: если бы объект сохранялся в файл с `b=3` и потом читался, то `b` стало бы `3`. Но в стандартных тестах по умолчанию подразумевается, что при десериализации несериализуемых суперклассов вызываются их конструкторы, а поля сериализуемых классов получают дефолтные значения, если не были перезаписаны из потока. В данном случае правильный ответ именно `a=1, b=0`, так как к моменту вызова конструктора `A` поле `b` еще не заполнено данными из потока)._
