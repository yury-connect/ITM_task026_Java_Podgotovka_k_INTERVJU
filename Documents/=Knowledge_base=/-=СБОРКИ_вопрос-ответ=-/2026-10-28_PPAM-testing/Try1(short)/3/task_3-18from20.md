    }

## 18/20: Каким будет результат попытки скомпилировать и выполнить следующую программу?

- 22    
- 32    
- 33    
- Во время выполнения будет выброшено исключение    
- Ошибка компиляции

---
Правильный ответ: **33** (третий вариант).

**Объяснение:**

Этот код демонстрирует два важных концепта ООП в Java: **полиморфизм (переопределение методов)** и **сокрытие полей (field hiding)**.

Давайте разберем выполнение по шагам:

1. **Строка 3:** `A7 o1 = new C7();`  
    Создается объект класса `C7`, но ссылка на него имеет тип `A7`. В памяти создается полноценный объект `C7`, который содержит поля и методы всех своих предков.
    
2. **Строка 4:** `B7 o2 = (B7) o1;`  
    Ссылка `o1` приводится к типу `B7`. Так как реальный объект в памяти — это `C7` (который является наследником `B7`), приведение типа проходит успешно. Теперь `o1` и `o2` указывают на один и тот же объект `C7`.
    
3. **Строка 5:** `System.out.print(o1.doIt());`  
    Вызывается метод `doIt()`. В Java для нестатических методов работает **динамический полиморфизм**: вызывается метод того класса, к которому принадлежит _реальный объект_ (в данном случае `C7`), а не того, к которому относится _тип ссылки_ (`A7`).
	    
    - Метод `doIt()` в классе `C7` (строки 23-25) возвращает поле `i` этого класса, которое равно `3`.
        
    - **Выводится `3`**.
    
4. **Строка 6:** `System.out.print(o2.i);`  
    Здесь происходит обращение к **полю** `i`, а не к методу. В Java **поля не обладают полиморфизмом**. Обращение к полю определяется _типом ссылки_, а не типом объекта. Ссылка `o2` имеет тип `B7`.
	    
    - Поэтому берется поле `i` из класса `B7` (строка 16), которое равно `2`.
        
    - **Выводится `2`**.

**Итог:** Программа выведет `3`, а затем `2`, что в сумме даст **33**.
