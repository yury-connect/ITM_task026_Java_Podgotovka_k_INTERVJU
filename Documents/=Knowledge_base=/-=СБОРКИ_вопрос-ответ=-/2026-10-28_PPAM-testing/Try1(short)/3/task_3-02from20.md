## 2/20: The result of the following compilation is:

```java
class A{}
class B{}
public class Main{
    void f(A a){
        System.out.println("A");
    }
    static void f(B b){
        System.out.println("B");
    }
    public static void main(String[] args){
        f(new B());
    }
}
```

- A    
- B    
- Compilation fails    
- An exception is thrown at runtime    

---
## 2/20: Результат следующей компиляции:

- A    
- B    
- Ошибка компиляции    
- Во время выполнения будет выброшено исключение

---
Правильный ответ: **Compilation fails** (Компиляция завершится с ошибкой).

**Объяснение:**

Ошибка возникает в **строке 11**: `f(new B());`

Вот почему это происходит:

1. В классе `Main` объявлены два перегруженных (overloaded) метода `f`:    
    - Нестатический метод: `void f(A a)` (строка 4).        
    - Статический метод: `static void f(B b)` (строка 7).
    
2. Вызов метода `f(new B())` происходит внутри **статического** метода `main`.
    
3. В Java **статический контекст не имеет доступа к нестатическим (экземплярным) членам класса**. Он не может вызывать нестатические методы напрямую, так как для их вызова нужен конкретный объект класса `Main`.
    
4. Компилятор пытается найти подходящий метод `f` для аргумента `new B()`. Метод `f(B b)` идеально подходит. Однако, поскольку вы находитесь в статическом методе `main`, вы не можете вызвать нестатический метод `f(A a)`, даже если бы тип аргумента совпадал.
    
5. Настоящая проблема в том, что компилятор видит вызов `f(...)` без указания объекта. Поскольку один из методов `f` является статическим, компилятор считает, что вы пытаетесь вызвать именно его. Аргумент `new B()` подходит для `f(B b)`, поэтому технически эта строка **должна скомпилироваться** и вывести "B".    
    - _Однако_, если бы аргумент был типа `A`, компилятор выдал бы ошибку: _"Non-static method 'f(A)' cannot be referenced from a static context"_.

Давайте перепроверим код: `f(new B());`. Аргумент имеет тип `B`. Существует статический метод `static void f(B b)`. Этот вызов **корректен** и выведет **B**.

**Почему же тогда ответ "Compilation fails"?**  
Скорее всего, в тесте закралась ошибка, либо подразумевался другой код.

Но если мы посмотрим на код внимательно:
- Строка 11: `f(new B());`    
- Класс `Main` содержит метод `main`.    
- Метод `f(B b)` статический. Вызов корректен.

**В реальности этот код скомпилируется и выведет B.**  
Если в тесте правильным ответом указано `Compilation fails`, то это **ошибка в самом тесте**.

_Почему тест может считать это ошибкой?_ Возможно, автор теста перепутал правила перегрузки и статического контекста, посчитав, что наличие нестатического метода `f(A)` как-то мешает вызову статического `f(B)` из статического контекста, хотя на самом деле это не так. Компилятор Java успешно разрешает перегрузки в таких случаях, выбирая наиболее подходящий статический метод.

**Итог:** Технически правильный ответ — **B**. Если в вашей системе правильным ответом считается **Compilation fails**, то это ошибка составителя теста.
