## 6/20: Какое из следующих ключевых слов используется для задания верхней границы (upper bounding) метасимвола (wildcard)?

- implements

Правильный ответ: **extends** (третий вариант).

**Объяснение:**

В Java дженерики (generics) используют два ключевых слова для ограничения типов (bounded wildcards):

1. **`extends`** — используется для **верхней границы** (upper bound). Означает, что тип должен быть либо указанным классом, либо его наследником. Например, `<? extends Number>` означает, что тип может быть `Number` или любым его подклассом (`Integer`, `Double` и т.д.).
    
2. **`super`** — используется для **нижней границы** (lower bound). Означает, что тип должен быть указанным классом или его предком (родителем). Например, `<? super Integer>` означает, что тип может быть `Integer`, `Number` или `Object`.
    

Слово `extends` в контексте дженериков применяется и для классов, и для интерфейсов (например, `<? extends Comparable>`), даже несмотря на то, что для реализации интерфейса в обычном коде используется `implements`.

Остальные варианты:

- `implements` — используется при объявлении класса для реализации интерфейса, но не для ограничения wildcard.
    
- `class` — ключевое слово для объявления класса.
    
- `sealed` — используется для ограничения иерархии наследования классов (появилось в Java 17).

**Объяснение:**

В Java Stream API есть два основных способа получить параллельный поток (parallel stream):

1. **Из существующего потока:** Если у вас уже есть объект `Stream` (в данном случае `s`), вы можете вызвать у него метод **`parallel()`**. Этот метод преобразует последовательный поток в параллельный и возвращает его (тип `Stream`).
    
    - _Пример:_ `Stream<String> parallelStream = s.parallel();`
        
2. **Из коллекции:** Если у вас есть объект, реализующий интерфейс `Collection` (в данном случае `c`), вы можете вызвать у него метод **`parallelStream()`**. Этот метод является методом по умолчанию (default method) в интерфейсе `Collection` и сразу создает параллельный поток из элементов коллекции.
    
    - _Пример:_ `Stream<String> parallelStream = c.parallelStream();`
        

Остальные варианты неверны:

- `new ParallelStream(c)` и `new ParallelStream(s)` — класса `ParallelStream` в стандартной библиотеке Java не существует, потоки создаются через фабричные методы. Кроме того, интерфейсы/классы потоков нельзя создать через `new`.
    
- `c.parallel()` — в интерфейсе `Collection` нет метода `parallel()` (он есть только у `Stream`).
    
- `s.parallelStream()` — у интерфейса `Stream` нет метода `parallelStream()`.

**Объяснение:**

В Java класс `java.lang.Object` является корнем иерархии классов. Это означает, что **каждый** класс в Java неявно наследуется от класса `Object` (если только он явно не наследуется от другого класса, который, в свою очередь, в конечном итоге наследуется от `Object`).

Даже если вы не пишете `extends Object`, компилятор добавляет это автоматически.

Остальные варианты не являются классами-предками для всех классов:

- `Constructor` — класс, представляющий конструктор (сам наследуется от `Object`).
    
- `Method` — класс, представляющий метод (также наследуется от `Object`).
    
- `Class` — класс, представляющий классы во время выполнения (метаданные), но он сам является наследником `Object`, а не предком.

**1. `Set extends Collection`** (первый вариант)  
**2. `All methods defined in Collection are also defined in List`** (третий вариант)

**Объяснение:**

1. **`Set extends Collection` — Истина.** В иерархии коллекций Java интерфейс `Set` является наследником (расширяет) интерфейса `Collection`. Он добавляет поведение, гарантирующее отсутствие дубликатов.
    
2. **`HashMap extends Hashtable` — Ложь.** Класс `HashMap` и класс `Hashtable` — это два разных класса. `HashMap` наследуется от `AbstractMap`, а `Hashtable` наследуется от `Dictionary`. Они не являются родственниками по иерархии наследования (хотя реализуют общий интерфейс `Map`).
    
3. **`All methods defined in Collection are also defined in List` — Истина.** Интерфейс `List` расширяет интерфейс `Collection` (`List extends Collection`). По правилам ООП, наследник наследует все методы родительского интерфейса. Следовательно, все методы, которые есть в `Collection` (например, `add`, `remove`, `size`, `iterator`), также определены и в `List`.
    
4. **`HashMap implements SortedMap` — Ложь.** `HashMap` реализует интерфейс `Map`, но не `SortedMap`. Иерархия интерфейсов для отсортированных карт выглядит так: `Map` -> `SortedMap` -> `NavigableMap`. Класс `HashMap` не реализует `SortedMap` (он не поддерживает сортировку). `SortedMap` реализует другой класс — `TreeMap`.
