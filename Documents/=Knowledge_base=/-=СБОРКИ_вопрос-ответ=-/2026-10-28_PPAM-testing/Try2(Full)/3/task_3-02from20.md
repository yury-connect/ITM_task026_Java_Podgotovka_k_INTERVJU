## 2/20: Which of the following is NOT a way to achieve thread synchronization?

- Volatile variables    
- Thread.sleep()    
- Synchronized methods    
- Synchronized blocks    

---
## 2/20: Что из следующего НЕ является способом достижения синхронизации потоков?

- Переменные volatile    
- Thread.sleep()    
- Синхронизированные методы    
- Синхронизированные блоки

---
Правильный ответ: **Thread.sleep()** (второй вариант).

#### **Объяснение:**

Синхронизация потоков (thread synchronization) — это механизм, который гарантирует, что два или более потоков не будут одновременно выполнять критическую секцию кода, чтобы избежать состояния гонки (race conditions) и повреждения данных.

#### Разберем варианты:

1. **Volatile variables (Волатильные переменные):** Ключевое слово `volatile` гарантирует, что изменения переменной одним потоком будут немедленно видны другим потокам (обеспечивает видимость, visibility). Хотя это не полная замена блокировкам (не обеспечивает атомарность), это один из механизмов управления памятью и видимостью данных между потоками.
    
2. **Thread.sleep():** Этот метод просто **приостанавливает** выполнение текущего потока на заданное время. Он **не блокирует** доступ к общим ресурсам для других потоков. Пока один поток спит, другие могут свободно зайти в тот же участок кода и изменить данные. Это инструмент управления временем, а не синхронизации.
    
3. **Synchronized methods (Синхронизированные методы):** Это классический способ синхронизации в Java. Модификатор `synchronized` в сигнатуре метода гарантирует, что только один поток сможет выполнять этот метод для конкретного объекта в единицу времени.
    
4. **Synchronized blocks (Синхронизированные блоки):** Это более гибкий вариант, чем методы. Выделяется участок кода `synchronized(obj) { ... }`, который блокируется для других потоков на основе монитора объекта `obj`.    

Таким образом, `Thread.sleep()` не является способом синхронизации.
