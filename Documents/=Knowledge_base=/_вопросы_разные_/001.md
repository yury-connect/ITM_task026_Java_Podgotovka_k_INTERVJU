Отличный блок вопросов по Spring, сервлетам и HTTP-протоколу. Держи четкие ответы, идеально подходящие для собеседования!

### 1. Стартеры (Spring Boot Starters)

**Ответ:** **Spring Boot Starters** — это набор готовых транзитивных зависимостей (POM-файлов), объединенных под конкретные типовые задачи.

- **Зачем нужны:** Избавляют от необходимости вручную прописывать десятки отдельных библиотек и согласовывать их версии.
    
- _Пример:_ `spring-boot-starter-web` автоматически подтягивает Spring MVC, встроенный Tomcat, Jackson для JSON и валидацию Hibernate Validator с уже совместимыми версиями.
    

### 2. Отличие ApplicationContext от BeanFactory

**Ответ:** Оба являются IoC-контейнерами в Spring, но `ApplicationContext` — это расширение `BeanFactory`.

- **`BeanFactory`:** Базовый контейнер. Использует **«ленивую» инициализацию** (Lazy) — создает бины только в момент вызова `getBean()`. Имеет минимальный footprint по памяти.
    
- **`ApplicationContext`:** Продвинутый контейнер. По умолчанию создает все `Singleton`-бины **сразу при старте** (Eager initialization). Дополнительно предоставляет:
    
    - Встроенную поддержку AOP и интернационализацию (i18n).
        
    - Публикацию событий (`ApplicationEventPublisher`).
        
    - Интеграцию с Web-контекстом (`WebApplicationContext`).
        

### 3. Как заинжектить примитив или строку с помощью Spring

**Ответ:** С помощью аннотации **`@Value`**:

1. **Из конфигурационных файлов (`application.properties` / `yml`):**
    
    Java
    
    ```
    @Value("${app.timeout:5000}") // 5000 — дефолтное значение
    private int timeout;
    ```
    
2. **Прямое значение:**
    
    Java
    
    ```
    @Value("Hello World")
    private String greeting;
    ```
    
3. **Через SpEL (Spring Expression Language):**
    
    Java
    
    ```
    @Value("#{2 * 60 * 1000}")
    private int millis;
    ```
    

### 4. Retention Policies аннотаций

**Ответ:** Политика удержания (`@Retention`) определяет жизненный цикл аннотации:

- **`SOURCE`:** Аннотация доступна только на уровне исходного кода и сбрасывается компилятором (например, `@Override`, `@Getter` в Lombok).
    
- **`CLASS` (по умолчанию):** Сохраняется в `.class`-файле при компиляции, но **недоступна** во время выполнения через JVM (используется для статического анализа).
    
- **`RUNTIME`:** Сохраняется в компилированном файле и загружается в JVM. Доступна во время выполнения приложения через **Reflection API** (все основные аннотации Spring и JPA).
    

### 5. Как получить ServletContext и ServletConfig

**Ответ:**

1. **Через Aware-интерфейсы:** Реализовать `ServletContextAware` или `ServletConfigAware` в своем бине — Spring сам внедрит объект через сеттер при инициализации.
    
2. **Через инъекцию зависимостей (DI):**
    
    Java
    
    ```
    @Autowired
    private ServletContext servletContext;
    ```
    
3. **В контроллере:** Передать объектом в параметр метода контроллера.
    

### 6. DispatcherServlet

**Ответ:** **`DispatcherServlet`** — это центральный компонент Spring MVC, реализующий паттерн **Front Controller**.

Он служит единой точкой входа для всех входящих HTTP-запросов: перехватывает их, запрашивает у `HandlerMapping` нужный контроллер, вызывает его через `HandlerAdapter`, а затем передает результат на рендеринг (`ViewResolver`) или сериализует в JSON (`HttpMessageConverter`).

### 7. Tomcat

**Ответ:** **Apache Tomcat** — это встраиваемый (Embedded) или автономный **контейнер сервлетов** и веб-сервер.

Он реализует спецификацию Jakarta Servlet / Jakarta Server Pages (JSP). Его задача — принимать сетевые TCP/HTTP соединения, управлять жизненным циклом сервлетов (включая `DispatcherServlet`) и передавать им HTTP-запросы в виде объектов `HttpServletRequest`.

### 8. Жизненный цикл бина в Spring

**Ответ:**

1. **Instantiation:** Вызов конструктора (создание объекта).
    
2. **Populate Properties:** Внедрение зависимостей (DI).
    
3. **Aware-интерфейсы:** Вызов `setBeanName()`, `setApplicationContext()` и др.
    
4. **BeanPostProcessor (Before):** Обработка `@PostConstruct`.
    
5. **Initialization:** Вызов `afterPropertiesSet()` или кастомного `initMethod`.
    
6. **BeanPostProcessor (After):** Создание AOP-прокси (для `@Transactional` и др.).
    
7. **Ready:** Бин готов к работе.
    
8. **Destruction:** Вызов `@PreDestroy` или `destroy()` при закрытии контекста.
    

### 9. Как работает Spring MVC

**Ответ:**

1. HTTP-запрос приходит на **`DispatcherServlet`**.
    
2. `DispatcherServlet` обращается к **`HandlerMapping`**, чтобы найти подходящий метод контроллера по URL.
    
3. `DispatcherServlet` вызывает **`HandlerAdapter`**, который непосредственно выполняет метод контроллера.
    
4. **Controler** исполняет бизнес-логику и возвращает ответ.
    
5. Если это `@RestController`: **`HttpMessageConverter`** (например, Jackson) сериализует Java-объект напрямую в JSON/XML.
    
6. `DispatcherServlet` отправляет итоговый HTTP-ответ клиенту.
    

### 10. Жизненный цикл сервлета

**Ответ:** Жизненным циклом управляет Сервлет-контейнер (Tomcat):

1. **Загрузка и создание:** Контейнер загружает класс сервлета и создает его экземпляр (`new`).
    
2. **Инициализация (`init()`):** Метод вызывается **один раз** при создании сервлета.
    
3. **Обслуживание запросов (`service()`):** Вызывается на **каждый** входящий запрос в отдельном потоке (внутри перенаправляет на `doGet`, `doPost` и т.д.).
    
4. **Уничтожение (`destroy()`):** Вызывается **один раз** при остановке контейнера/контекста для высвобождения ресурсов.
    

### 11. @SpringBootApplication

**Ответ:** Мета-аннотация, объединяющая 3 ключевые конфигурации:

- **`@SpringBootConfiguration`:** Помечает класс как источнику конфигурации бинов (`@Configuration`).
    
- **`@EnableAutoConfiguration`:** Включает магию автоконфигурации Spring Boot на основе библиотек в classpath.
    
- **`@ComponentScan`:** Включает сканирование компонентов (`@Component`, `@Service`, `@Repository`, `@Controller`) в текущем пакете и всех его подпакетах.
    

### 12. Аннотации Spring MVC

**Ответ:**

- **`@Controller` / `@RestController`:** Объявление веб-контроллера (вторая включает `@ResponseBody`).
    
- **`@RequestMapping`:** Базовый маппинг URL на класс или метод.
    
- **`@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`:** Сокращения для обработки конкретных HTTP-методов.
    
- **`@ResponseBody`:** Указывает, что результат метода должен быть записан напрямую в тело HTTP-ответа (без поиска View-шаблона).
    
- **`@ResponseStatus`:** Явно задает HTTP-код ответа (например, `201 CREATED`).
    

### 13. RequestBody, PathVariable, RequestParam

**Ответ:**

- **`@RequestBody`:** Десериализует **тело HTTP-запроса** (обычно JSON) в Java-объект.
    
- **`@PathVariable`:** Извлекает значение из **переменной части URL-пути** (`/users/{id}`).
    
- **`@RequestParam`:** Извлекает параметры из **Query String** (`/users?page=1`) или из данных формы (`form-data`).
    

### 14. HTTP-методы

**Ответ:**

- **`GET`:** Чтение ресурса (безопасный, идемпотентный).
    
- **`POST`:** Создание нового ресурса (неидемпотентный).
    
- **`PUT`:** Полное замещение существующего ресурса или создание с известным ID (идемпотентный).
    
- **`PATCH`:** Частичное изменение ресурса.
    
- **`DELETE`:** Удаление ресурса (идемпотентный).
    
- **`HEAD`:** Запрос заголовков аналогично `GET`, но без тела ответа.
    
- **`OPTIONS`:** Запрос поддерживаемых сервером методов для указанного URL (используется для CORS).
    

### 15. Отличие GET от HEAD

**Ответ:** Метод **`HEAD`** работает абсолютно аналогично `GET`, с одним исключением: **сервер НЕ отправляет тело ответа (body)**, а возвращает только HTTP-заголовки.

**Зачем нужен:** Чтобы быстро проверить существование ресурса, узнать его размер (`Content-Length`) или дату изменения (`Last-Modified`), не скачивая сам файл/данные.

### 16. Отличие PUT и POST

**Ответ:**

- **`PUT` (Идемпотентный):** Используется для **полной перезаписи** ресурса. Если отправить один и тот же `PUT`-запрос 10 раз, состояние системы не изменится (ресурс перезапишется теми же данными).
    
- **`POST` (Неидемпотентный):** Используется для **создания нового** ресурса. Если отправить один и тот же `POST`-запрос 10 раз, на сервере создастся 10 разных записей с разными ID.
    

### 17. ContentType (Content-Type)

**Ответ:** Заголовок `Content-Type` указывает **MIME-тип** данных, передаваемых в теле (body) HTTP-запроса или ответа.

- **Примеры:** `application/json`, `application/xml`, `text/html`, `multipart/form-data`.
    
- **В Spring MVC:** Используется в маппингах через параметры `consumes` (что принимает контроллер) и `produces` (в каком формате отдает ответ).
