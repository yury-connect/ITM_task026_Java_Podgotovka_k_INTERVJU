### 🔑 1. Lock (`java.util.concurrent.locks.Lock`)

Гибкий интерфейс для управления блокировками на уровне классов, пришедший на смену `synchronized`:

- 🛡️ **Неблокирующий выбор (`tryLock()`):** Позволяет попытаться захватить замок без ухода в ожидания или с указанием таймаута (`tryLock(time, unit)`).
    
- 🛑 **Прерываемое ожидание (`lockInterruptibly()`):** Поток можно прервать во время ожидания блокировки через `Thread.interrupt()`.
    
- ⚖️ **Честность (Fairness):** Конструктор `new ReentrantLock(true)` гарантирует соблюдение FIFO-очереди ожидания потоков, исключая голодание (starvation).
    
- 🔔 **Условия (`Condition`):** Позволяет создавать несколько независимых очередей ожидания сигналов на базе одной блокировки (аналог `wait/notify`).
    

### 🧹 2. Distinct (в Stream API и SQL)

- 🌊 **В Stream API (`.distinct()`):** Промежуточная **stateful**-операция. Фильтрует дубликаты на основе методов `equals()` и `hashCode()`. Требует накопления элементов во внутренний буфер, из-за чего потребляет больше памяти и снижает скорость в параллельных стримах.
    
- 🗄️ **В SQL (`SELECT DISTINCT`):** Оператор, исключающий одинаковые строки из итогового результирующего набора данных на стороне СУБД.
    

### 🚀 3. Запуск стримов (Stream Execution)

Стримы в Java работают по принципу **ленивых вычислений (Lazy Evaluation)**:

- 🛠️ **Промежуточные операции** (`map`, `filter`, `sorted`) не исполняются моментально при вызове — они лишь конструируют конвейер (pipeline) обработки.
    
- ⚡ **Реальный запуск** и проход по данным начинается **только в момент вызова терминальной операции** (`collect`, `forEach`, `reduce`, `count`).
    

### 💳 4. Что такое транзакция

Логическая единица работы с базой данных, состоящая из одного или нескольких SQL-запросов, выполняемая по принципу «все или ничего».

- **Гарантирует соблюдение требований ACID:**
    
    - **A (Atomicity):** Атомарность (все операции выполнены или ни одна).
        
    - **C (Consistency):** Согласованность (соблюдение правил и ограничений БД).
        
    - **I (Isolation):** Изолированность (параллельные транзакции не мешают друг другу).
        
    - **D (Durability):** Долговечность (результат сохранен на диск и не пропадет).
        

### 🔗 5. Inner Join

Оператор SQL для соединения двух таблиц.

- Возвращает **только те строки**, для которых условие соединения выполняется в обеих таблицах (пересечение множеств).
    
- Если для строки из левой таблицы нет соответствия в правой — строка отбрасывается.
    

### 👁️ 6. View (Обычное представление)

«Виртуальная таблица» в БД, созданная на основе сохраненного SQL-запроса.

- **Особенность:** **Не хранит данные** на диске. При каждом обращении к View СУБД динамически выполняет сохраненный SQL-запрос заново.
    
- **Применение:** Изоляция доступа к колонкам, упрощение сложных выборк.
    

### 💾 7. Materialized View (Материализованное представление)

Представление, которое **физически сохраняет результат выполнения SQL-запроса на диск**.

- 🚀 **Плюс:** Мгновенное чтение сложных тяжелых агрегатов без постоянного пересчета.
    
- ⚠️ **Минус:** Данные устаревают. Требуется обновление через `REFRESH MATERIALIZED VIEW` (ручное или по расписанию).
    

### ⚡ 8. Триггеры в БД

Хранимые процедуры СУБД, которые выполняются **автоматически** при наступлении определенных событий на таблице:

- Вызываются до (`BEFORE`), после (`AFTER`) или вместо (`INSTEAD OF`) выполнения DML-операций (`INSERT`, `UPDATE`, `DELETE`).
    
- Применяются для сложного аудита, автоматического расчета полей и проверки бизнес-правил на уровне БД.
    

### 📖 9. Индексы в БД

Специализированные древовидные структуры данных (B-Tree, Hash, GIN, GiST, BRIN), создаваемые для колонок таблиц.

- 📈 **Плюс:** Кардинально ускоряют операции поиска и чтения данных (`SELECT`).
    
- 📉 **Минус:** Расходуют память/диск и **замедляют операции записи** (`INSERT`, `UPDATE`, `DELETE`), так как СУБД вынуждена перестраивать индексы при любом изменении данных.
    

### 🖥️ 10. Из чего состоит процессор (CPU Architecture)

- 🎮 **CU (Control Unit / Устройство управления):** Декодирует команды и управляет потоком выполнения инструкций.
    
- 🧮 **ALU (Arithmetic Logic Unit / АЛУ):** Выполняет арифметические и логические операции.
    
- 📦 **Регистры:** Сверхбыстрая память малого объема прямо на кристалле для мгновенного хранения промежуточных данных.
    
- ⚡ **Кэш-память (L1, L2, L3):** Быстрая буферная память между процессором и оперативной памятью (RAM).
    

### 🍃 11. Нереляционные базы данных (NoSQL)

СУБД, отказывающиеся от жесткой табличной схемы и строгого ACID в пользу горизонтального масштабирования и модели **BASE** (Eventual Consistency).

- 🔑 **Key-Value:** Redis, Memcached (кэширование, быстрый доступ за $O(1)$).
    
- 📄 **Document-oriented:** MongoDB (хранение гибких JSON/BSON документов).
    
- 🏛️ **Columnar:** Cassandra, ClickHouse (для хранения гигантских объемов аналитики).
    
- 🕸️ **Graph:** Neo4j (для сложной граф-логики и соцсетей).
    

### 🏗️ 12. Двухфазовый конструктор (Two-Phase Initialization)

Паттерн разделения создания объекта и его сложной бизнес-инициализации:

1. **Фаза 1 (Конструктор):** Вызывается конструктор класса, Spring внедряет зависимости (DI). В этой фазе зависимости еще могут быть не до конца проинициализированы.
    
2. **Фаза 2 (`@PostConstruct`):** После завершения внедрения зависимостей Spring автоматически вызывает метод, помеченный аннотацией `@PostConstruct`, где безопасно выполняется сложная стартовая логика.
    

### 🎭 13. Прокси в Spring

Динамические обертки вокруга реальных Spring-бинов.

- **Зачем нужны:** Позволяют перехватывать вызовы методов класса для автоматического добавления сквозной системной логики (управление транзакциями `@Transactional`, кэширование `@Cacheable`, асинхронность `@Async`, проверка прав).
    

### 💡 14. Aware-интерфейсы в Spring

Интерфейсы обратного вызова (например, `ApplicationContextAware`, `BeanNameAware`, `BeanFactoryAware`).

- **Зачем нужны:** Если бин реализует один из этих интерфейсов, Spring при его инициализации автоматически внедряет соответствующий служебный компонент фреймворка через сеттер.
    

### 🎯 15. Скоупы бинов (Bean Scopes)

Определяют жизненный цикл и видимость экземпляра бина:

- 1️⃣ **`singleton`** (дефолт): Один экземпляр на весь Spring-контейнер.
    
- 🔄 **`prototype`:** Новый экземпляр при каждом запросе из контекста.
    
- 🌐 **`request`:** Новый экземпляр на каждый HTTP-запрос.
    
- 📱 **`session`:** Новый экземпляр на каждую HTTP-сессию.
    
- 🏙️ **`application`:** Один экземпляр на весь жизненный цикл `ServletContext`.
    
- 🔄 **`@RefreshScope`:** Динамическое пересоздание бинов без перезапуска приложения при обновлении конфигов.
    

### 🌐 16. Request scope (`@RequestScope`)

Скоуп в веб-приложениях Spring, при котором контейнер создает отдельный новый экземпляр бина под каждый входящий HTTP-запрос.

- Экземпляр живет ровно столько, сколько обрабатывается запрос, и физически уничтожается после отправки ответа клиенту.
    

### 🧰 17. Свои стартеры (Custom Spring Boot Starters)

Модуль для повторного использования автоконфигурируемого функционала между микросервисами.

**Состоит из:**

1. Библиотеки с бинами, обернутыми в условные аннотации `@ConditionalOn...`.
    
2. Файла импорта автоконфигураций: `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` (Spring Boot 2.7+ / 3.x).
    

### ⚙️ 18. Типы Condition в Spring Boot

Аннотации семейства `@ConditionalOn...`, управляющие активацией автоконфигураций:

- 📄 **`@ConditionalOnProperty`:** Проверяет наличие или значение свойства в `application.yml`.
    
- 📦 **`@ConditionalOnClass` / `@ConditionalOnMissingClass`:** Проверяет наличие указанного класса в `classpath`.
    
- 🧩 **`@ConditionalOnBean` / `@ConditionalOnMissingBean`:** Проверяет наличие задекларированного бина в контексте.
    

### 🔄 19. Разница между Spring MVC и Spring Boot

- 🍃 **Spring MVC:** Веб-фреймворк для создания REST API / Web-приложений. Требует явной настройки XML/Java-конфигов, диспетчеров и внешнего сервера приложений (WAR).
    
- 🧰 **Spring Boot:** Инструмент поверх Spring (включая MVC). Предоставляет автоконфигурацию, стартеры и встроенный Tomcat/Netty для запуска как исполняемого JAR.
    

### 🔑 20. JWT токен (JSON Web Token)

Открытый стандарт (RFC 7519) для безопасной передаче утверждений при Stateless-аутентификации.

**Состоит из 3 частей (закодированных в Base64URL):**

1. **Header:** Алгоритм подписи (`alg`).
    
2. **Payload:** Данные пользователя и роли (`claims`).
    
3. **Signature:** Цифровая подпись, гарантирующая неизменность токена.
    

### 🗣️ 21. SQL Диалект (Hibernate / JPA)

Параметр конфигурации ORM (например, `PostgreSQLDialect`), указывающий конкретную вендорную СУБД.

- На его основе Hibernate генерирует вендор-специфичный SQL-код, учитывая особенности синтаксиса, типов данных и внутренних функций конкретной базы.
    

### ☕ 22. Разница между Java 17 и Java 21

Ключевые новшества **Java 21 LTS** по сравнению с Java 17 LTS:

- 🧵 **Virtual Threads (Project Loom):** Легковесные потоки JVM для эффективного I/O.
    
- 📦 **Sequenced Collections:** Новые интерфейсы (`SequencedCollection`, `SequencedSet`, `SequencedMap`) с методами `getFirst()` и `getLast()`.
    
- 🎯 **Pattern Matching for switch & Record Patterns:** Полноценный паттерн-матчинг и деструктуризация рекордов.
    

### 🔍 23. `findById()` vs `getReferenceById()` (`find()` vs `getReference()`)

- ⚡ **`findById()` / `em.find()`:** Выполняет **мгновенный SQL-запрос `SELECT`** в БД и возвращает реальный инициализированный объект (или `Optional.empty()`).
    
- 💤 **`getReferenceById()` / `em.getReference()`:** **Не делает SQL-запрос** сразу. Возвращает необработанный Lazy-прокси объект с зафиксированным ID. Реальный запрос в БД уйдет только при первом обращении к остальным полям объекта.
    

### 👥 24. Типы прокси в Spring (JDK vs CGLIB)

- ☕ **JDK Dynamic Proxy:** Создает прокси на базе встроенного Reflection API. Работает **только с классами, реализующими интерфейсы**.
    
- ⚡ **CGLIB:** Создает прокси путем динамической генерации дочернего класса-наследника. Используется по умолчанию в Spring Boot 2.x+.
    

### 🧬 25. Стратегии наследования в JPA

- 📄 **`SINGLE_TABLE`:** Все классы иерархии в одной таблице с колонкой-дискриминатором.
    
- 🔗 **`JOINED`:** Базовый и дочерние классы в разных нормализованных таблицах, связываемых через `JOIN`.
    
- 📚 **`TABLE_PER_CLASS`:** Отдельная полная таблица под каждый конкретный класс.
    
- 🧱 **`@MappedSuperclass`:** Родительский класс не сущность, его поля наследуются таблицами дочерних сущностей.
    

### 💥 26. LazyInitializationException

Ошибка Hibernate, возникающая при попытке обратиться к инициализируемому лениво (`FetchType.LAZY`) полю или коллекции сущности в момент, когда сессия Hibernate (`EntityManager`) **уже закрыта**.

- **Решения:** Использовать `JOIN FETCH` в JPQL, аннотацию `@EntityGraph`, выполнять вызов внутри метода с `@Transactional` или использовать DTO-проекции.
