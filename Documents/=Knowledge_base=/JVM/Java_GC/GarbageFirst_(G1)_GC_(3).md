## 🗑 G1 GC (*Garbage First*)
**G1 (Garbage-First)** — это сборщик мусора, который стал **дефолтным в Java 9** и пришёл на смену CMS. Он предназначен для серверных приложений с **большими кучами** (от 6 ГБ) и требованием **предсказуемых пауз** (не более 0.5–1 секунды) [](https://docs.oracle.com/javase/8/docs/technotes/guides/vm/G1.html?source=fb#1#1)[](https://graphsearch.epfl.ch/en/concept/35316136#1).

---
# 🥇 Главная идея
**Heap** делится не на 2 области (Young/Old), а на **много одинаковых регионов** (*обычно ~2048 регионов, размер 1–32 МБ каждый*) [](https://docs.oracle.com/javase/8/docs/technotes/guides/vm/G1.html?source=fb#1#1)[](https://docs.oracle.com/javase/8/docs/technotes/guides/vm/gctuning/g1_gc_tuning.html#1).
👉 G1 собирает **сначала самые «мусорные» регионы** (*отсюда название «Garbage-First»*).

---
# 🧩 Архитектура
### Heap → набор регионов (обычно `1`–`32`MB)
> Типы регионов:
> - **Eden** (молодой, новые объекты)   
> - **Survivor** (выживший после GC)   
> - **Old** (старый, долгоживущие объекты)   
> - **Humongous** *(Очень крупные объекты// обычно >50% региона в G1)*    
> - **Free** (свободный)

---
# 🔄 Как работает

### 1️⃣ Young GC
> - Чистится Eden    
> - Короткие Stop-the-World паузы    
> - Быстро    
### 2️⃣ Concurrent Mark
> - Параллельно помечает живые объекты в Old    
> - Минимальные паузы    
### 3️⃣ Mixed GC
> - Чистит часть Old + Young    
> - Выбирает регионы с максимумом мусора    

---
# ⏱ Главная цель

👉 **Предсказуемые паузы**
Настраивается через:
**`-XX:MaxGCPauseMillis=200`**
> G1 пытается уложиться в заданный *target* *(Доп. нагрузка на CPU из-за работы GC)*.

---
# ⚙ Плюсы
> ✅ Предсказуемый **latency**  *(Время отклика системы //`запрос` → `ответ`)*
> ✅ Хорош для больших **heap** (>4–8GB)  
> ✅ Параллельная и конкурентная работа  
> ✅ Меньше **full GC** *(Полная сборка всего heap// `Young` + `Old`)*

---
# ⚠ Минусы
> ❌ Сложная внутренняя логика  
> ❌ Немного выше CPU overhead *(Доп. нагрузка на CPU из-за работы GC)*  
> ❌ Humongous объекты могут фрагментировать heap

---
# 🧠 Когда использовать

| Сценарий       | Подходит? |
| -------------- | --------- |
| Микросервисы   | Да        |
| Большой heap   | Да        |
| Низкая latency | Да        |
| Real-time      | Нет       |

---
# 🧠 Как запомнить

**CMS** → минимальные паузы  
**Parallel** → максимальный throughput  
**G1** → баланс + предсказуемость
