**Ребалансировка** — это перераспределение партиций между консюмерами в группе при добавлении/удалении консюмеров или изменении топиков.

---

**Три основные стратегии назначения партиций (`partition.assignment.strategy`):**

## 1. **Range **<br>(по умолчанию для старых версий)  
    — Каждый топик разбивается на диапазоны, которые распределяются между консюмерами.  
    → **Проблема**: при неравном количестве партиций на консюмера возникают перекосы (один консюмер получает на 2 партиции больше).
    
## 2. **RoundRobin**  
    — Все партиции всех подписанных топиков распределяются по кругу, как карточная колода.  
    → **Плюс**: равномерное распределение.  
    → **Минус**: при перебалансировке перемещается **много** партиций между консюмерами (stop-the-world для всей группы).
    
## 3. **Sticky (начиная с Kafka 2.4, рекомендуемая)**  
    — Максимально сохраняет существующее назначение, перемещая **только минимальное количество партиций** для достижения баланса.  
    → **Плюс**: минимизирует "шок" при ребалансе (меньше остановок обработки).
    
## 4. **Cooperative Sticky (Kafka 2.4+, для Incremental Cooperative Rebalancing)**  
    — Поэтапная ребалансировка: сначала освобождаются "лишние" партиции, потом назначаются новые.  
    → **Ключевое отличие**: вся группа не пересобирается целиком, партиции перераспределяются **инкрементально**.  
    → Минимальный даунтайм, рекомендована для продакшена.

---
**Главное для Middle:**

> При ребалансировке **все консюмеры в группе приостанавливают чтение** (кроме Cooperative — там пауза частичная).  
> Если обработка сообщений долгая, а `max.poll.interval.ms` маленький — консюмер будет исключён из группы раньше, чем завершит обработку, что вызовет бесконечные ребалансировки (критичная проблема в продакшене).

---

**Что делать, чтобы минимизировать проблемы:**

1. Использовать **`Cooperative Sticky`**.
    
2. Увеличить `max.poll.interval.ms` (например, до 5-10 минут), если обработка тяжёлая.
    
3. Уменьшить `max.poll.records`, чтобы батчи были меньше.
    
4. Мониторить **consumer lag** и частоту ребалансировок через JMX-метрики.
