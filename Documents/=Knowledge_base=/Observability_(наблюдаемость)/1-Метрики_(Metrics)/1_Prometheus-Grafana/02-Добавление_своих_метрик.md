Добавление своих метрик в Spring Boot делается через **Micrometer**, который уже встроен в *Actuator*. Тебе нужно просто внедрить `MeterRegistry` и зарегистрировать в нем нужный тип метрики.

Вот четыре основных типа метрик, которые покрывают 95% задач, и как их добавить.

### 1. Counter (*Счетчик*)

Используй для **подсчета событий**: сколько раз что-то произошло. Значение может только расти.

**Пример:** подсчет созданных заказов.
```java
import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

@Component
public class OrderMetrics {
    private final Counter ordersCreated;
    
    public OrderMetrics(MeterRegistry registry) {
        this.ordersCreated = Counter.builder("orders.created")
            .description("Total number of orders created")
            .tag("type", "business")
            .register(registry);
    }
    
    public void onOrderCreated() {
        ordersCreated.increment();
    }
}
```
Теперь при каждом вызове `onOrderCreated()` счетчик увеличивается. 
В Prometheus это будет выглядеть как `orders_created_total`[](https://raw.githubusercontent.com/OneUptime/blog/refs/heads/master/posts/2025-07-02-spring-boot-micrometer-metrics/README.md#1)[](https://www.guance.com/learn/articles/java-prometheus?gc_source=learn_datadog_vs_newrelic)[](https://cloud.tencent.com.cn/developer/article/2560717?from=15425&policyId=undefined&traceId=&frompage=seopage#2).

### 2. Gauge (*Датчик*)

Используй для **мгновенного значения**, которое может расти и падать: размер очереди, количество активных пользователей, использование памяти.

**Пример:** отслеживание размера очереди задач.
```java
import io.micrometer.core.instrument.Gauge;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;
import java.util.concurrent.ConcurrentLinkedQueue;

@Component
public class TaskQueueMetrics {
    private final ConcurrentLinkedQueue<String> taskQueue = 
								    new ConcurrentLinkedQueue<>();
								    
    public TaskQueueMetrics(MeterRegistry registry) {
        Gauge.builder(
	        "tasks.queue.size", taskQueue, ConcurrentLinkedQueue::size)
            .description("Current number of tasks in queue")
            .register(registry);
    }
    
    public void addTask(String task) {
        taskQueue.add(task);
    }
}
```
*Micrometer* будет вызывать `taskQueue.size()` каждый раз, когда *Prometheus* запрашивает метрики[](https://raw.githubusercontent.com/OneUptime/blog/refs/heads/master/posts/2025-07-02-spring-boot-micrometer-metrics/README.md#1)[](https://www.guance.com/learn/articles/java-prometheus?gc_source=learn_datadog_vs_newrelic).

### 3. Timer (*Таймер*)

Используй для **измерения длительности операций** и получения статистики (*среднее, максимум, процентили*).

**Пример:** измерение времени обработки платежа.
```java
import io.micrometer.core.instrument.Timer;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

@Component
public class PaymentMetrics {
    private final Timer paymentTimer;
    
    public PaymentMetrics(MeterRegistry registry) {
        this.paymentTimer = Timer.builder("payment.processing.time")
            .description("Time taken to process a payment")
            // Важно: включает процентили
            .publishPercentiles(0.5, 0.95, 0.99) 
            .register(registry);
    }
    
    public void processPayment(Runnable paymentLogic) {
        paymentTimer.record(paymentLogic);
    }
}
```
> **Важно:** По умолчанию Timer отдает только count/sum/max. Для расчета P95/P99 через Grafana обязательно добавь `.publishPercentileHistogram(true)` или `.publishPercentiles(...)`[](https://www.guance.com/learn/articles/java-prometheus?gc_source=learn_datadog_vs_newrelic).

### 4. DistributionSummary (*Распределение*)

Используй для **распределения значений**, которые не являются временем: размер заказа, размер ответа API.

**Пример:** запись суммы заказа.
```java
import io.micrometer.core.instrument.DistributionSummary;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Component;

@Component
public class OrderAmountMetrics {
    private final DistributionSummary orderAmount;
    
    public OrderAmountMetrics(MeterRegistry registry) {
        this.orderAmount = DistributionSummary.builder("order.amount")
            .description("Distribution of order amounts")
            .baseUnit("USD")
            .register(registry);
    }
    
    public void recordAmount(double amount) {
        orderAmount.record(amount);
    }
}
```
Это позволит видеть медианный чек, максимальный чек и распределение сумм[](https://raw.githubusercontent.com/humank/genai-demo/a48be6fb9534feb6b35dfc16ae9edab30543f38b/docs/viewpoints/operational/monitoring/metrics.md#1).

### 💡 Ключевые правила

1. **Не создавай метрики в цикле** — создай их один раз при инициализации бина и сохрани в поле, а в методах только вызывай `increment()` или `record()`[](https://raw.githubusercontent.com/humank/genai-demo/a48be6fb9534feb6b35dfc16ae9edab30543f38b/docs/viewpoints/operational/monitoring/metrics.md#1).
    
2. **Следи за кардинальностью тегов** — никогда не используй в тегах `userId`, `orderId` или полный URL. Используй только шаблоны (`/api/orders/{id}`) или категории (`status=success`), иначе Prometheus «взорвется» от количества уникальных метрик[](https://raw.githubusercontent.com/OneUptime/blog/refs/heads/master/posts/2025-07-02-spring-boot-micrometer-metrics/README.md#1)[](https://www.guance.com/learn/articles/java-prometheus?gc_source=learn_datadog_vs_newrelic).
    
3. **Именование** — придерживайся схемы `domain.action.result`, например `orders.created.success`[](https://raw.githubusercontent.com/OneUptime/blog/refs/heads/master/posts/2025-07-02-spring-boot-micrometer-metrics/README.md#1)[](https://raw.githubusercontent.com/humank/genai-demo/a48be6fb9534feb6b35dfc16ae9edab30543f38b/docs/viewpoints/operational/monitoring/metrics.md#1).    

После добавления этих метрик они автоматически появятся на эндпоинте `/actuator/prometheus` и будут доступны для графиков в Grafana.
