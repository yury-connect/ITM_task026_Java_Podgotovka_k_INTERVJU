# Dead Letter Topic (DLT)

**Dead Letter Topic (DLT)** — это служебный топик, куда перенаправляются сообщения, которые **не удалось обработать** потребителю после нескольких повторных попыток (retries).
### **Зачем нужен:**
1. **Не терять данные** — проблемное сообщение не дропается, а сохраняется для ручного разбора.
    
2. **Не блокировать поток** — основная очередь продолжает работать, а "битое" сообщение уходит в сторону.
    
3. **Диагностика и отладка** — в DLT складывается оригинальное сообщение + заголовки с причиной ошибки и стектрейсом.
### **Как это работает (стандартный паттерн):**
```text
Consumer пытается обработать → ошибка → retry (например, 3 раза)
→ всё равно ошибка → продюсер отправляет в DLT → коммитит offset основного топика
```
### **Важные нюансы для Middle:**
- В DLT сообщения хранятся **бессрочно** (или с долгим retention), чтобы инженер успел разобраться.
    
- В Kafka-экосистеме готовые реализации есть в **Spring Kafka** (`@RetryableTopic`, `@DltHandler`) и **Kafka Streams**.
    
- Главная ошибка новичков — положить в DLT сообщение без **контекста ошибки** (обязательно добавляйте `headers` с причиной, временем, количеством попыток).
    
- DLT должен иметь **больше партиций**, чем основной топик? Нет, обычно достаточно одной партиции, т.к. это невысоконагруженный "мусорный" поток, но если ошибки массовые — нужно мониторить.

---
**Короткая формулировка для ответа:**

> _"Dead Letter Topic — это топик-изолятор для сообщений-отказников. После исчерпания всех ретраев консюмер не удаляет сообщение, а перемещает его в DLT с метаданными об ошибке. Это гарантирует, что мы не потеряем данные и не застопорим обработку, а инцидент можно разобрать постфактум."_
