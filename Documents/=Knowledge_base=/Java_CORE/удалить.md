LongAdder vs AtomicInteger
### ⚛️ 4. LongAdder vs AtomicInteger

- ⚛️ **`AtomicInteger`:**
            
    - Держит единое `volatile`-значение и обновляет его через CAS в циклическом `spin-lock`.
        
    - _При высокой конкуренции:_ Потоки массово терпят неудачу при CAS и сжигают CPU в бесконечных циклах повтора.
    
- 🚀 **`LongAdder`:**
            
    - Предназначен для **высоконагруженных счетчиков (High Contention)**.
        
    - Внутри хранит динамический массив ячеек (`Cell[]`). При состязании потоки случайным образом распределяются по разным ячейкам и обновляют их независимо.
        
    - Метод `sum()` суммирует значения всех ячеек при запросе.
        
    - _Когда использовать:_ Когда нужен частый инкремент счетчика из сотен потоков, а точный CAS (`compareAndSet`) не требуется.

## 🎯 Суть LongAdder (на пальцах)

Представь **школьную доску** и **учеников**:

- **AtomicLong**: Это **одна доска**. 100 учеников (потоков) бегут к ней одновременно, чтобы поставить плюсик. Возникает драка (CAS-конфликт). Ученики толкаются, ошибки, постоянные повторные попытки. **Все тормозят**.
    
- **LongAdder**: Это **много досок** (массив `Cell[]`). Учитель говорит: «Ребята, не толпитесь! Кто четный — бежит к Доске №1, кто нечетный — к Доске №2, остальные — к Доске №3». Ученики раскиданы, драк нет, все ставят плюсики супер-быстро. В конце учитель просто складывает числа со всех досок (`sum()`). **Все летают**.

---
## 🧠 Как это устроено внутри?

- **Пока мало потоков**: LongAdder ведет себя как обычный `AtomicLong` (одна ячейка).
    
- **Как только начались драки (конфликты CAS)**: Он **динамически расширяет** массив `Cell[]`. Чем больше потоков толкаются — тем больше ячеек создается (до размера количества ядер CPU).
    
- **Поток не блокируется никогда!** Он просто находит свою ячейку через хеш-функцию (обычно `ThreadLocalRandom`) и дергает `cas` только внутри этой маленькой ячейки.
    
- Когда нужно узнать точное значение (`sum()`) — он просто пробегает по всем ячейкам и складывает их.

---
## 🆚 LongAdder vs AtomicLong (Главные отличия)

- **AtomicLong**: Одна переменная. 100 потоков пытаются сделать CAS. 99 из них проваливаются и крутятся в цикле заново. **Процессор горит**.
    
- **LongAdder**: 100 потоков → 100 ячеек (условно). Каждый делает CAS в своей ячейке. **Драк нет**. Скорость инкремента в 5–10 раз выше при высокой нагрузке.

---
## 🤔 Когда использовать? (Очень простое правило)

- **Используй LongAdder**, если:
    
    - Ты считаешь **статистику** (количество хитов, кликов, ошибок).
        
    - Тебе **не нужна** мгновенная атомарная операция "прочитал-изменил-вернул" (как `incrementAndGet()`).
        
    - У тебя больше 2-3 потоков, которые бесконечно дергают счетчик.
        
- **Используй AtomicLong**, если:
    
    - Тебе нужно атомарно **получить старое значение** и поставить новое (`compareAndSet`).
        
    - Ты строишь **блокировку** или генератор уникальных ID (где важен строгий порядок).
        
    - У тебя всего 1-2 потока (там LongAdder излишен).

---
## 💥 Бомба для собеседования (Связка с False Sharing!)

Внутри `LongAdder` ячейки (`Cell`) **помечены аннотацией `@Contended`**!

Помнишь наш прошлый разговор про кэш-линии? Разработчики Java специально раздувают эти ячейки (падинг), чтобы они **не лежали рядом** в кэше процессора. Если бы они лежали рядом — даже при работе с разными ячейками, процессор синхронизировал бы кэш-линии (False Sharing). Они этого избежали!

---
## 🚀 Пример кода (Как пользоваться)
```java
// Вместо:
AtomicLong counter = new AtomicLong();
counter.incrementAndGet(); // Больно при 100 потоках
// Пиши:
LongAdder counter = new LongAdder();
counter.increment(); // Быстро при 100 потоках
long total = counter.sum(); // Берем итог
```

## 🔥 Итоговая фраза для интервьюера:

> _"Я использую `LongAdder` для счетчиков метрик, где мне важен итог через `sum()`, а не мгновенное значение. Он работает за счет шардирования нагрузки по массиву ячеек, каждая из которых защищена `@Contended` от False Sharing. Однако он не заменяет `AtomicLong` там, где нужна атомарная операция `getAndSet()` или построение очередей."_
