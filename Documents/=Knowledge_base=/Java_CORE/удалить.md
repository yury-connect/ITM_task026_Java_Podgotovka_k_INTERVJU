Чем **явные** блокировки (*ReentrantLock*) отличаются от **встроенной** синхронизации (*synchronized*)? Какие возможности они дают?

### Ответ:
**synchronized** — это синтаксическая конструкция JVM, а  
**ReentrantLock** — класс из пакета java.`util.concurrent.locks`.

`ReentrantLock` предоставляет возможности, которых нет у `synchronized`:
1. **Неблокирующий захват** (*tryLock()*): Позволяет попытаться взять блокировку без ухода в ожидание, либо с указанием таймаута (tryLock(time, unit)).
2. **Прерываемое ожидание** (*lockInterruptibly()*): Поток реагирует на Thread.interrupt(), пока ждет блокировку.
3. **Честность** (*Fairness*): Конструктор new ReentrantLock(true) гарантирует FIFO-очередь ожидания для потоков (предотвращает starvation).
4. **Гибкие условия ожидания** (*Condition*): Позволяет ожидать конкретных условий на одной блокировке (аналог wait/notify, но с несколькими независимыми очередями сигналов).
