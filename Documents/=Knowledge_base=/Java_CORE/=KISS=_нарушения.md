**Принцип KISS** (аббревиатура от **«Keep It Simple, Stupid»** — _«Делай проще, тупица»_ или более вежливо _«Делай просто и понятно»_) — это один из фундаментальных принципов программирования и проектирования систем.

### 🎯 В чём суть?
Главная идея — **система работает лучше всего, если она остается простой, а не усложняется без необходимости**.

В разработке ПО существует естественная тенденция к переусложнению (Overengineering): написание универсальных фреймворков для простых задач, создание десятков классов «на будущее» или применение сложных паттернов там, где достаточно одной функции. KISS призывает бороться с этим.

### ❌ Пример нарушения KISS
Разработчик создает задачу «*Сложить два числа и вывести результат*»:
```Java
// Переусложнённый код
public interface AdditionStrategy {
    int add(int a, int b);
}

public class SimpleAdditionStrategy implements AdditionStrategy {
    @Override
    public int add(int a, int b) {
        return a + b;
    }
}

public class MathContext {
    private AdditionStrategy strategy;
    
    public MathContext(AdditionStrategy strategy) {
        this.strategy = strategy;
    }

    public int execute(int a, int b) {
        return strategy.add(a, b);
    }
}
```


### ✅ Соблюдение KISS
То же самое решение, сделанное максимально просто:
```Java
// Простой и понятный код
public class MathUtils {
    public static int add(int a, int b) {
        return a + b;
    }
}
```

### 💡 Почему KISS так важен?
	
1. **Легче читать и понимать:** Простой код понятен коллегам (и вам через полгода) без дополнительных инструкций.
    
2. **Меньше багов:** Чем меньше строк, абстракций и ветвлений, тем меньше мест, где можно допустить ошибку.
    
3. **Быстрее отладка и поддержка:** Если что-то сломалось в простом коде, место поломки находится за минуты.
    
4. **Легче тестировать:** Простые функции без сложных внешних связей покрываются unit-тестами элементарно.

### ⚖️ KISS vs YAGNI vs DRY
Часто KISS упоминается вместе с другими базовыми принципами:
	
- **KISS** — пиши _просто_ (избегай сложной архитектуры там, где она не нужна).
    
- **YAGNI** (_You Ain't Gonna Need It_) — не пиши функционал _про запас_, пока в нем нет реальной потребности.
    
- **DRY** (_Don't Repeat Yourself_) — избегай дублирования кода.

### 🎤 Короткая шпаргалка для собеседования

> «Принцип KISS (Keep It Simple, Stupid) означает, что решение должно быть максимально простым и понятным. Не нужно добавлять лишние абстракции, паттерны или универсальность "на будущее" (Overengineering), если задача решается простым способом. Простой код проще читать, тестировать и поддерживать.»
