# 📦 Maven vs Gradle

- 📄 **Maven**
    - Конфигурация — XML, `pom.xml`.
    - Основа — стандартный **lifecycle**: `validate → compile → test → package → verify → install → deploy`.
    - ✅ Плюсы: предсказуемость, стандартная структура проекта, много готовых плагинов.
    - ❌ Минусы: многословный XML, меньше гибкости.

- 🚀 **Gradle**
    - Конфигурация — **Groovy DSL или Kotlin DSL**, например `build.gradle.kts`.
    - Основа — **граф задач (Task Graph)**.
    - ✅ Плюсы: гибкость, инкрементальная сборка, кэширование, параллельное выполнение, Daemon.
    - ❌ Минусы: сложнее разобраться в кастомной конфигурации и отлаживать сложные build-скрипты.

### ⚡ Главное отличие
>
> **Maven — более стандартизированный и декларативный: описываем, что нужно собрать, через `pom.xml` и lifecycle.**
> 
> **Gradle — более гибкий: сборка строится вокруг задач и позволяет гораздо свободнее программировать процесс сборки.**

---
## 🔥 Что могут спросить дополнительно

### 1. Gradle Daemon
Gradle может использовать **долгоживущий JVM-процесс — Daemon**.

Он сохраняет состояние между запусками, поэтому повторные сборки обычно быстрее.

У Maven традиционно каждый запуск `mvn` стартует отдельный JVM-процесс. **Maven Daemon (`mvnd`) существует отдельно от обычного Maven CLI.**

---
### 2. Зависимости

Здесь в твоей заготовке есть важный нюанс.

**Maven:**
> По умолчанию при конфликте версий используется **nearest definition** — версия зависимости, находящаяся ближе к корню дерева зависимостей.

**Gradle:**
> По умолчанию при конфликте версий обычно выбирается **наиболее новая версия**.

Например:
```
A → lib:1.0
B → lib:2.0
```

Maven может выбрать `1.0`, если она ближе к корню.

Gradle по умолчанию выберет `2.0`.

---
### 3. Мультимодульность

**Maven** использует `<modules>` и Reactor для сборки нескольких модулей. Наследование через `<parent>` — отдельный механизм управления общей конфигурацией, а не обязательное условие мультимодульности.

**Gradle** описывает состав проекта через `settings.gradle(.kts)` и поддерживает **Composite Builds** — можно подключить другой Gradle build как замену опубликованной зависимости.

### 🎯 Что реально запомнить для Middle

> **Maven — XML + lifecycle + convention + предсказуемость.**
> 
> **Gradle — DSL + tasks + гибкость + кэширование + Daemon.**
> 
> При конфликте зависимостей: **Maven → nearest, Gradle → highest version по умолчанию.**
