Если объяснять максимально просто: **Query** и **Mutation** — это два способа, которыми фронтенд может «*поговорить*» с бэкендом в **GraphQL**.

Всё крутится вокруг одного правила: **Query — это чтение, Mutation — это изменение.**

---
## 🔍 **Query** (*Запрос*) — «Дай мне данные»

Это аналог `GET`-запроса в REST. Ты просишь сервер вернуть информацию, и ничего в базе данных не меняется.

- **Что делает:** Читает данные (*получить список пользователей, найти заказ по ID, посмотреть профиль*).
    
- **Как выглядит:**
```graphql
query {
  user(id: 1) {
    name
    email
  }
}
```
    
- **Особенность:** Если в одном запросе ты просишь три разных Query (например, пользователя, список товаров и погоду), сервер может выполнить их **параллельно**, чтобы быстрее отдать ответ.

---
## ✍️ **Mutation** (*Мутация*) — «Сделай что-то с данными»

Это аналог `POST`, `PUT` или `DELETE`. Ты просишь сервер создать, обновить или удалить данные. Слово «мутация» означает изменение (*мутацию*) состояния.

- **Что делает:** Изменяет данные (*создать пользователя, обновить пароль, удалить товар*).
    
- **Как выглядит:**
```graphql
mutation {
  createUser(name: "Юрий", email: "test@mail.ru") {
    id
    name
  }
}
```
    
- **Особенность №1 (*Последовательность*):** Если ты отправишь в одной мутации два действия (например, «создать заказ» и «списать деньги»), сервер выполнит их **строго по очереди**. Сначала первое, потом второе. Это сделано для безопасности, чтобы не сломать данные.
    
- **Особенность №2 (*Возврат результата*):** Мутация не просто говорит «Успех!». Она возвращает те данные, которые ты попросил (например, ID только что созданного пользователя). Это позволяет фронтенду сразу обновить интерфейс, не делая повторный Query.    

---
### 🎯 Главное отличие (*для собеседования*)

| |**Query**|**Mutation**|
|---|---|---|
|**Смысл**|Чтение (Read)|Изменение (Write)|
|**Аналог в REST**|`GET`|`POST`, `PUT`, `DELETE`|
|**Изменяет данные?**|❌ Нет|✅ Да|
|**Порядок выполнения**|Может быть параллельным|Строго последовательный|
|**Кэширование**|Хорошо кэшируется (как GET)|Не кэшируется|

**Одной фразой:** _Query — это «безопасный» вопрос, который ничего не ломает. Mutation — это команда, которая меняет состояние системы._
