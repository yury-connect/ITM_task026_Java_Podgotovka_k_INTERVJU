## 🧵 Подробный разбор локов в Java

---
## 1️⃣ `synchronized` — Встроенный монитор

### 📌 Что это?
Блокировка, встроенная в каждый объект Java. Работает на уровне байт-кода.

### ⚙️ Как работает
- Каждый объект имеет **монитор**.    
- Поток, входя в `synchronized` блок, **захватывает** этот монитор.    
- Другие потоки **ждут** освобождения.    

### 🎯 Способы использования
```java
// 1. Блокировка на объекте (this)
public void method() {
    synchronized(this) {
        // критическая секция
    }
}
// 2. Синхронизированный метод (блокировка на this)
public synchronized void method() {
    // критическая секция
}
// 3. Синхронизированный статический метод (блокировка на Class)
public static synchronized void staticMethod() {
    // критическая секция
}
// 4. Блокировка на любом объекте
private final Object lock = new Object();
synchronized(lock) {
    // критическая секция
}
```

### ✅ Плюсы
- **Простота** — не нужно вызывать `lock()`/`unlock()`.    
- **Автоматическое освобождение** — даже при исключении.    
- **Встроен** в язык — не требует дополнительных зависимостей.    
### ❌ Минусы
- **Нельзя прервать** ожидание (`Thread.interrupt()` игнорируется).    
- **Нельзя попробовать** захватить с таймаутом.    
- **Нельзя** выбрать **честную** стратегию.    
- **Производительность** — уступает `ReentrantLock` в высоконагруженных системах.    
### 🔥 Когда использовать
- Простые случаи, где не нужна гибкость.    
- Начальные этапы разработки.    
- Быстрое решение без излишней сложности.

## 2️⃣ `ReentrantLock` — Гибкая альтернатива

### 📌 Что это?

Явная блокировка из пакета `java.util.concurrent.locks`. Дает полный контроль.

### ⚙️ Как работает
```java
ReentrantLock lock = new ReentrantLock();
lock.lock();  // захват
try {
    // критическая секция
} finally {
    lock.unlock();  // ОБЯЗАТЕЛЬНО!
}
```

### 🎯 Основные методы

|Метод|Что делает|
|---|---|
|`lock()`|Захватывает блокировку (ждет вечно)|
|`tryLock()`|Пытается захватить, возвращает `boolean` сразу|
|`tryLock(timeout, unit)`|Пытается захватить с таймаутом|
|`lockInterruptibly()`|Захватывает с возможностью прерывания|
|`unlock()`|Освобождает блокировку|
|`getHoldCount()`|Сколько раз поток вошел в блокировку|
|`isHeldByCurrentThread()`|Захвачена ли текущим потоком|

### ✅ Плюсы

- **Гибкость** — можно прервать, установить таймаут.
    
- **Честность** — можно включить очередь (`new ReentrantLock(true)`).
    
- **`tryLock()`** — неблокирующая попытка.
    
- **Лучшая производительность** в высоконагруженных системах.
    

### ❌ Минусы

- **Обязательный `unlock()` в `finally`** — забыть легко.
    
- **Сложнее** в использовании.
    

### 🔥 Когда использовать

- Нужен таймаут или прерывание.
    
- Нужна честная блокировка.
    
- Высокая конкуренция.

## 3️⃣ `ReadWriteLock` / `ReentrantReadWriteLock` — Чтение vs Запись

### 📌 Что это?

Разделяет блокировки на читательские и писательские.

### ⚙️ Как работает

java

ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
Lock readLock = rwLock.readLock();
Lock writeLock = rwLock.writeLock();
// Чтение (много потоков могут одновременно)
readLock.lock();
try {
    // читаем данные
} finally {
    readLock.unlock();
}
// Запись (только один поток)
writeLock.lock();
try {
    // пишем данные
} finally {
    writeLock.unlock();
}

### 📊 Правила

|Действие|Результат|
|---|---|
|**Читатель** vs **Читатель**|✅ Могут одновременно|
|**Читатель** vs **Писатель**|❌ Блокировка, пока писатель не закончит|
|**Писатель** vs **Писатель**|❌ Только один|

### ✅ Плюсы

- **Высокая производительность** при частом чтении.
    
- **Безопасность** — писатель не мешает читателям.
    

### ❌ Минусы

- **Риск голодания писателя** — постоянные читатели не дают писателю войти.
    
- **Сложнее** в использовании.
    
- **Не подходит** для частой записи.
    

### 🔥 Когда использовать

- Данные редко меняются (`read:write` = 100:1).
    
- Кэши, словари, конфигурации.

## 4️⃣ `StampedLock` — Оптимистичная версия (Java 8+)

### 📌 Что это?

Улучшенная альтернатива `ReadWriteLock` с **оптимистичным чтением**.

### ⚙️ Как работает

java

StampedLock lock = new StampedLock();
// 1️⃣ ОПТИМИСТИЧНОЕ ЧТЕНИЕ (без блокировки!)
long stamp = lock.tryOptimisticRead();
// читаем данные
if (!lock.validate(stamp)) {
    // данные изменились → повторяем чтение с блокировкой
    stamp = lock.readLock();
    try {
        // читаем данные заново
    } finally {
        lock.unlockRead(stamp);
    }
}
// 2️⃣ ПЕССИМИСТИЧНОЕ ЧТЕНИЕ
long stamp = lock.readLock();
try {
    // читаем данные
} finally {
    lock.unlockRead(stamp);
}
// 3️⃣ ЗАПИСЬ
long stamp = lock.writeLock();
try {
    // пишем данные
} finally {
    lock.unlockWrite(stamp);
}

### 🎯 Три режима

|Режим|Что делает|Блокирует ли|
|---|---|---|
|**Оптимистичное чтение**|Читает без блокировки, потом проверяет штамп|❌ Нет|
|**Пессимистичное чтение**|Как `ReadLock` у `ReadWriteLock`|✅ Да (читатели могут)|
|**Запись**|Как `WriteLock` у `ReadWriteLock`|✅ Да (эксклюзивно)|

### ✅ Плюсы

- **Максимальная производительность** (оптимистичное чтение).
    
- Можно **преобразовывать** блокировки (`tryConvertToWriteLock()`).
    

### ❌ Минусы

- **Не реентерабельный** — повторный захват приводит к дедлоку.
    
- **Сложный** в использовании.
    

### 🔥 Когда использовать

- Очень высокая нагрузка на чтение.
    
- Данные редко меняются.
    
- Нужна максимальная производительность.

## 5️⃣ `Semaphore` — Счетчик разрешений

### 📌 Что это?

Семафор — ограничивает **количество одновременных потоков**.

### ⚙️ Как работает

java

Semaphore semaphore = new Semaphore(3);  // разрешаем 3 потока
// Поток пытается войти
semaphore.acquire();  // если мест нет — ждет
try {
    // работа с ресурсом
} finally {
    semaphore.release();  // освобождаем место
}

### 🎯 Виды семафоров

java

// Нечестный (по умолчанию) — быстрее
Semaphore sem = new Semaphore(3);
// Честный — соблюдает очередность
Semaphore fairSem = new Semaphore(3, true);

### ✅ Плюсы

- **Управляет пулом ресурсов** (база данных, соединения).
    
- **Гибкий** счетчик.
    
- Можно **проверить** количество разрешений (`availablePermits()`).
    

### ❌ Минусы

- Не привязан к конкретному ресурсу.
    
- Требует явного `release()`.
    

### 🔥 Когда использовать

- **Пул соединений** с БД.
    
- Ограничение одновременных запросов к API.
    
- Реализация паттерна **Bounded Buffer**.

## 6️⃣ `CountDownLatch` — Ожидание событий

### 📌 Что это?

Одноразовый барьер — ждем, пока счетчик не достигнет нуля.

### ⚙️ Как работает

java

CountDownLatch latch = new CountDownLatch(3);  // ждем 3 события
// Поток-воркер (выполняется 3 раза)
latch.countDown();  // уменьшаем счетчик
// Главный поток ждет
latch.await();  // блокируется, пока счетчик не станет 0

### 🎯 Пример

java

// Запускаем 3 воркера
CountDownLatch latch = new CountDownLatch(3);
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // делаем работу
        latch.countDown();
    }).start();
}
// Ждем, пока все 3 закончат
latch.await();
System.out.println("Все воркеры завершили работу!");

### ✅ Плюсы

- **Простой**.
    
- **Надежный** — счетчик не может быть увеличен.
    

### ❌ Минусы

- **Одноразовый** — нельзя использовать повторно.
    
- Нельзя увеличить счетчик.
    

### 🔥 Когда использовать

- **Дождаться** завершения N потоков.
    
- **Синхронизация** запуска (все готовы — поехали!).

## 7️⃣ `CyclicBarrier` — Многократный барьер

### 📌 Что это?

Многоразовый барьер — все потоки ждут друг друга.

### ⚙️ Как работает

java

CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("Все собрались! Пошли дальше.");
});
// 3 потока
barrier.await();  // ждем остальных
// когда все трое вызвали await() — барьер ломается

### 🎯 Разница с `CountDownLatch`

|Характеристика|`CountDownLatch`|`CyclicBarrier`|
|---|---|---|
|**Использование**|Одноразовый|Многоразовый|
|**Счетчик**|Уменьшается|Достигает предела|
|**Действие**|После 0 — больше не используется|Можно переиспользовать (`reset()`)|
|**Синхронизация**|Один поток ждет остальных|Все потоки ждут друг друга|

### ✅ Плюсы

- **Многоразовый**.
    
- Можно переиспользовать через `reset()`.
    

### ❌ Минусы

- При `reset()` потоки, ожидающие барьер, получают `BrokenBarrierException`.
    

### 🔥 Когда использовать

- **Поэтапная обработка** (фазы).
    
- **Команда** собирается перед каждым этапом.
    
- Например, **партиционирование данных**.

## 8️⃣ `Phaser` — Гибкий барьер с фазами

### 📌 Что это?

Улучшенный `CyclicBarrier` с динамическим количеством участников.

### ⚙️ Как работает

java

Phaser phaser = new Phaser();
// Регистрируем участников
phaser.register();  // +1
phaser.bulkRegister(5);  // +5
// Участник ждет
phaser.arriveAndAwaitAdvance();  // ждем других на этой фазе
// Участник уходит
phaser.arriveAndDeregister();  // завершил работу

### 🎯 Основные методы

|Метод|Что делает|
|---|---|
|`register()`|Добавляет нового участника|
|`bulkRegister(n)`|Добавляет n участников|
|`arrive()`|Сообщает, что участник прибыл (не ждет)|
|`arriveAndAwaitAdvance()`|Прибыл + ждет остальных|
|`arriveAndDeregister()`|Прибыл + уходит|
|`getPhase()`|Текущая фаза|

### ✅ Плюсы

- **Динамическое** количество участников.
    
- **Многофазный**.
    

### ❌ Минусы

- Сложнее в использовании.
    

### 🔥 Когда использовать

- **Динамические** коллективы.
    
- **Многофазные** алгоритмы.
    
- Например, **MapReduce** с динамическим числом воркеров.

## 9️⃣ `Exchanger` — Обмен данными

### 📌 Что это?

Точка синхронизации для обмена данными между двумя потоками.

### ⚙️ Как работает

java

Exchanger<String> exchanger = new Exchanger<>();
// Поток 1
String data1 = "Hello from Thread1";
String data2 = exchanger.exchange(data1);
// теперь data2 = "Hello from Thread2"
// Поток 2
String data1 = "Hello from Thread2";
String data2 = exchanger.exchange(data1);
// теперь data2 = "Hello from Thread1"

### ✅ Плюсы

- **Простой**.
    
- **Синхронный** — оба потока обмениваются одновременно.
    

### ❌ Минусы

- Только **два** потока.
    
- Оба потока должны быть готовы к обмену.
    

### 🔥 Когда использовать

- **Producer-Consumer** с буфером данных.
    
- **Алгоритмы** с обменом данными между потоками.
    
- Например, два потока обмениваются промежуточными результатами.

## 🔟 `LockSupport` — Базовый парковщик

### 📌 Что это?

Утилитный класс для парковки потоков.

### ⚙️ Как работает

java

Thread thread = new Thread(() -> {
    LockSupport.park();  // останавливаем поток
    System.out.println("Проснулся!");
});
thread.start();
Thread.sleep(1000);
LockSupport.unpark(thread);  // пробуждаем поток

### 🎯 Особенности

- **Однократная** парковка.
    
- **Не требует** объекта блокировки.
    
- Можно парковать **конкретный** поток.
    

### ✅ Плюсы

- **Легковесный**.
    
- Используется внутри всех `java.util.concurrent.locks`.
    

### ❌ Минусы

- **Низкоуровневый**.
    
- Парковка **не блокирует** прерывание.
    

### 🔥 Когда использовать

- **Реализация собственных** примитивов синхронизации.
    
- **Профилирование** и отладка.

|`CountDownLatch`|Одноразовый барьер|Ждем завершения N потоков|
|`CyclicBarrier`|Многоразовый барьер|Поэтапная синхронизация групп|
