# ⚡ `Future` vs `CompletableFuture`

Это эволюция API для работы с **асинхронными задачами**.

---
## 🐢 `Future`

`Future` — старый и простой интерфейс, представляющий **результат асинхронной операции**, который может быть ещё не готов.

Основные возможности:
- `get()` — получить результат, **блокируя поток** до завершения;
- `isDone()` — проверить, завершилась ли задача;
- `cancel()` — отменить задачу.

Главная проблема — **ограниченный API**: нельзя нормально строить цепочки асинхронных операций, комбинировать несколько `Future` и удобно обрабатывать ошибки.
```java
Future<String> future = executor.submit(() -> "Hello");
String result = future.get(); // блокируем поток
```

---
## 🚀 `CompletableFuture`

`CompletableFuture` реализует `Future`, но предоставляет гораздо более богатый API для построения **асинхронных цепочек**.

Можно:
- 🔗 продолжить выполнение → `thenApply`, `thenAccept`, `thenRun`;
- ❌ обработать ошибку → `exceptionally`, `handle`;
- 🔀 объединить результаты → `thenCombine`;
- ⛓️ построить зависимую цепочку → `thenCompose`;
- 🏁 дождаться первого результата → `anyOf`;
- 🤝 дождаться всех → `allOf`.

Пример:
```java
CompletableFuture
    .supplyAsync(() -> getUser())
    .thenApply(user -> user.getName())
    .thenAccept(System.out::println)
    .exceptionally(ex -> {
        ex.printStackTrace();
        return null;
    });
```
с комментариями:
```java
CompletableFuture
    // 🚀 Запускаем асинхронную задачу.
    // supplyAsync() принимает Supplier<T>, который должен вернуть результат.
    // Здесь getUser() выполняется асинхронно, а результатом будет User.
    .supplyAsync(() -> getUser())

    // 🔗 Когда supplyAsync() завершится успешно,
    // берём полученный User и преобразуем его в String — имя пользователя.
    // thenApply() возвращает новый CompletableFuture<String>.
    .thenApply(user -> user.getName())

    // 📤 Когда предыдущий этап вернул имя,
    // передаём его в System.out.println().
    // thenAccept() ничего не возвращает, поэтому результат здесь — Void.
    .thenAccept(System.out::println)

    // ❌ Если на любом из предыдущих этапов произошла ошибка,
    // exceptionally() перехватывает исключение.
    // ex — исключение, которое привело к неуспешному завершению Future.
    .exceptionally(ex -> {

        // 📝 Выводим информацию об ошибке.
        ex.printStackTrace();

        // 🔚 exceptionally() должен вернуть значение,
        // которым будет заменён результат при ошибке.
        // Здесь возвращаем null.
        return null;
    });
```

Здесь мы **не вызываем `get()` и не блокируем текущий поток**, а описываем последовательность действий, которые будут выполнены после завершения предыдущих этапов.

---
### 🎯 Главное отличие

> **`Future`** — получил задачу и потом в основном **ждёшь результат через `get()`**.
> 
> **`CompletableFuture`** — позволяет **строить асинхронные цепочки, комбинировать операции и обрабатывать ошибки без необходимости блокироваться на каждом шаге**.

### 🧠 Запомнить одной фразой
- **Future → «Когда будет результат?»**
- **CompletableFuture → «Что делать, когда результат будет?»**
