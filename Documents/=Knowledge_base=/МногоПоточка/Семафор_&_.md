## **`Semaphore`, `CyclicBarrier`, `CountDownLatch`**

---
### **Semaphore (Семафор)**

> **Суть:** Счетчик разрешений.   
> Ограничивает количество потоков, одновременно работающих с ресурсом.
```java
Semaphore semaphore = new Semaphore(3); // максимум 3 потока
// Поток 1
semaphore.acquire(); // забрал разрешение (счетчик: 2)
// работа с ресурсом
semaphore.release(); // вернул (счетчик: 3)
// Поток 4 (когда счетчик = 0)
semaphore.acquire(); // БЛОКИРУЕТСЯ, ждет пока кто-то release()
```
**Где используют:**
- Пул подключений к БД (не дать создать 1000 соединений)
- Ограничение одновременных запросов к API
- Реализация пула объектов

**Важно:** 
- Поток, вызвавший `acquire()`, НЕ обязан сам делать `release()` — может любой другой поток.
- После создания и начала использования невозможно посмотреть на сколько потоков он был изначально создан, а только актуальное значение.

---
### **CountDownLatch (*Защелка*)**

> **Суть:** Одноразовый синхронизатор.  
> Один или несколько потоков ждут, пока другие выполнят **N** действий (*счетчик уменьшается до **0***).
```java
CountDownLatch latch = new CountDownLatch(3); // ждем 3 операции
// Потоки-исполнители
new Thread(() -> {
    // делаем работу
    latch.countDown(); // 3 -> 2 -> 1 -> 0
}).start();
// Главный поток ЖДЕТ, пока счетчик не станет 0
latch.await(); // блокируется до 0
System.out.println("Все сделали, поехали дальше!");
```
**Где используют:**
- Запуск сервера: ждем, пока поднимутся все компоненты    
- Параллельные вычисления: ждем завершения всех подзадач    
- Интеграционные тесты: ждем, пока все mock-сервисы стартанут    

**Ключевое отличие от Semaphore:** Нельзя увеличить обратно. Одноразовый.

---
### **CyclicBarrier (Барьер)**

> **Суть:** Точка сбора.   
> N потоков ждут **ДРУГ ДРУГА** у барьера, и только когда все собрались — одновременно продолжают работу.
```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("Все собрались! Действуем!");
});
// Поток 1
new Thread(() -> {
    // делаем что-то
    barrier.await(); // жду остальных
    // продолжаем все вместе
}).start();
// Поток 2 и 3 аналогично
```
**Ключевое отличие от CountDownLatch:**
- `CountDownLatch`: один ждет всех (событие)    
- `CyclicBarrier`: все ждут друг друга (барьер)    
- `CyclicBarrier` можно переиспользовать: после того как все собрались, барьер сбрасывается (можно использовать снова)    

**Где используют:**
- Разбивка задачи на этапы (map-reduce)    
- Асинхронная обработка с объединением результатов    
- Симуляция гонок: все стартуют одновременно    

---
### **Сравнительная таблица:**

|Характеристика|Semaphore|CountDownLatch|CyclicBarrier|
|---|---|---|---|
|Счетчик|+/- (можно увеличивать)|Только уменьшается|Константа|
|Переиспользование|Да|Нет|Да|
|Кто ждет|Все потоки|Один/несколько потоков|Все потоки|
|Блокировка|acquire()|await()|await()|
|Кто уменьшает|release() (любой)|countDown() (исполнители)|await() (сами ждущие)|
|Когда просыпаются|Когда есть разрешение|Когда счетчик = 0|Когда все собрались|
