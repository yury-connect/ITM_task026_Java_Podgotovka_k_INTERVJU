## HashMap vs Collections.synchronizedMap(HashMap) — простыми словами

---
### 🗺️ Что такое HashMap

**HashMap** — это просто несинхронизированная мапа. Если два потока одновременно попытаются в неё что-то записать или прочитать — могут возникнуть проблемы (*гонки, потеря данных, ошибки*).

---
### 🛡️ Что такое Collections.synchronizedMap(HashMap)

Это **обёртка**. Ты передаёшь в неё обычный HashMap, а она возвращает тот же HashMap, но **все его методы (*get, put, remove и т.д.*) теперь синхронизированы**.

Простыми словами: это как взять обычную HashMap и **обернуть её в синхронизированную обёртку**.
```java
Map<String, String> unsafeMap = new HashMap<>();
Map<String, String> safeMap = Collections.synchronizedMap(unsafeMap);

```

---
### 🔧 Как это работает внутри

Когда ты вызываешь `synchronizedMap()`, внутри создаётся объект класса `SynchronizedMap`. У этого класса есть поле `mutex` (*объект для блокировки*) и ссылка на исходную HashMap.
```java
// Упрощённо (как это выглядит внутри)
class SynchronizedMap<K, V> implements Map<K, V> {
    private final Map<K, V> m;      // ← твоя HashMap
    private final Object mutex;     // ← объект для синхронизации
    
    public V get(Object key) {
        synchronized (mutex) {
            return m.get(key);      // ← синхронизированный вызов
        }
    }
    
    public V put(K key, V value) {
        synchronized (mutex) {
            return m.put(key, value); // ← синхронизированный вызов
        }
    }
}
```

**Важно:** Она **не создаёт новую структуру**. Она просто **декорирует** существующий `HashMap`, добавляя **синхронизацию**.

---
### 📊 Сравнение

| Характеристика         | HashMap | synchronizedMap                        | ConcurrentHashMap             |
| ---------------------- | ------- | -------------------------------------- | ----------------------------- |
| **Синхронизация**      | ❌ Нет   | ✅ Да (*один общий лок*)                | ✅ Да (*много локов*)          |
| **Что блокируется**    | —       | Весь объект                            | Один сегмент                  |
| **Параллелизм**        | ❌ Нет   | Низкий (*все методы синхронизированы*) | Высокий                       |
| **Уровень блокировки** | —       | Метод (***весь** объект*)              | Сегмент (***часть** объекта*) |
| **Null ключи**         | ✅ Да    | ✅ Да                                   | ❌ Нет                         |

---
### 🚨 Главное ограничение

**synchronizedMap** синхронизирует **каждый метод по отдельности**, но не синхронизирует **комбинацию методов**!
```java
// ❌ НЕ атомарно!
if (!map.containsKey(key)) {
    map.put(key, value);  // Два вызова, между ними может влезть другой поток
}
```
Это пример **грязной проверки** (check-then-act). Нужно синхронизировать вручную:
```java
synchronized (map) {
    if (!map.containsKey(key)) {
        map.put(key, value);
    }
}
```

---
### 🧠 Простая аналогия

**HashMap** — это **общий блокнот**. Два человека могут одновременно писать в нём — и записи перемешаются.

**Collections.synchronizedMap()** — это **общий блокнот с одной ручкой**. Чтобы писать, нужно взять ручку (*блокировку*). Пока один пишет — второй ждёт.

**ConcurrentHashMap** — это **блокнот, разделённый на 16 отдельных страниц**. На каждой странице своя ручка. Можно писать на разных страницах одновременно.

---
### 📝 Итог
```text
HashMap:
- ❌ Не синхронизирована
- ✅ Быстрая
  
synchronizedMap:
- ✅ Синхронизирована (один глобальный лок)
- ⚠️ Медленнее, чем ConcurrentHashMap
- ⚠️ Не атомарна для комбинаций методов
  
ConcurrentHashMap:
- ✅ Синхронизирована (много локов)
- ✅ Высокий параллелизм
- ✅ Лучший выбор для многопоточных приложений
```
