## `ConcurrentHashMap` vs `Collections.synchronizedMap(HashMap)` — простыми словами

---
### 🎯 Оба — синхронизированные, но по-разному
**Оба** дают потокобезопасность, но **подход** и **производительность** сильно отличаются.

---
### 🔒 Collections.synchronizedMap(HashMap)

**Один замок на всё.**
- Это как **обычный HashMap, который обернули в синхронизированную обёртку**.    
- Когда один поток выполняет `put()` или `get()`, **весь объект блокируется**.    
- Остальные потоки **ждут** — даже если они читают или пишут в разные части карты.   
- Подходит для **однопоточных** сценариев или если **конкуренция низкая**.    

```java
Map<String, String> map = Collections.synchronizedMap(new HashMap<>());
// Все методы synchronized — один поток за раз
```

---
### ⚡ ConcurrentHashMap

**Много замков — много дорог.**
- Это **HashMap, разделённый на 16 отдельных сегментов (*комнат*)**.    
- При записи блокируется **только один сегмент**.    
- Остальные 15 сегментов — свободны для других потоков.    
- Чтение вообще **без блокировок** (*можно читать параллельно*).    
- Подходит для **высоконагруженных многопоточных** приложений.    

```java
ConcurrentHashMap<String, String> map = new ConcurrentHashMap<>();
// Только нужный сегмент блокируется — остальные свободны
```

---
### 📊 Сравнение

|Характеристика|synchronizedMap|ConcurrentHashMap|
|---|---|---|
|**Принцип**|Обёртка над HashMap|Встроенная сегментация|
|**Блокировка**|Весь объект|Один сегмент (1/16)|
|**Чтение**|Блокируется|Без блокировки|
|**Запись**|Блокируется весь объект|Блокируется только сегмент|
|**Параллелизм**|Низкий (1 поток за раз)|Высокий (до 16 потоков)|
|**Null ключи**|✅ Да|❌ Нет|
|**Производительность**|Падает с ростом потоков|Остаётся высокой|
|**Итераторы**|Неустойчивые (fail-fast)|Устойчивые (не бросают ConcurrentModification)|

---
### 🧠 Аналогия

**synchronizedMap** — это **одна касса в банке**. Клиенты выстраиваются в очередь. Один обслуживается — остальные ждут. Даже если кому-то просто нужно узнать баланс (чтение) — он всё равно ждёт.

**ConcurrentHashMap** — это **16 окон в банке**. Клиент идёт в своё окно в зависимости от номера счёта. Все окна работают независимо. Если одно окно занято — остальные продолжают работать. Чтение вообще без очереди.

---
### 📝 Итог
```text
synchronizedMap:
✅ Простота
✅ Подходит для редкой многопоточности
❌ Один лок → низкая производительность при высокой нагрузке

ConcurrentHashMap:
✅ Высокий параллелизм
✅ Оптимален для многопоточных приложений
✅ Безопасное чтение без блокировок
❌ Чуть сложнее по структуре
❌ Не разрешает null ключи
```
**Для высоконагруженных многопоточных приложений → ConcurrentHashMap.**
