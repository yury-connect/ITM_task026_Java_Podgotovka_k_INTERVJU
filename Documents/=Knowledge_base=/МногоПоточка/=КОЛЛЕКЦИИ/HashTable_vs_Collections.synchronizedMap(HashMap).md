## HashTable vs Collections.synchronizedMap(HashMap) — простыми словами

---
### 🎯 Они действительно очень похожи

Оба:
- ✅ **Синхронизированы**    
- ✅ **Блокируют весь объект** при каждом вызове    
- ✅ **Не разрешают null** ключи (для HashTable) / зависят от обёртки    
- ✅ **Медленные** при высокой конкуренции    

---
### 🔍 Единственное реальное различие

| Характеристика    | HashTable                                 | synchronizedMap(HashMap)                          |
| ----------------- | ----------------------------------------- | ------------------------------------------------- |
| **История**       | Наследие (Java 1.0)                       | Современная обёртка (Java 1.2)                    |
| **Итераторы**     | `Enumeration` (старый стиль) + `Iterator` | Только `Iterator`                                 |
| **Использование** | ❌ Устарел, не рекомендуется               | ✅ Можно использовать (но лучше ConcurrentHashMap) |
| **Null ключи**    | ❌ Не разрешает                            | ✅ Зависит от внутренней HashMap (разрешает)       |

---
### 🧠 Производительность — одинаковая

Оба используют **один общий лок** (монитор) для всех методов:

```java
// HashTable
public synchronized V put(K key, V value) { ... }
// synchronizedMap
public V put(K key, V value) {
    synchronized (mutex) {
        return m.put(key, value);
    }
}
```

**Итог:** при многопоточном доступе оба будут работать медленно, так как потоки будут ждать друг друга.

---
### ⚠️ Важный нюанс

`synchronizedMap` **не синхронизирует** итерацию:

```java
Map<String, String> map = Collections.synchronizedMap(new HashMap<>());
// ❌ НЕ синхронизировано!
for (String key : map.keySet()) {
    // может бросить ConcurrentModificationException
}
// ✅ Нужно синхронизировать вручную
synchronized (map) {
    for (String key : map.keySet()) {
        // безопасно
    }
}
```

У `HashTable` этого недостатка нет, но он устарел.

---
### 📊 Сравнение

|Критерий|HashTable|synchronizedMap|
|---|---|---|
|**Блокировка**|Весь объект|Весь объект|
|**Производительность**|🐢 Низкая|🐢 Низкая|
|**Enumeration**|✅ Да|❌ Нет|
|**Null ключи**|❌ Нет|✅ Да (если HashMap)|
|**Устарел**|✅ Да|❌ Нет (но не оптимален)|
|**Iterator синхронизация**|✅ Да (внутренняя)|❌ Нет (нужна ручная)|

---
### 💡 Что использовать сегодня?

|Сценарий|Решение|
|---|---|
|**Однопоточный**|`HashMap`|
|**Многопоточный (высокая нагрузка)**|`ConcurrentHashMap`|
|**Многопоточный (низкая нагрузка)**|`Collections.synchronizedMap()`|
|**HashTable**|❌ **Никогда!**|

---
### 📝 Итог
```text
HashTable и synchronizedMap(HashMap):
- Одинаковые по производительности
- Одинаковые по механизму блокировки
- Отличаются только историей и мелочами
Ни тот, ни другой не оптимальны для многопоточки.
Лучший выбор → ConcurrentHashMap!
```
