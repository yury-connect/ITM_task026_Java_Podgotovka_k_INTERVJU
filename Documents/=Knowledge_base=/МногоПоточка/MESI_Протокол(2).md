# MESI

**MESI** — это **протокол когерентности кэшей** (Cache Coherence Protocol), используемый в многоядерных процессорах. Он гарантирует, что все ядра видят **согласованную картину памяти**, даже если у каждого ядра есть свой локальный кэш (L1/L2).

Название — это аббревиатура из **четырёх состояний**, в которых может находиться кэш-линия (строка кэша) на конкретном ядре.

## 🧠 Четыре состояния
	
**M — Modified (Изменена)**  
Линия есть только в этом кэше, и она **отличается** от основной памяти. Данные «грязные» — их нужно будет записать обратно в память, когда линию вытеснят или запросит другое ядро.
	
**E — Exclusive (Эксклюзивна)**  
Линия есть только в этом кэше, и она **совпадает** с основной памятью. Данные «чистые». Это состояние — «быстрый путь» для записи: если ядро хочет изменить линию, оно может сделать это сразу, переведя её в **M**, без обращения к другим ядрам.
	
**S — Shared (Разделяема)**  
Линия есть в **нескольких** кэшах, и она совпадает с памятью. Читать можно всем. Но если кто-то захочет **записать** — все остальные копии должны быть инвалидированы (переведены в **I**).
	
**I — Invalid (Недействительна)**  
Линия **отсутствует** в этом кэше или **устарела**. Любое обращение к ней — это **промах кэша** (cache miss), данные нужно загружать из памяти или из другого кэша.

## 🔄 Как это работает на практике
	
Представь, что два ядра (Core 0 и Core 1) работают с одной переменной `x`.
	
**1. Core 0 читает `x`**  
Промах кэша. Данные загружаются из памяти. Core 0 переводит линию в **E** (эксклюзивно), потому что больше никто её не читал.
	
**2. Core 1 читает `x`**  
Core 1 запрашивает линию. Протокол видит, что у Core 0 она в **E**. Core 0 «отдаёт» копию (через шину или кэш-когерентную сеть), и **оба ядра** переводят линию в **S** (разделяема).
	
**3. Core 0 пишет в `x`**  
Core 0 хочет изменить `x`. Он отправляет **invalidate**-запрос. Core 1 переводит свою копию в **I**. Core 0 переводит свою линию в **M** (изменена) и меняет данные. Теперь только у Core 0 есть актуальная версия.
	
**4. Core 1 снова читает `x`**  
Промах кэша. Core 1 запрашивает линию. Протокол видит, что у Core 0 она в **M** (грязная). Core 0 **сбрасывает** данные в память (или передаёт напрямую), и оба ядра переводят линию в **S**.

## 🎯 Зачем это нужно
	
**Когерентность кэшей** — это фундамент, на котором строится вся модель памяти Java (JMM). Когда ты пишешь `volatile` или `synchronized`, JVM генерирует инструкции (memory barriers), которые заставляют процессор использовать MESI (или его расширения) для синхронизации кэшей между ядрами.

Без MESI (или аналогичного протокола) ядра видели бы **разные** значения одной и той же переменной, и никакая многопоточность была бы невозможна.

### 🔧 Расширения MESI
	
- **MOESI:** Добавляет состояние **O (Owned)** — линия «грязная», но может быть **разделяемой**. Владелец отвечает за сброс в память, другие ядра могут читать без обращения к памяти.
    
- **MESIF:** Добавляет **F (Forward)** — для эффективной передачи данных между кэшами в многопроцессорных системах (Intel).    

## 🎤 Для собеседования

> _«MESI — это протокол когерентности кэшей, который гарантирует, что все ядра видят согласованную память. Каждая кэш-линия может быть в одном из четырёх состояний: Modified (изменена, грязная), Exclusive (эксклюзивна, чистая), Shared (разделяема), Invalid (недействительна). Когда ядро пишет в линию, оно инвалидирует копии в других кэшах. Этот протокол — основа модели памяти Java: инструкции `volatile` и `synchronized` заставляют процессор использовать MESI для синхронизации.»
