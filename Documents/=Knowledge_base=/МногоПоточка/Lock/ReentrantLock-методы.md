## 🔄 `ReentrantLock` (*Повторно входимая блокировка*)

`ReentrantLock` — это главная и наиболее часто используемая реализация интерфейса `Lock`.

#### ⚙️ Главный принцип — Повторная входимость (*Reentrancy*):

Если поток **уже владеет** этой блокировкой, он может вызвать `lock()` повторно **без ухода в deadlock**!
- Внутри класса стоит счетчик удержаний (Hold Count).    
- Каждая повторная вставка `lock()` увеличивает счетчик на $+1$.    
- Каждая операция `unlock()` уменьшает счетчик на $-1$.    
- Блокировка окончательно освобождается для других потоков только тогда, когда счетчик становится равен **`0`**.    

## ⚖️ **Справедливая** и **Несправедливая** блокировка (Fair vs Non-fair)

При создании `new ReentrantLock(boolean fair)` можно задать режим поведения очереди:

#### ⚡ **Non-Fair** (*Несправедливый*) — *По умолчанию (`new ReentrantLock()`)
- Поток, только что вызвавший `lock()`, может обгнать потоки, давно стоящие в очереди, если блокировка освободилась прямо в этот момент.    
- 🟢 _Плюс:_ Максимальная производительность и throughput (высокая скорость).    
- 🔴 _Минус:_ Риск "голодания" потоков (Thread Starvation).    

#### ⚖️ **Fair** (*Справедливый*) — _`new ReentrantLock(true)`_
- Все потоки встают в строгую очередь (FIFO). Блокировку всегда получает тот, кто ждет дольше всех.    
- 🟢 _Плюс:_ Гарантия от голодания потоков.    
- 🔴 _Минус:_ Ощутимая просадка по производительности из-за частых контекстных переключений процессора.    

## 🧰 Дополнительные методы `ReentrantLock` (Метрики и диагностика)
	
- `getHoldCount()` — сколько раз **текущий** поток зашел в блокировку.    
- `isHeldByCurrentThread()` — принадлежит ли блокировка текущему потоку.    
- `isLocked()` — заблокирован ли ресурс хоть кем-то в данный момент.    
- `hasQueuedThreads()` — стоят ли другие потоки в очереди на захват.    
- `getQueueLength()` — примерное количество потоков, ожидающих блокировку.    

## 💻  Канонический шаблон использования (Best Practice)

Чтобы избежать вечных блокировок и утечек ресурсов, **всегда** соблюдайте следующий паттерн:
```Java
Lock lock = new ReentrantLock();

lock.lock(); // 1. Захватываем ДО блока try
try {
    // 2. Критическая секция (работа с общими данными)
} finally {
    lock.unlock(); // 3. Гарантированно освобождаем В FINALLY!
}
```

### 🎤 Короткая шпаргалка для собеседования
> «Интерфейс **`Lock`** — это гибкая альтернатива `synchronized` с поддержкой неблокирующего захвата (`tryLock`), таймаутов и прерываний. Его реализация **`ReentrantLock`** поддерживает повторный вход одним и тем же потоком за счет счетчика удержаний (Hold Count) и позволяет настраивать режим честной очереди (FIFO). Главное правило при работе с `Lock` — всегда освобождать ресурс вызовом `unlock()` строго внутри блока `finally`.» 🚀
