## 🔒 Виды локов в Java

### 1️⃣ `synchronized` — Встроенный монитор
- **Блокировка на уровне объекта или класса.**
- **Нечестная** — кто первый встал, того и тапки.
- **Нельзя прервать** ожидание.
- **Автоматически** освобождается при выходе из блока.
- _Пример:_ `synchronized(this) { ... }`

### 2️⃣ `ReentrantLock` — Гибкая альтернатива
- **Явная блокировка** (ручной `lock()` и `unlock()`).
- Может быть **честной** или **нечестной** (по конструктору).
- **Позволяет прервать** ожидание (`lockInterruptibly()`).
- **Попытка захвата** с таймаутом (`tryLock(5, SECONDS)`).
- **Счетчик входа** — один поток может войти несколько раз.

### 3️⃣ `ReadWriteLock` / `ReentrantReadWriteLock` — Чтение vs Запись
- **Разделяет** блокировки на **читательскую** и **писательскую**.
- **Много читателей** могут заходить одновременно.
- **Писатель** заходит только когда **нет читателей**.
- **Идеально** для частого чтения и редкой записи.
- _Повышает производительность_ в сценариях read-heavy.

### 4️⃣ `StampedLock` — Оптимистичная версия (Java 8)
- **Улучшенный** `ReadWriteLock` с **оптимистичным чтением**.
- **Оптимистичный лок:** читаем данные, потом проверяем штамп (`validate()`).
- Если штамп невалидный — **повторяем** чтение уже с пессимистичным локом.
- **Быстрее** `ReadWriteLock` при низкой конкуренции.
- _Может привести к_ **проблеме гонок** (retry).

### 5️⃣ `ReentrantLock` (варианты) — `tryLock()`
- **Неблокирующая** попытка захвата.
- Возвращает `true`/`false` сразу.
- Можно **указать таймаут** ожидания.
- **Позволяет избежать** бесконечных ожиданий.
- _Пример:_ `if (lock.tryLock(1, SECONDS)) { ... }`

### 6️⃣ `Semaphore` — Счетчик разрешений
- Ограничивает **количество одновременных потоков**.
- Не привязан к монитору объекта.
- Позволяет **управлять пулом ресурсов** (например, соединений).
- _Аналог:_ швейцар в клубе — впускает только N человек.

### 7️⃣ `CountDownLatch` — Ожидание событий
- **Однократный** барьер.    
- Потоки ждут, пока счетчик **не достигнет нуля**.    
- _Пример:_ ждем, пока все водители сядут в автобус.

### 8️⃣ `CyclicBarrier` — Многократный барьер
- **Переиспользуемый** барьер.
- Все потоки ждут друг друга у барьера.
- **После достижения** барьера — выполняют общее действие.
- _Пример:_ команда собирается у точки старта.

### 9️⃣ `Phaser` — Гибкая версия `CyclicBarrier`
- **Динамическое** количество участников.    
- Можно **добавлять/удалять** стороны во время выполнения.    
- Поддерживает **несколько фаз**.    
- _Пример:_ поэтапный сбор данных.    

### 🔟 `Exchanger` — Обмен данными
- **Точка синхронизации** для двух потоков.
- Обмениваются объектами **в обе стороны**.
- _Пример:_ курьер и получатель меняются посылками.

### 1️⃣1️⃣ `LockSupport` — Базовый парковщик
- **Утилитный класс** для парковки потоков.
- Используется внутри `ReentrantLock`, `Semaphore`.
- Методы: `park()`, `unpark(thread)`.
- **Не требует** объекта блокировки.

## 🧠 Итог (шпаргалка)

| Тип              | Суть                                      |
| ---------------- | ----------------------------------------- |
| `synchronized`   | Встроенный, простой, но негибкий          |
| `ReentrantLock`  | Явный, гибкий, можно прервать             |
| `ReadWriteLock`  | Разделяем читателей и писателей           |
| `StampedLock`    | Оптимистичное чтение для высокой скорости |
| `Semaphore`      | Счетчик разрешений (пул потоков)          |
| `CountDownLatch` | Одноразовый барьер                        |
| `CyclicBarrier`  | Многоразовый барьер                       |
| `Phaser`         | Гибкий барьер с фазами                    |
| `Exchanger`      | Обмен данными между двумя потоками        |

> **Выбирай `ReentrantLock`** — 80% кейсов.  
> **Используй `ReadWriteLock`** — если много читателей.  
> **`StampedLock`** — для микро-оптимизаций.  
> **Остальное** — для редких специфических задач.
