## 🧵 **Асинхронное** vs **Многопоточное** программирование

Это **разные подходы** к решению задачи, хотя они часто пересекаются.

---
### 📊 Сравнительная таблица

| Характеристика         | **Многопоточность (Multithreading)**                                 | **Асинхронность (Asynchronous)**                                                   |
| ---------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **Суть**               | Одновременное выполнение нескольких задач в **параллельных потоках** | Выполнение задачи **без блокировки** основного потока, с уведомлением о завершении |
| **Аппаратная основа**  | Использует **несколько ядер** CPU (реальный параллелизм)             | Может работать **в одном потоке** (конкурентность без параллелизма)                |
| **Блокировка**         | Потоки могут блокироваться (ожидание I/O, `sleep`, `join`)           | **Не блокирует** вызывающий поток (задача "обещает" вернуть результат позже)       |
| **Сложность**          | Высокая (гонки, дедлоки, синхронизация)                              | Средняя (работа с колбэками, `Future`, `CompletableFuture`)                        |
| **Ресурсы**            | Каждый поток — это ресурс ОС (стек, контекст)                        | Легковесная (один поток может обслуживать тысячи задач)                            |
| **Когда использовать** | CPU-интенсивные задачи (расчёты, обработка данных)                   | I/O-интенсивные задачи (сеть, БД, файлы, вызовы API)                               |
| **Пример в Java**      | `new Thread().start()`, `ExecutorService`                            | `CompletableFuture.runAsync()`, `WebClient`, `@Async`                              |

---
### 🔍 Детальный разбор

#### 🧵 **Многопоточность** (*Parallelism*)

> **"Я беру несколько рабочих и даю каждому свою задачу."**	
- Задачи выполняются **физически параллельно** на разных ядрах CPU.    
- Каждый поток — это отдельный "исполнитель" со своим стеком.    
- Подходит для **вычислений**, где нужно задействовать все ядра процессора.    
- **Проблемы:** синхронизация доступа к общим данным, дедлоки, накладные расходы на создание потоков.

**Пример:**
```java
ExecutorService executor = Executors.newFixedThreadPool(4);
for (int i = 0; i < 100; i++) {
    executor.submit(() -> heavyCalculation());
}
```

---
#### 🔄 **Асинхронность** (*Concurrency without Parallelism*)

> **"Я даю задание и говорю: 'Когда закончишь — позвони'. А сам иду делать другие дела."**	
- Выполнение задачи **не блокирует** основной поток.    
- Часто используется для **I/O-операций** (запросы к БД, HTTP-вызовы, чтение файлов), где процессор простаивает в ожидании ответа.    
- Может работать **в одном потоке** (например, Event Loop в Node.js) — тогда это **конкурентность**, но не параллелизм.    
- В Java: `CompletableFuture`, реактивные стримы (Project Reactor), `@Async`.

**Пример:**
```java
CompletableFuture.supplyAsync(() -> fetchFromDB())
    .thenApply(data -> process(data))
    .thenAccept(result -> System.out.println(result));
```

---
### 🧠 Главное отличие — одной фразой

> **Многопоточность — это про "одновременно".**  
> **Асинхронность — это про "не блокируй меня".**

---
### 🔄 Они могут работать вместе
```java
// Асинхронная задача, которая выполняется в отдельном потоке
CompletableFuture<Void> future = CompletableFuture.runAsync(() -> {
    // Этот код выполняется в потоке из ForkJoinPool.commonPool()
    heavyCalculation();
});

// Основной поток не блокируется
System.out.println("Я свободен!");
future.join(); // Ждём результата (если нужно)
```

---
### 🎤 Короткий ответ на собеседовании

> _«Многопоточность — это способ достижения параллелизма через использование нескольких потоков ОС, эффективен для CPU-интенсивных задач. Асинхронность — это способ не блокировать вызывающий поток во время выполнения долгих операций, эффективен для I/O-задач. Они часто используются вместе: асинхронные задачи выполняются в пуле потоков.»_

### 📊 Таблица выбора

|Сценарий|Решение|
|---|---|
|**Сортировка массива из 10 млн элементов**|✅ Многопоточность (`ForkJoinPool`)|
|**HTTP-запрос к 100 внешним API**|✅ Асинхронность (`CompletableFuture`, WebClient)|
|**Параллельный парсинг больших файлов**|✅ Многопоточность|
|**Обработка входящих запросов в веб-сервере**|✅ Асинхронность (не блокировать потоки, ждущие I/O)|
|**И то, и другое**|✅ Асинхронный вызов + пул потоков для тяжёлых операций|
