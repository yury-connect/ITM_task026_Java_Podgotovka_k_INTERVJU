# LongAdder

Представь: у тебя есть **один счетчик**, который бешено инкрементируют 100 потоков одновременно (например, счетчик посещений страницы).
	
- **Через `AtomicLong`**: 100 потоков бьются лбами за одну ячейку памяти. CAS-операции постоянно фейлятся, потоки крутятся в цикле (`spin`), ЦП греется как утюг.
    
- **Через `LongAdder`**: Потоки перестают драться. Каждый получает свой личный уголок для записи.

---
## 🧠 Как он устроен изнутри (1 схема)

Представь **доску объявлений** в офисе:

|Концепция|Что это в `LongAdder`|
|---|---|
|**База** (`base`)|Общая доска. Если потоков мало — пишут сюда через CAS (быстро).|
|**Массив ячеек** (`Cell[]`)|Отдельные личные доски для каждого потока. Каждая ячейка — это `volatile long`.|
|**Хеш потока** (`probe`)|Номер стола, за который садится поток. Вычисляется случайно через ThreadLocalRandom.|

#### **Алгоритм одной фразой:**
> Поток пытается плюнуть в общую `base`. Если не получилось (CAS провалился, значит много конкурентов), он берет случайную ячейку из массива и плюет туда. Другие потоки плюют в другие ячейки. **Драки нет!**

---
## 📊 Сравнение (`AtomicLong` vs `LongAdder`)

|Характеристика|`AtomicLong`|`LongAdder`|
|---|---|---|
|**При низкой нагрузке**|✅ Очень быстрый (один CAS)|🟡 Чуть медленнее (лишняя логика с массивом)|
|**При высокой нагрузке (100+ потоков)**|❌ **Ад!** Постоянные спин-лупы, просадка в 10-20 раз|✅ **Космическая скорость** — каждый пишет в свою ячейку|
|**Память**|16 байт (одна переменная)|16 байт + массив ячеек (если есть конкуренция)|
|**Точность `get()`**|Абсолютно точная всегда|Неточная! `sum()` пробегает по ячейкам и суммирует на лету — во время суммирования ячейки могут меняться|

## 💻 Как использовать в коде (Элементарно)
```java
import java.util.concurrent.atomic.LongAdder;

public class HitCounter {
    private final LongAdder counter = new LongAdder();
    
    // Метод, который дергают 1000 потоков одновременно
    public void hit() {
        counter.increment(); // 🔥 НЕТ БЛОКИРОВОК, НЕТ SPIN-ЦИКЛОВ!
    }
    
    // Периодический отчет (например, раз в секунду)
    public long getTotalHits() {
        return counter.sum(); // Пробегает по всем ячейкам и складывает
    }
}
```

---
## ⚡️ **Подводные камни** (*На собеседовании скажи это!*)

1. **`sum()` не атомарен!** Пока ты суммируешь 100 ячеек, другие потоки продолжают инкрементить. Это ок для статистики, но **не ок** для финансовых транзакций.
    
2. **Если потоков мало** — `LongAdder` чуть медленнее `AtomicLong`, потому что он сначала пытается писать в `base`, потом проверяет массив. Не используй его для 2-3 потоков.
    
3. **Массив ячеек создается ЛЕНИВО**. Если конкуренции нет, массив `null` — используется только `base`. Экономия памяти.
    
4. **Перехеширование**: Если 2 потока случайно попали в одну ячейку и начали драться, они меняют свой `probe` (хеш) и переходят в другую ячейку.

---
## 🎯 **Когда использовать** (*Правило большого пальца*)

| Сценарий                                          | Инструмент                               |
| ------------------------------------------------- | ---------------------------------------- |
| Счетчик в цикле с 1-2 потоками                    | `AtomicLong`                             |
| Счетчик в веб-приложении под нагрузкой (100+ RPS) | **`LongAdder`**                          |
| Нужно атомарно сделать `get()` и `set()`          | `AtomicLong` (у `LongAdder` нет `set()`) |
| Нужно делать `compareAndSet()`                    | `AtomicLong`                             |
| Счетчик запросов, статистика, хиты, лайки         | **`LongAdder`** (идеальный выбор)        |

## 🔥 Связка с предыдущей темой (False Sharing)

Внутри `LongAdder` класс `Cell` **уже содержит падинг** (через аннотацию `@Contended` в новых версиях JDK)!
```java
@Contended
static final class Cell {
    volatile long value;
    // JVM сама разнесет ячейки по разным кэш-линиям
}
```
То есть создатели Java **уже решили** проблему False Sharing внутри самого `LongAdder`. Поэтому он летает как ракета.

## 🧠 Фраза-убийца для собеседования:

> _"**`LongAdder`** — это торжество техники **sharding** (шардирования) над монолитным CAS. Вместо того чтобы 100 потоков бились в одну дверь, мы создаем 100 дверей, и каждый входит в свою. Ценой этой скорости является неточность при вызове `sum()` — но для счетчиков статистики это допустимо. Поэтому в своем коде для подсчета запросов, времени ответов или лайков я всегда использую `LongAdder`, а для бинарных флагов или точных транзакций — `AtomicLong`."_
