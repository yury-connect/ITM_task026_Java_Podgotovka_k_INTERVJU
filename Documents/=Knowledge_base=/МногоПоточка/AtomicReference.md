## `AtomicReference` — кратко

**AtomicReference** — это потокобезопасная **обёртка** над ссылкой на объект.   
Позволяет атомарно читать и изменять ссылку без использования `synchronized`.

### Зачем нужна
Обычная ссылка `Object ref` небезопасна в многопоточке: один поток может прочитать старое значение, другой — записать новое, и результат будет непредсказуемым. `AtomicReference` решает это через CAS (Compare-And-Swap).

### Основные методы
- `get()` — атомарно читает текущую ссылку    
- `set(newValue)` — атомарно устанавливает новое значение    
- `compareAndSet(expected, newValue)` — атомарно меняет значение, только если текущее равно ожидаемому    
- `getAndSet(newValue)` — атомарно возвр. старое значение и устанавл. новое    
- `updateAndGet(function)` — атомарно обновляет значение через функцию    

### Пример
```java
AtomicReference<String> ref = new AtomicReference<>("old");
ref.compareAndSet("old", "new");  // true — заменит
ref.compareAndSet("old", "another"); // false — не заменит, т.к. уже "new"
```

### Где используется
- Замена `volatile`-ссылок, когда нужна атомарная замена
- Реализация lock-free структур данных    
- Хранение состояния в многопоточных алгоритмах без блокировок    
- Внутри `AtomicStampedReference` и `AtomicMarkableReference` (для реш. пробл. ABA)    

### Главное
`AtomicReference` — это не про объект внутри, а про **ссылку на него**. Сам объект может быть изменяемым, но замена ссылки происходит атомарно.
