# Fetch-And-Add (*FAA*)
[статья1](https://proselyte.net/cas-faa-java/) [видео про **CAS**](https://youtu.be/oxmMm6QK98s?si=bj4joZixxJZOneqB)

---
> [!IMPORTANT]
> КРАТКО
### СУТЬ (*для конспекта*)

**Fetch-And-Add (FAA)** — атомарная операция, которая:
1. **Читает** текущее значение переменной
2. **Прибавляет** к нему заданное число
3. **Записывает** новое значение
4. Возвращает **старое** значение

**Ключевое:** всё это происходит **одной неделимой** инструкцией на уровне процессора.

---
> [!TIP]
> ПОДРОБНЕЕ
### ДЕТАЛИ
**Где используется:**
- Счетчики (`AtomicLong.incrementAndGet()` внутри исп-т FAA на нек-х платформах)
- Очереди (генерация индексов)
- Распределенные системы (генерация ID)

**В Java:**
```java
// Аналог FAA через AtomicLong
AtomicLong counter = new AtomicLong(0);
long oldValue = counter.getAndIncrement(); // возвращает 0, становится 1
// Это и есть Fetch-And-Add
```

**Реализация в процессорах:**
- x86: инструкция `XADD`
- Реализуется без блокировок (lock-free)

**Проблемы:**
- Только для **сложения/вычитания** (не для произвольных операций)
- При переполнении — поведение зависит от архитектуры

---
### СРАВНЕНИЕ: **FAA** vs **CAS**

| Характеристика         | **Fetch-And-Add**                       | **Compare-And-Swap**                                                  |
| ---------------------- | --------------------------------------- | --------------------------------------------------------------------- |
| **Суть**               | Просто <br>прибавить число              | Изменить, только если <br>значение НЕ изменилось <br>с момента чтения |
| **Возвращает**         | Старое значение                         | Булевый флаг (*успех/неуспех*) <br>или старое значение                |
| **Где применяется**    | Счетчики, <br>генераторы номеров        | Сложные структуры данных <br>(стэки, очереди, map'ы)                  |
| **Главный минус**      | Только арифметика                       | Нужен цикл при неудаче <br>(retry-loop)                               |
| **В Java**             | `AtomicLong`<br>   `.getAndIncrement()` | `AtomicReference`<br>   `.compareAndSet()`                            |
| **Производительность** | Быстрее <br>(*одна инструкция*)         | Медленнее <br>(*цикл + сравнение*)                                    |

| FAA                                             | CAS                                          |
| ----------------------------------------------- | -------------------------------------------- |
| Всегда изменяет значение                        | Меняет, только если текущее равно ожидаемому |
| Не может провалиться <br>(*кроме переполнения*) | Может провалиться → нужен retry-цикл         |
| Используется для счётчиков                      | Используется для сложных обновлений          |

---
**Пример для наглядности:**
```java
// FAA (просто +1)
atomicLong.getAndIncrement(); // всегда увеличит

// CAS (с проверкой)
atomicInteger.compareAndSet(expected, newValue); // увеличит, только если никто не изменил
```

```java
AtomicInteger counter = new AtomicInteger(0);
// Аналог FAA:
int old = counter.getAndIncrement(); // old = 0, теперь counter = 1
int current = counter.incrementAndGet(); // теперь counter = 2, current = 2
```

---
**Итог (*запомнить*):**

> **FAA** — для простых счетчиков (*быстро, без циклов*).  
> **CAS** — для сложных операций (*гибко, но с retry*).  
> В современных JVM `AtomicLong.incrementAndGet()` — это CAS в цикле, но на некоторых архитектурах JIT-компилятор заменяет это на аппаратный FAA.

---
**Для конспекта (*одной строкой*):**

> **FAA** — аппаратная атомарная операция "*`прочитал`-`прибавил`-`записал`-`вернул`*". 
> В Java — это `AtomicInteger.getAndIncrement()`. Работает быстрее *локов*, не вызывает *deadlock*. Относится к многопоточности и *lock-free* алгоритмам.

---
**Если спросят на собесе:**  
Скажите, что это примитив для атомарных счётчиков, реализованный через процессорные инструкции, и в *Java* его обёртка — `AtomicInteger`. Главное — не путать с CAS (*это другая операция*).

---
---
---
**CAS — это фундамент** (низкоуровневый примитив), а **FAA — это частный случай**, который может быть реализован **через CAS** (в цикле) или **через аппаратную инструкцию** процессора.

**Простыми словами:**
- **CAS** — универсальный инструмент ("проверь и поменяй").
- **FAA** — специализированный инструмент ("прочитай и прибавь").
- FAA **можно эмулировать** через CAS, но на некоторых процессорах есть отдельная, более быстрая инструкция для FAA.

---
### ДЕТАЛИ

#### 1. FAA через CAS (эмуляция)
Если проц не поддерживает FAA аппаратно — JVM эмулирует его через CAS в цикле:
```java
// Реализация getAndIncrement() через CAS (упрощённо)
public int getAndIncrement() {
    int oldValue;
    int newValue;
    do {
        oldValue = current;               // прочитали
        newValue = oldValue + 1;          // вычислили
    } while (!compareAndSet(oldValue, newValue)); // CAS — пробуем записать
    return oldValue;
}
```
**Что здесь происходит:**
1. Читаем текущее значение.    
2. Вычисляем новое (старое + 1).    
3. Пробуем атомарно записать через **CAS**.    
4. Если CAS не удался (кто-то изменил значение) — повторяем цикл.    

---
#### 2. Аппаратный FAA (без CAS)
На x86 есть инструкция **`XADD`**, которая делает FAA **атомарно и без циклов**:
```assembly
LOCK XADD [address], eax   ; атомарно прибавить eax к ячейке памяти
```
В этом случае JIT-компилятор может заменить цикл с CAS на одну инструкцию.

---
#### 3. Сравнение производительности

|Аспект|FAA через CAS|Аппаратный FAA|
|---|---|---|
|**Количество инструкций**|Много (цикл + CAS)|Одна (`XADD`)|
|**Конфликты (contention)**|Высокие (при частых изменениях циклы долгие)|Низкие (одна инструкция)|
|**Поддержка**|Все процессоры|Только x86 (и некоторые ARM)|

---
#### 4. В Java (как это выглядит)

- **`AtomicInteger.getAndIncrement()`** — внутри использует CAS-цикл (на всех платформах).
- **`AtomicLong.getAndAdd()`** — аналогично.
- **JIT-компилятор** может оптимизировать CAS-цикл в аппаратный FAA, если распознает паттерн (на x86).

**Пример (один и тот же код):**
```java
AtomicLong counter = new AtomicLong(0);
counter.getAndIncrement(); // всегда атомарно, но реализация зависит от платформы
```

### КЛЮЧЕВЫЕ ВЫВОДЫ (для собеса)

1. **CAS — базовый примитив**, FAA — **надстройка** над ним или аппаратная оптимизация.
    
2. В Java **`AtomicInteger`** — это CAS, а не FAA (хотя JIT может заменить).
    
3. **FAA быстрее CAS** при высокой конкуренции, потому что не требует retry-циклов.
    
4. На практике разница заметна только при **очень высокой нагрузке** (миллионы операций/сек).
    
5. В **`LongAdder`** используется другая стратегия (шардинг счетчиков), чтобы избежать даже CAS-конфликтов.

---
### ИТОГ (одной фразой)

> **FAA — это оптимизированная версия CAS для операции сложения.**  
> Там, где CAS делает цикл с повторными попытками, FAA (на поддерживаемом железе) делает всё за одну атомарную инструкцию.
