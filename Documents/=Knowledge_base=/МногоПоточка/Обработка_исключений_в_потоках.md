## 🧵 Обработка исключений в потоках (*кратко*)

### 🔥 Главное правило

> **Исключение, выброшенное в потоке, НЕ передается в родительский поток (main) и НЕ ловится try-catch снаружи!**

---
## 📦 Два способа обработки

### 1️⃣ **Внутри** самого потока (*локально*)
```java
Thread t = new Thread(() -> {
    try {
        // опасный код
    } catch (Exception e) {
        // обработали внутри
    }
});
```

### 2️⃣ **Глобальный** обработчик (*UncaughtExceptionHandler*)
```java
Thread t = new Thread(() -> {
    throw new RuntimeException("Ошибка в потоке");
});
t.setUncaughtExceptionHandler((thread, throwable) -> {
    System.out.println("Поймали: " + throwable.getMessage());
});
t.start();
```

---
## ⚙️ Глобальный хендлер для ВСЕХ потоков
```java
Thread.setDefaultUncaughtExceptionHandler((thread, throwable) -> {
    System.out.println("Любая ошибка в любом потоке: " + throwable);
});
```

---
## 🔍 Приоритет обработки

| Уровень                                               | Описание                             |
| ----------------------------------------------------- | ------------------------------------ |
| 1️⃣ **Локальный try-catch**                           | Самая высокая важность               |
| 2️⃣ **`thread.setUncaughtExceptionHandler()`**        | Для конкретного потока               |
| 3️⃣ **`Thread.setDefaultUncaughtExceptionHandler()`** | Для всех потоков                     |
| 4️⃣ **Группа потоков (`ThreadGroup`)**                | Fallback, если ничего выше не задано |

---
## ⚠️ Особенности

- **`InterruptedException`** — **не подавляй!** Всегда восстанавливай флаг:
```java
catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // 🔥
}
```
    
- **Исключение в потоке** → **поток умирает** (*если не обработано*).
    
- **Пул потоков (`ExecutorService`)** — исключение перехватывается через **`Future.get()`**:
```java
Future<?> future = executor.submit(() -> { throw new RuntimeException(); });
future.get(); // throws ExecutionException
```

> **Подвох** с `ExecutorService`: `execute()` vs `submit()`
>
>Важно помнить разницу:>
> - **`executor.submit(...)`**: исключение «проглатывается» и оборачивается в `ExecutionException`, которое вылетит **только** при вызове `future.get()`. Если `future.get()` не вызвать, ошибка просто «потеряется» в тишине.
>    
>- **`executor.execute(...)`**: если передать задачу через `execute()` (которая возвращает `void`), исключение вылетит напрямую и попадет в **`UncaughtExceptionHandler`** потока из пула (если он задан в `ThreadFactory`).

---
## 🎤 Короткий ответ на собеседовании

> _«Исключения в потоках не передаются наружу. Их можно обработать **внутри** самого потока (try-catch), либо назначить **`UncaughtExceptionHandler`**. Для пулов потоков используем `Future.get()`, чтобы получить исключение. `InterruptedException` нужно обрабатывать корректно — восстанавливать флаг прерывания через `Thread.currentThread().interrupt()`.»_
