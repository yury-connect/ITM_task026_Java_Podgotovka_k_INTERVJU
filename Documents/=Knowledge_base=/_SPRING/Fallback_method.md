## Fallback в Spring Cloud

**Fallback (запасной метод)** — это "план Б" для вашего сервиса. Когда основной метод падает с ошибкой, система автоматически переключается на запасной вариант, чтобы пользователь получил ответ вместо ошибки.

---
### 🔧 Как работает?

Аннотация `@CircuitBreaker` с параметром `fallbackMethod` связывает основной метод с запасным:
```java
@CircuitBreaker(fallbackMethod = "getDefaultUser")
public User getUser(Long id) {
    // основной метод - запрос к внешнему сервису
}

public User getDefaultUser(Long id, Throwable t) {
    // запасной метод - возврат заглушки
    return new User(id, "Unknown", "Not available");
}
```

**Правила для fallback-метода:**
- ✅ **Те же параметры**, что у основного метода    
- ✅ **Плюс опционально** `Throwable` (для анализа ошибки)    
- ✅ **Тот же тип возврата**, что у основного метода    

### 📋 Что можно вернуть в **fallback**?

| Вариант                 | Пример использования                 |
| ----------------------- | ------------------------------------ |
| **Кешированные данные** | <u>Последний успешный</u> ответ      |
| **Заглушка (stub)**     | <u>Дефолтный</u> объект с прочерками |
| **Дефолтное значение**  | <u>Пустой список</u> вместо `null`   |
| **Упрощенный ответ**    | "*Сервис временно недоступен*"       |

### 🤔 Когда использовать **fallback**, а когда нет?

|Ситуация|Стратегия|Почему?|
|---|---|---|
|**Сервис недоступен**|✅ Fallback|Вернуть кеш или заглушку|
|**Таймаут**|✅ Fallback|Вернуть дефолтное значение|
|**Ошибка валидации**|❌ Исключение|Повтор не исправит данные|
|**BusinessException**|❌ Специфичная логика|Нужна бизнес-обработка|

### 🏗️ Связь с **Circuit Breaker**

Это **тандем**, который работает в паре:
```text
Circuit Breaker:  "Стоит ли вызывать сервис?"
        ↓
Fallback:          "Что делать, если вызов невозможен или упал?"
```
**Результат:** Система остается **отзывчивой** даже при сбоях зависимых сервисов.

---
### 💡 Главное запомнить
1. **Fallback** — это не *костыль*, а *архитектурное решение* для **graceful degradation**    
2. **Отключайте ретраи** для ошибок валидации и бизнес-ошибок    
3. **Анализируйте `Throwable`** в fallback, чтобы выбирать правильную стратегию    
4. **Всегда возвращайте** тот же тип, что и основной метод
