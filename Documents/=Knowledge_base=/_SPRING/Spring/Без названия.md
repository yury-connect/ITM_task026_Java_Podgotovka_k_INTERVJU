Жизненный цикл Spring-бина делится на 5 ключевых фаз: от сканирования классов до полного уничтожения объекта при закрытии контекста.

### 🏛️ ФАЗА 1: Регистрация метаданных (Bean Definition Phase)

На этом этапе физических Java-объектов в памяти ещё нет. Spring работает только с метаданными.

1. **Component Scanning (Сканирование):** Spring сканирует classpath приложения в поисках классов, помеченных `@Component`, `@Service`, `@Repository`, `@Controller`, или классов `@Configuration` с методами `@Bean`.
    
2. **Bean Definition Registration (Создание BeanDefinition):** Для каждого найденного бина создается объект-паспорт — **`BeanDefinition`**. В нем записываются класс, scope (`singleton`/`prototype`), ленивая инициализация (`lazy`), методы инициализации и список зависимостей. Все `BeanDefinition` регистрируются в **`BeanDefinitionRegistry`**.
    
3. **`BeanFactoryPostProcessor` (Обработка метаданных):** Выполняются модификаторы метаданных (например, `PropertySourcesPlaceholderConfigurer`). На этом шаге можно изменить параметры `BeanDefinition` — в частности, подставить реальные значения из `.properties` / `.yml` файлов в выражения `${...}`.
    

### 🏗️ ФАЗА 2: Инстанцирование и Внедрение (Instantiation & DI)

4. **Instantiation (Создание экземпляра):** Spring выбирает нужный конструктор и рефлексивно создает «сырой» Java-объект в Heap.
    
5. **Populate Properties (Внедрение зависимостей):** Spring внедряет необходимые зависимости и свойства в поля и сеттеры (`@Autowired`, `@Value`, `@Resource`).
    

### ⚙️ ФАЗА 3: Инициализация (Initialization Phase)

6. **Aware Interfaces (Инъекция служебных объектов):** Если бин реализует маркерные Aware-интерфейсы, Spring передает ему ссылки на свои внутренние компоненты:
    
    - `BeanNameAware` $\rightarrow$ внедряет имя бина в контексте.
        
    - `BeanFactoryAware` / `ApplicationContextAware` $\rightarrow$ внедряет сам контейнер Spring.
        
7. **`BeanPostProcessor.postProcessBeforeInitialization()`:** Выполняется первичная постобработка. На этом шаге вызываются методы, помеченные аннотацией **`@PostConstruct`**.
    
8. **InitializingBean (`afterPropertiesSet()`):** Если бин реализует интерфейс `InitializingBean`, Spring вызывает его метод `afterPropertiesSet()`.
    
9. **Custom `initMethod`:** Вызывается кастомный метод инициализации, если он был явно указан в Java-конфиге: `@Bean(initMethod = "customInit")`.
    
10. **`BeanPostProcessor.postProcessAfterInitialization()` (Создание AOP-прокси):**
    
    - ⚠️ **Критически важный шаг:** Именно здесь Spring проверяет, нужны ли бину AOP-аспекты (`@Transactional`, `@Async`, `@Cacheable`, `@Validated`).
        
    - Если аннотации есть, Spring оборачивает оригинальный объект в **CGLIB или JDK Dynamic Proxy** и возвращает в контекст уже объект-прокси!
        

### 🟢 ФАЗА 4: Готовность к работе (Ready Phase)

11. **Singleton Cache:** Полностью готовый и проинициализированный бин помещается в кэш синглтонов (`DefaultSingletonBeanRegistry`). Контекст считается поднятым, бин готов обрабатывать запросы приложения.
    

### 🧹 ФАЗА 5: Уничтожение (Destruction Phase)

Этап запускается при явном закрытии контекста (`context.close()`) или при остановке JVM.

12. **Shutdown Trigger:** Контейнер инициирует процедуру остановки.
    
13. **`@PreDestroy`:** Вызываются методы, помеченные аннотацией `@PreDestroy`.
    
14. **`DisposableBean.destroy()`:** Вызывается метод `destroy()`, если бин реализует интерфейс `DisposableBean`.
    
15. **Custom `destroyMethod`:** Вызывается кастомный метод очистки, объявленный в `@Bean(destroyMethod = "cleanup")`.
    

> ⚠️ **Исключение для `prototype`-бинов:**
> 
> Для бинов со скоупом `prototype` Spring выполняет только Фазы 1–3 (создает, внедряет зависимости и инициализирует), после чего отдаёт объект клиенту и полностью забывает про него. **Фазу 5 (уничтожение) для Prototype-бинов контейнер не выполняет!** Освобождение их ресурсов лежит на разработчике.
