# 📄 Что такое **страница** (*page*) в PostgreSQL

**Страница** — это **минимальная единица хранения данных на диске** в PostgreSQL. Всё, что PostgreSQL читает или записывает, происходит **страницами**, а не отдельными строками.

### 📏 Размер
Стандартный размер страницы в PostgreSQL — **8 КБ (8192 байта)**. Это фиксированная величина, заданная при компиляции СУБД (можно изменить через `--with-blocksize`, но на практике этого не делают).

> **🧠 Аналогия**
> Представь **книгу**:
> - Страница книги — это **page** в PostgreSQL.    
> - Строки текста на странице — это **строки таблицы (tuples)**.    
> - Ты не можешь прочитать пол страницы — ты читаешь **всю страницу целиком**.
> 
> - Так же и PostgreSQL: даже если тебе нужна одна строка, с диска будет прочитана **вся страница** (8 КБ), в которой она лежит.

---
### 📦 Что внутри страницы

Страница состоит из нескольких частей:

**Header (*заголовок*)** — 24 байта. Содержит метаданные: LSN (*log sequence number*), контрольную сумму, указатели на свободное пространство.

**Item pointers (*указатели на строки*)** — массив указателей, которые говорят, где именно на странице лежит каждая строка. Именно на эти указатели ссылаются **индексы** (*TID — tuple identifier = номер страницы + номер указателя*).

**Free space (*свободное место*)** — пустое пространство для новых строк или новых версий существующих строк.

**Tuples (*строки*)** — сами данные, которые растут с конца страницы к началу.

**Special space** — используется некоторыми типами индексов (например, GiST, GIN).

> *PostgreSQL* хранит таблицы и индексы **в отдельных файлах** на диске. Один файл = одна таблица или один индекс (или его сегмент).
> **Внутри этого файла** данные разбиты на **страницы по 8 КБ**. То есть:
> > **Файл таблицы** = последовательность **страниц по 8 КБ**.
> Например, таблица размером 80 КБ — это **один файл**, внутри которого **10 страниц** по 8 КБ.

---
### 🔗 Как связаны страница, строка и индекс

**Индекс** хранит **TID (*tuple identifier*)** — это пара `(номер_страницы, номер_указателя)`.
	
Когда *PostgreSQL* ищет строку по индексу:
1. Находит в индексе *TID*: например, `(страница 42, указатель 3)`.
2. Загружает **всю страницу 42** с диска в память (8 КБ).
3. По указателю 3 находит нужную строку.
	
**Важно:** даже если нужна одна строка, читается **вся страница**.

---
### 📌 Почему это важно
	
**Кэш (*shared_buffers*).** PostgreSQL держит страницы в памяти (*shared_buffers*). Если нужная страница уже в кэше — чтение мгновенное. Если нет — идёт диск (*медленно*).
	
**Bloat.** Если строки обновляются, старые версии остаются на странице. Страница «*раздувается*» мёртвыми строками, и `VACUUM` нужен, чтобы освободить место.
	
**TOAST.** Если строка не помещается на страницу (8 КБ), [TOAST](Documents/=Knowledge_base=/DataBases/=DB-relational=/=PostgreSQL=/TOAST) выносит данные во вспомогательную таблицу.
	
**HOT.** Если новая версия строки помещается **на ту же страницу**, и индексируемые колонки не менялись — [HOT](Documents/=Knowledge_base=/DataBases/=DB-relational=/=PostgreSQL=/HOT)-обновление без изменения индексов.
	
**fillfactor.** Можно указать, какой процент страницы заполнять (по умолчанию 100%). Если оставить 70–80%, на странице будет место для HOT-обновлений.

### 🎤 Для собеседования
> _«Страница в PostgreSQL — это минимальная единица хранения и чтения данных на диске, размером 8 КБ. Внутри неё лежат строки таблицы, указатели на них и свободное место. Индексы ссылаются на строки через TID — номер страницы и номер указателя. Даже для чтения одной строки PostgreSQL загружает всю страницу целиком. Понимание страниц важно для тем MVCC, HOT, TOAST, fillfactor и bloat.»_

>📄 Страница PostgreSQL — это **не файл** и **не единица файловой системы**. 
Это **внутренняя логическая единица** самого PostgreSQL.

**Страница PostgreSQL** — это **блок фиксированного размера (8 КБ)**, которым оперирует **сам PostgreSQL** внутри своих файлов данных. Это его внутренняя абстракция.

**Файловая система (NTFS, ext4, XFS)** — это **внешний слой** между PostgreSQL и диском. ФС тоже оперирует блоками, но **своего** размера (обычно 4 КБ в NTFS).

---
### 🔗 Как это соотносится
	
**PostgreSQL хранит данные в файлах.** Каждая таблица, индекс, TOAST-таблица — это **отдельный файл** (*или несколько файлов, если размер превышает 1 ГБ*).
	
**Внутри файла данные разбиты на страницы по 8 КБ.** То есть файл — это просто последовательность страниц.
	
**Файловая система видит этот файл как набор своих блоков.** Например, одна страница PostgreSQL (8 КБ) в NTFS с кластером 4 КБ занимает **2 блока NTFS**.

### 📊 Иерархия (*от нижнего уровня к верхнему*)
	
**Диск** → **Файловая система (NTFS)** → **Файл таблицы (`/base/.../16384`)** → **Страница PostgreSQL (8 КБ)** → **Строка (tuple)**.
	
То есть:
- **Файл** — это единица файловой системы.    
- **Страница** — это единица PostgreSQL.    
- Это **разные уровни абстракции**.

### ⚠️ Почему важно не путать
**PostgreSQL читает данные страницами, а не файлами целиком.** Он обращается к файлу через системные вызовы (`pread`, `pwrite`), указывая смещение и размер **в страницах**.
	
**Кэш (shared_buffers) хранит страницы, а не файлы.** Это позволяет эффективно работать с большими таблицами, не загружая их в память полностью.
	
**TOAST, HOT, fillfactor, bloat** — все эти механизмы оперируют **страницами**, а не файлами.

### 🎤 Для собеседования
> _«Страница PostgreSQL — это внутренняя единица хранения данных размером 8 КБ, которой оперирует сам PostgreSQL внутри своих файлов. Это не файл и не единица файловой системы. Файловая система (NTFS или ext4) видит файлы PostgreSQL как набор своих блоков, но PostgreSQL работает с ними через страницы. Одна страница PostgreSQL может занимать несколько блоков файловой системы — это зависит от размера кластера ФС.»_
