# 4️⃣ 🗺️ Bitmap Scan <br>(*Bitmap Index Scan + Bitmap Heap Scan*)
Умный компромиссный механизм Postgres, который превращает медленный Random I/O в быстрый Sequential I/O!

- ⚙️ **Принцип работы:** Проходит в два этапа:
	    
    1. **Bitmap Index Scan:** Postgres ищет ключи в индексе, но НЕ идет сразу в таблицу. Вместо этого он строит в памяти битовую карту (Bitmap), помечая единичками те дисковые страницы таблицы, где лежат нужные строки.
        
    2. **Bitmap Heap Scan:** Postgres сортирует битовую карту по физическому порядку страниц на диске и **последовательно (Sequential I/O)** вычитывает только нужные блоки из таблицы!
    
- 🎯 **Для чего он:** Для выборок средних объемов строк ($1-15\%$ таблицы) или при объединении условий с несколькими независимыми индексами (`WHERE status = 'NEW' AND category_id = 5`).
    
- ⚡ **Сложность:** `O(log N)` на поиск по индексам + `O(B)` на последовательное чтение отсортированных страниц $B$.
    
- 🟢 **Плюсы:** Полностью устраняет главный минус `Index Scan` — хаотичный Random I/O; умеет на лету объединять несколько разных индексов по операциям `BitmapAnd` и `BitmapOr`!
    
- 🔴 **Минусы:** Требует накладных расходов памяти (RAM) на построение битовой карты (`work_mem`). При нехватке памяти битовая карта превращается из точной (exact) в «загрубленную» (lossy), из-за чего приходится допроверять лишние строки.
    
- 📌 **Когда происходит:** Часто при выборке диапазона данных (`WHERE age BETWEEN 20 AND 30`) или объединении фильтров по двум разным одиночным индексам.
