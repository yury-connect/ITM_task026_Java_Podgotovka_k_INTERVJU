# 5️⃣ TID Scan / TID Range Scan 🎯

Сканирование напрямую по внутреннему системному физическому адресу строки (`Tuple ID` / `ctid`).

- ⚙️ **Принцип работы:** Postgres мгновенно обращается к конкретной физической странице диска и номеру строки на ней, переданному в запросе (`WHERE ctid = '(0,1)'`).
    
- 🎯 **Для чего он:** Внутренние системные операции СУБД, удаление физических дубликатов, специфические пагинаторы.
    
- ⚡ **Сложность:** `O(1)` — физический адрес известен заранее!
    
- 🟢 **Плюсы:** Самый быстрый способ получить конкретный кортеж в Postgres (быстрее, чем `Index Scan` по `id`).
    
- 🔴 **Минусы:** Значение `ctid` нестабильно и может меняться после любого `UPDATE` или `VACUUM`.
    
- 📌 **Когда происходит:** Редко в пользовательском коде; активно во внутренних утилитах и системных скриптах.

---
### 🎤 Короткая шпаргалка для собеседования

> «В PostgreSQL существует 5 основных способов считывания данных:
> 
> 1. **Seq Scan** — читает всю таблицу подряд за $O(N)$ (для мелких таблиц или больших выборок).
>     
> 2. **Index Scan** — ищет по индексу за $O(\log N)$ и вычитывает Heap (идеален для $1-2\%$ точечных строк).
>     
> 3. **Index Only Scan** — берет данные строго из индекса без обращения к Heap (самый быстрый).
>     
> 4. **Bitmap Scan** — сначала строит битовую карту страниц по индексу, а затем последовательно читает Heap, устраняя просадки из-за Random I/O и умея объединять несколько индексов через `AND/OR`.
>     
> 5. **TID Scan** — мгновенный доступ за $O(1)$ прямо по физическому адресу `ctid`.» 🚀
