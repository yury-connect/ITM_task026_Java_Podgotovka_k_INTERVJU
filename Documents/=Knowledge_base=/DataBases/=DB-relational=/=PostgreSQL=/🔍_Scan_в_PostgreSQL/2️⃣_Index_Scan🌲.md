# 2️⃣ Index Scan 🌲

Классическое точечное сканирование с использованием B-Tree (или другого) индекса.

- ⚙️ **Принцип работы:**    
    1. Postgres находит нужные записи в дереве индекса `O(log N)`.        
    2. В листьях индекса берет физические адреса строк на диске (`TID/ctid`).        
    3. Идет в основную таблицу (Heap) по этим адресам и забирает остальные поля строки.
    
- 🎯 **Для чего он:** Для точечного выбора небольшого количества строк (до $1-5\%$ от общего объема).
    
- ⚡ **Сложность:** Поиск в индексе: `O(log N)`. Вычитка строк из Heap: `O(K)` (где $K$ — количество найденных строк).
    
- 🟢 **Плюсы:** Молниеносный точечный поиск отдельной строки или небольшого диапазона.
    
- 🔴 **Минусы:** Вызывает **Random I/O (произвольное хаотичное чтение)** с диска при переходе от индекса к Heap. Если запрашиваемых строк много, Random I/O станет медленнее, чем обычный `Seq Scan`!
    
- 📌 **Когда происходит:** Поиск по уникальному ключу, точечные выборки с высокой селективностью (`WHERE id = 42` или `WHERE email = '...'`).
    
- 🛑 **Когда избегать:** Если нужно вычитать 50% всей таблицы — Postgres сам проигнорирует Index Scan и выберет `Seq Scan`.
