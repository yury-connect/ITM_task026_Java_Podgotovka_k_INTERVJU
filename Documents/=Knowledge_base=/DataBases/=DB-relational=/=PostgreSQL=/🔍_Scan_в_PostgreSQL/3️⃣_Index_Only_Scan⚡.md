# 3️⃣ Index Only Scan ⚡

Самый быстрый и эффективный вид сканирования!

- ⚙️ **Принцип работы:** Postgres находит данные внутри индекса и **вообще НЕ обращается к основной таблице на диске (Heap)**! Для проверки актуальности строк использует карту видимости страниц (Visibility Map).
    
- 🎯 **Для чего он:** Когда запрашиваемый `SELECT` содержит **только те поля, которые уже лежат внутри самого индекса** (включая секцию `INCLUDE`).
    
- ⚡ **Сложность:** `O(log N + K)` без накладных расходов на чтение Heap!
    
- 🟢 **Плюсы:** Абсолютный лидер по скорости; минимальное использование RAM и дискового I/O; нет Random I/O к Heap.
    
- 🔴 **Минусы:** Если страница таблицы не помечана как «чистая» в Visibility Map (например, недавно были `UPDATE`), Postgres всё равно придется дочитывать строку из Heap.
    
- 📌 **Когда происходит:** Запросы закрываются покрывающими индексами (`Covering Index`) или выбором `SELECT COUNT(*)` при наличии индекса.
    
- 🛑 **Когда избегать:** Нельзя принудительно заставить его работать, если в `SELECT` просят поля, которых нет в индексе.
