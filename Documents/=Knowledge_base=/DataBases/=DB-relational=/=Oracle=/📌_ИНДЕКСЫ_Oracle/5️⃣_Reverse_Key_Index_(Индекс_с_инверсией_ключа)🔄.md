# 5️⃣ Reverse Key Index (*Индекс с инверсией ключа*) 🔄

Специализированная разновидность B-Tree индекса, меняющая байты значения ключа на противоположные перед сохранением.

- ⚙️ **Принцип работы:** Значение `1001` превращается в `1001`, а `1002` — в `2001`.
    
- 🎯 **Для чего он:** Для устранения проблемы «горячих блоков» (Buffer Busy Waits) при вставках монотонно возрастающих sequence-ключей (1, 2, 3, 4, 5...) в многопоточных системах.
    
- ⚡ **Сложность:** Поиск по равенству: $O(\log N)$.
    
- 🟢 **Плюсы:** Равномерно распределяет вставляемые записи по разным листовым блокам B-Tree дерева, снимая contention (конкуренцию) по CPU/диску.
    
- 🔴 **Минусы:** **Категорически НЕ умеет делать диапазонное сканирование!** Запросы вида `WHERE id BETWEEN 10 AND 20` приведут к `Full Table Scan`.
    
- 📌 **Когда брать:** Высоконагруженный OLTP на запись с последовательными суррогатными ключами (Sequence / Identity).
    
- 🛑 **Когда НЕ брать:** Если по этому полю часто выполняются диапазонные запросы (`>`, `<`, `BETWEEN`).
