В **Oracle Database** также существует обширная классификация типов индексов. Если в Postgres акцент сделан на типы структур данных (`B-Tree`, `GIN`, `GiST`, `BRIN` и т.д.), то Oracle предлагает широкий набор встроенных архитектурных разновидностей, оптимизированных под OLTP, OLAP (DWH) и спецификации корпоративного уровня.

Ниже представлен разбор основных встроенных типов индексов в Oracle, отранжированный по частоте использования в реальных проектах! 🚀

# 1️⃣ B-Tree Index (Стандартный сбалансированный индекс) 🌲

Дефолтный тип индекса в Oracle Database, используемый по умолчанию для большинства таблиц.

- ⚙️ **Принцип работы:** Классическое сбалансированное дерево поиска. Листовые блоки содержат ключевые значения и физические адреса строк **`ROWID`** (указывающие на файл, блок и номер строки в блоке).
    
- 🎯 **Для чего он:** Для выборок по полям с высокой селективностью (много уникальных значений: `id`, `email`, `code`) и условий `=`, `<`, `>`, `BETWEEN`.
    
- ⚡ **Сложность:** Поиск: $O(\log N)$. Вставка/Удаление: $O(\log N)$.
    
- 🟢 **Плюсы:** Универсален; мгновенный доступ к строкам; гарантирует сбалансированность дерева.
    
- 🔴 **Минусы:** Плохо работает на полях с низкой селективностью; раздувается при частых удалениях (требует `COALESCE` / `REBUILD`).
    
- 📌 **Когда брать:** В 80-90% случаев для любых высокоселективных колонок в OLTP-системах.
    
- 🛑 **Когда НЕ брать:** Для статусных полей (где всего 2-3 уникальных значения).
