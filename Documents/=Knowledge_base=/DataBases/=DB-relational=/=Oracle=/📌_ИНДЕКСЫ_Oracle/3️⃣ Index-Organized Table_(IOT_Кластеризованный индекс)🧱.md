# 3️⃣ Index-Organized Table (IOT / Кластеризованный индекс) 🧱

Аналог `Clustered Index` из MySQL/SQL Server или таблиц с первичным ключом в других СУБД.

- ⚙️ **Принцип работы:** Сама таблица физически превращается в B-Tree индекс. Все оставшиеся колонки строки хранятся прямо в листовых узлах первичного ключа.
    
- 🎯 **Для чего он:** Для таблиц, поиск по которым почти всегда идет строго по Primary Key (`WHERE id = :id`).
    
- ⚡ **Сложность:** Поиск: $O(\log N)$, доступ к данным: $O(0)$ дополнительных переходов к дисковому блоку (без `ROWID`).
    
- 🟢 **Плюсы:** Экономит дисковый I/O (нет необходимости делать дополнительный скан самой таблицы после чтения индекса); экономит память.
    
- 🔴 **Минусы:** Вторичные индексы на IOT-таблицах работают медленнее (используют «логический» ROWID).
    
- 📌 **Когда брать:** Связующие таблицы `Many-To-Many`, справочники, таблицы поиска «ключ-значение».
    
- 🛑 **Когда НЕ брать:** Таблицы с большим числом вторичных индексов или постоянными случайными вставками.
