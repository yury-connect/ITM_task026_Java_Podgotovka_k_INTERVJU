# ⑨ Обратный индекс / Инвертированный (Inverted Index) 🔄

Индекс, где ключом является **отдельное слово или элемент**, а значением — список документов/строк, где этот элемент встречается (основа для GIN в Postgres или Elasticsearch).

- ⚙️ **Принцип работы:** Раскладывает сложные данные на составляющие: текст разбивает на слова, JSON/массив — на отдельные элементы.
    
- 🎯 **Для чего он:** Полнотекстовый поиск (Full-Text Search) и поиск элементов внутри `JSONB` или массивов (`WHERE tags @> ARRAY['java']`).
    
- ⚡ **Сложность:** Поиск: `O(1)` или `O(log N)` на слово, но сборка результатов зависит от количества совпадений.
    
- 🟢 **Плюсы:** Позволяет мгновенно искать слова внутри гигантских текстов или элементов в JSON.
    
- 🔴 **Минусы:** **Очень тяжелый** при записи/обновлении; занимает много места на диске.
    
- 📌 **Когда брать:** Полнотекстовый поиск по статьям, поиск по тегам или динамическим JSON-документам.
    
- 🛑 **Когда НЕ брать:** Для простых полей с простыми значениями (числа, даты, статус).

---
### 🎤 Короткая шпаргалка для собеседования

> «Помимо логических паттернов (`Composite`, `Partial`, `Covering`, `Expression`), ключевыми являются:  
> - **Кластеризованный** (*сортирует и хранит сами строки на диске, в таблице может быть только один*), 
> - **Некластеризованный** (*хранит ссылки на строки*), 
> - **Уникальный** (*блокирует дубликаты на уровне БД*), 
> - **Префиксный** (*индексирует первые N символов длинных строк*) и 
> - **Инвертированный/GIN** (*для поиска внутри JSON, массивов и полнотекстового поиска*).» 🚀
