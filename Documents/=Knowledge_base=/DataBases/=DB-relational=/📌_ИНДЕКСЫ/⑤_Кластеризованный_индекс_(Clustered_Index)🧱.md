# ⑤ Кластеризованный индекс (*Clustered Index*) 🧱

Фундаментальный индекс, который определяет **физический порядок хранения самих строк таблицы** на диске (в MySQL InnoDB это всегда Первичный Ключ / `PRIMARY KEY`).

- ⚙️ **Принцип работы:** Таблица становится «индексной таблицей» (*Index-Organized Table*). Листовые узлы B-Tree дерева содержат не просто ссылки, а **все реальные данные строки**.
    
- 🎯 **Для чего он:** Для мгновенного чтения записей по `PRIMARY KEY` и эффективного чтения диапазонов (`WHERE id BETWEEN 100 AND 200`).
    
- ⚡ **Сложность:** Поиск: `O(log N)`. Доступ к данным: `O(0)` (*не нужно идти в Heap, данные уже в самом узле*).
    
- 🟢 **Плюсы:** Самый быстрый выбор данных; строки с соседними ключами физически лежат рядом на диске.
    
- 🔴 **Минусы:** На таблицу может быть создан **строго ОДИН** кластеризованный индекс (так как отсортировать физический диск можно только одним способом); вставки с немонотонными ключами (например, UUID) разрывают страницы диска (Page Split).
    
- 📌 **Когда брать:** Всегда создается автоматически при определении `PRIMARY KEY`.
    
- 🛑 **Когда НЕ брать:** При выборе ключа кластеризации избегайте случайных значений (UUID v4) — используйте автоинкремент (`BIGINT` / `UUID v7`).
