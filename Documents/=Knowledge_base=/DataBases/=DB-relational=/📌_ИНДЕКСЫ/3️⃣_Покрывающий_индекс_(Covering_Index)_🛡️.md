# 3️⃣ Покрывающий индекс (Covering Index) 🛡️

Индекс, содержащий ВСЕ поля, запрашиваемые в `SELECT` и `WHERE`: `CREATE INDEX ON users (department_id) INCLUDE (name, salary)`.

- ⚙️ **Принцип работы:** Ключевые колонки выстраивают B-Tree дерево, а дополнительная секция `INCLUDE` просто складывает значения в **листовые узлы** дерева.
    
- 🎯 **Для чего он:** Чтобы СУБД прочитала данные прямо из индекса в памяти и вообще не обращалась к самой таблице на диске (Heap). Вызывает **`Index Only Scan`**.
    
- ⚡ **Сложность:** Поиск: `O(log N)`. Доступ к данным: `O(0)` дополнительного обращения к Heap.
    
- 🟢 **Плюсы:** Самый быстрый тип чтения; колонки из `INCLUDE` не раздувают глубину дерева и не удорожают поиск.
    
- 🔴 **Минусы:** Дополнительные поля в `INCLUDE` раздувают размер листовых страниц и расходуют память RAM/диск.
    
- 📌 **Когда брать:** На Highload-ручках, где `SELECT` выбирает пару конкретных полей и требуется выжать максимум скорости.
    
- 🛑 **Когда НЕ брать:** Если в `SELECT` запрашиваются десятки полей или `SELECT *`.
