# ⑥ Некластеризованный / Вторичный индекс (Non-Clustered / Secondary Index) 🔗

Любой обычный индекс, создаваемый поверх таблицы.

- ⚙️ **Принцип работы:** Хранится в виде отдельной структуры данных. В листовых узлах содержит **значение индексируемого поля + указатель на строку** (в Postgres — адрес `TID/ctid`, в MySQL InnoDB — значение `PRIMARY KEY`).
    
- 🎯 **Для чего он:** Для ускорения поиска по непервичным полям (`WHERE email = '...'`).
    
- ⚡ **Сложность:** Поиск по индексу: `O(log N)`. Дополнительный переход к строке таблицы (Heap Lookup): `O(1)`.
    
- 🟢 **Плюсы:** На одну таблицу можно повесить десятки таких индексов для разных полей.
    
- 🔴 **Минусы:** Требует дополнительного шага (двойной переход) для вычитки остальных колонок таблицы; замедляет `INSERT`/`DELETE`.
    
- 📌 **Когда брать:** Почти для всех полей, используемых в `WHERE`, `JOIN` и `ORDER BY`.
    
- 🛑 **Когда НЕ брать:** Не создавать на таблицах, где запись происходят сотни тысяч раз в секунду, а чтение почти отсутствует.
