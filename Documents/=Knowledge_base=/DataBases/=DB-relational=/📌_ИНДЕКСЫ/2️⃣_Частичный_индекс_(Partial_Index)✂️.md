# 2️⃣ Частичный индекс (*Partial Index*) ✂️

Индекс, включающий в себя не все строки таблицы, а только подпадающие под условие `WHERE`: `CREATE INDEX ON orders (created_at) WHERE status = 'PENDING'`.

- ⚙️ **Принцип работы:** При записи строки СУБД сначала проверяет предикат `WHERE`. Если строка под него подпадает — она добавляется в B-Tree, иначе — проигнорируется.
    
- 🎯 **Для чего он:** Для индексации небольшого процента критически важных данных (необработанные заказы, флаги `is_deleted = false`, очереди задач).
    
- ⚡ **Сложность:** Поиск: `O(log N)` (где $N$ — только отфильтрованная часть). Вставка/Обновление: `O(1)` для 95% строк, не подпадающих под `WHERE`!
    
- 🟢 **Плюсы:** Экономит гигабайты на диске и в RAM; вообще не замедляет `INSERT` для неиндексируемых строк.
    
- 🔴 **Минусы:** СУБД проигнорирует индекс, если в `WHERE`-условии SQL-запроса не указан ровно тот же предикат, с которым создавался индекс.
    
- 📌 **Когда брать:** Когда индексировать нужно только редкий статус или категорию (например, 5% горячих данных из всей таблицы).
    
- 🛑 **Когда НЕ брать:** Если в запросах равномерно ищутся данные по всем возможным статусам.
