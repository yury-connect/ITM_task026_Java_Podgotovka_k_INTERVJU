# ⑦ Уникальный индекс (Unique Index) 🔐

Индекс, который одновременно ускоряет поиск и обеспечивает **бизнес-ограничение уникальности** на уровне СУБД.

- ⚙️ **Принцип работы:** Обычное B-Tree дерево, но при вставке СУБД за `O(log N)` проверяет, нет ли уже в дереве такого же значения. Если есть — выбрасывает ошибку (Constraint Violation).
    
- 🎯 **Для чего он:** Гарантированное предотвращение дубликатов (`email`, `passport_number`, `inn`).
    
- ⚡ **Сложность:** Поиск: `O(log N)`. Проверка уникальности при `INSERT`: `O(log N)`.
    
- 🟢 **Плюсы:** Работает на уровне СУБД (100% защита от дублей при параллельных запросах, в отличие от проверок в Java/Python).
    
- 🔴 **Минусы:** Незначительное замедление записи из-за обязательной проверки перед вставкой.
    
- 📌 **Когда брать:** Для всех бизнес-ключей и логических идентификаторов.
    
- 🛑 **Когда НЕ брать:** Если дубликаты бизнес-логикой допускаются.
