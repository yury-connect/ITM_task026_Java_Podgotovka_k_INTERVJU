# 4️⃣ Функциональный индекс / По выражению (Expression Index) 📐

Индекс, построенный не на сырой колонке, а на результате работы функции над ней: `CREATE INDEX ON users (LOWER(email))`.

- ⚙️ **Принцип работы:** СУБД высчитывает результат функции при `INSERT`/`UPDATE` и заносит в B-Tree дерево уже готовое вычисленное значение.
    
- 🎯 **Для чего он:** Для поиска без учета регистра (`LOWER`, `UPPER`), работы с датами (`DATE()`, `EXTRACT()`) или вычислений прямо в условии `WHERE`.
    
- ⚡ **Сложность:** Поиск: `O(log N)`. Вставка/Обновление: `O(log N) + время на выполнение функции`.
    
- 🟢 **Плюсы:** Позволяет оптимизировать запросы, которые раньше приводили к полному сканированию таблицы (`Seq Scan`).
    
- 🔴 **Минусы:** Замедляет запись из-за постоянного вычисления функции процессором (CPU); сработает только при точечном совпадении функции в SQL-запросе.
    
- 📌 **Когда брать:** В коде приложению неизбежно приходится вызывать функции над колонкой в `WHERE`.
    
- 🛑 **Когда НЕ брать:** Если выражение можно переписать на стороне приложения еще до отправки SQL-запроса в БД.

---
### 🎤 Короткая шпаргалка для собеседования

> «Существует 4 основных конструкции индексов: **Составной** (для фильтрации по нескольким полям, критичен порядок по правилу левого префикса), **Частичный** (через `WHERE` индексирует только нужный срез данных, экономя память), **Покрывающий** (через `INCLUDE` позволяет делать `Index Only Scan` без обращения к дисковой таблице) и **Функциональный** (индексирует результат функции, спасая от `Seq Scan` при вызовах вроде `LOWER(email)`).» 🚀
