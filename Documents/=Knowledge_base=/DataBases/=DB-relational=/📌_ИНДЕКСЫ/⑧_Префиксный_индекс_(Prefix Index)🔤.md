# ⑧ Префиксный индекс / На часть строки (Prefix Index) 🔤

Индекс, построенный не по всей длинной строковой колонке, а только по её **первым $N$ символам**: `CREATE INDEX ON articles (title(10))`.

- ⚙️ **Принцип работы:** СУБД берет подстроку (например, первые 10 символов) и строит B-Tree только на основе этого куска.
    
- 🎯 **Для чего он:** Оптимизация памяти при индексировании длинных текста, URL или длинных Hash-строк.
    
- ⚡ **Сложность:** Поиск по префиксу: `O(log N)`.
    
- 🟢 **Плюсы:** В разы уменьшает размер индекса на диске и в RAM.
    
- 🔴 **Минусы:** Может давать больше «ложных срабатываний» (СУБД придется дочитывать строки из таблицы, чтобы проверить полную строку); **не работает для сортировки (`ORDER BY`)**.
    
- 📌 **When брать:** Когда нужно проиндексировать длинное текстовое поле (`VARCHAR(500)` или `TEXT`), но ищется оно чаще по началу.
    
- 🛑 **Когда НЕ брать:** Если по этому полю нужно делать точное полное соответствие или сортировку.
