# 1️⃣ Составной индекс (*Composite Index*) 🧱

Индекс, построенный сразу по нескольким колонкам таблицы: `CREATE INDEX ON users (status, created_at)`.

- ⚙️ **Принцип работы:** Данные в *B-Tree* строятся в отсортированном порядке по первой колонке, внутри нее — по второй и так далее. Выполняет **Правило левого префикса (*Leftmost Prefix Rule*)**: работает для запросов по `(A)`, по `(A, B)`, но **НЕ сработает** для запросов только по `(B)`!
    
- 🎯 **Для чего он:** Для запросов, фильтрующих или сортирующих одновременно по нескольким полям (`WHERE status = 'ACTIVE' AND created_at > '2026-01-01'`).
    
- ⚡ **Сложность:** Поиск: `O(log N)`. Вставка/Обновление: `O(log N)` (*но удорожается пропорционально числу колонок*).
    
- 🟢 **Плюсы:** Ускоряет сложные многокритериальные запросы; один индекс закрывает сразу множество вариаций условий.
    
- 🔴 **Минусы:** Занимает больше места на диске; не сработает, если пропустить первую (*левую*) колонку в `WHERE`.
    
- 📌 **Когда брать:** Постоянно используются запросы с фильтрацией по **2+** колонкам.
    
- 🛑 **Когда НЕ брать:** Если колонки используются в запросах абсолютно <u>независимо</u> друг от друга.
    
- 💡 **Важный нюанс:** Колонки с точным равенством (`=`) и высокой селективностью выносят левее, а диапазоны (`>`, `<`) — в самый конец ключа.
