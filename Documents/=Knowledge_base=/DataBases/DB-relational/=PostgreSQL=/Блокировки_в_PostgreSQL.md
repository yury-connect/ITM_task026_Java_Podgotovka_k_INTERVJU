## 🔒 Блокировки в PostgreSQL — полный обзор

PostgreSQL — это СУБД с **пессимистичной** моделью блокировок. Блокировки делятся на **уровни** и **типы** в зависимости от того, что именно и как блокируется.

---
## 📊 1. Типы блокировок по объектам

| Уровень блокировки    | Что блокируется                     | Описание                                                               |
| --------------------- | ----------------------------------- | ---------------------------------------------------------------------- |
| **Table-level**       | Вся таблица                         | Блокировка всей таблицы (например, при `ALTER TABLE` или `DROP TABLE`) |
| **Row-level**         | Отдельные строки                    | Блокировка конкретных строк (`SELECT FOR UPDATE`, `UPDATE`, `DELETE`)  |
| **Page-level**        | Страница в памяти (buffer)          | Внутренняя блокировка страницы (редко, используется VACUUM)            |
| **Transaction-level** | ID транзакции                       | Блокировка самой транзакции (используется для XID)                     |
| **Advisory**          | Числовой идентификатор (приложение) | **Пользовательские** блокировки, управляемые из кода приложения        |

---
## 📌 2. **Row-level** блокировки (самые частые)
Это блокировки **на уровне строк**, которые ставятся при изменении данных.

| Тип блокировки        | SQL-команда                    | Описание                                                                                                       |
| --------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| **FOR UPDATE**        | `SELECT ... FOR UPDATE`        | Эксклюзивная блокировка. Другие транзакции **не могут** читать (с `FOR UPDATE`) и изменять эту строку.         |
| **FOR NO KEY UPDATE** | `SELECT ... FOR NO KEY UPDATE` | Блокировка **без** запрета на изменения по `FK` (не блокирует `FOR KEY SHARE`)                                 |
| **FOR SHARE**         | `SELECT ... FOR SHARE`         | Разделяемая блокировка. Другие могут читать (`FOR SHARE`), но **не могут** изменять (`FOR UPDATE` / `UPDATE`). |
| **FOR KEY SHARE**     | `SELECT ... FOR KEY SHARE`     | Блокировка **только** для ключей FK (используется для проверки внешних ключей)                                 |

**Пример:**
```sql
-- Транзакция 1
BEGIN;
SELECT * FROM users WHERE id = 1 FOR UPDATE; -- Блокируем строку
-- Транзакция 2 (будет ждать)
UPDATE users SET name = 'New' WHERE id = 1; -- Блокировка!
```

---
## 🛡️ 3. **Table-level** блокировки (*на уровне **таблицы***)
PostgreSQL автоматически ставит их для DDL-операций (`ALTER`, `DROP`, `TRUNCATE`), но их можно ставить и вручную через `LOCK TABLE`.

|Режим|Совместимость с `SELECT`|Совместимость с `INSERT/UPDATE/DELETE`|Кто ставит|
|---|---|---|---|
|**ACCESS SHARE**|✅ Да|✅ Да|`SELECT`|
|**ROW SHARE**|✅ Да|✅ Да|`SELECT FOR UPDATE/SHARE`|
|**ROW EXCLUSIVE**|✅ Да|❌ Нет (только одна)|`INSERT/UPDATE/DELETE`|
|**SHARE UPDATE EXCLUSIVE**|✅ Да|❌ Нет|`VACUUM`, `ANALYZE`, `CREATE INDEX CONCURRENTLY`|
|**SHARE**|✅ Да|❌ Нет|`CREATE INDEX` (неконкурентный)|
|**SHARE ROW EXCLUSIVE**|❌ Нет|❌ Нет|`CREATE TRIGGER`, `ALTER TABLE` (некоторые)|
|**EXCLUSIVE**|❌ Нет|❌ Нет|`REFRESH MATERIALIZED VIEW CONCURRENTLY`|
|**ACCESS EXCLUSIVE**|❌ Нет|❌ Нет|`DROP TABLE`, `ALTER TABLE` (тяжёлые), `TRUNCATE`|

**Самый сильный:** `ACCESS EXCLUSIVE` — блокирует всё, включая чтение.

---
## 🧠 4. Advisory Locks (блокировки по идентификатору)

Это блокировки, которыми управляет **приложение** через числовые ключи. Они не привязаны к таблицам и строкам!
```sql
-- Захватить эксклюзивную блокировку по ключу 42
SELECT pg_advisory_lock(42);
-- Захватить разделяемую блокировку по ключу 42
SELECT pg_advisory_shared_lock(42);
-- Попытаться захватить (не блокируясь)
SELECT pg_try_advisory_lock(42);
```

**Когда использовать:**  
Для распределённых задач, кросс-табличных операций, синхронизации приложения вне транзакций.

---
## 🔄 5. Deadlock (взаимоблокировка)

**Пояснение:** Когда две транзакции ждут друг друга:
```sql
-- Транзакция 1: UPDATE A → ожидает B
-- Транзакция 2: UPDATE B → ожидает A
```

PostgreSQL **детектирует** дедлок и **откатывает одну** из транзакций с ошибкой:
```text
ERROR: deadlock detected
DETAIL: Process 12345 waits for ShareLock on transaction 67890; blocked by process 12346.
```

**Как избежать:**
- Всегда обновляй строки в **одинаковом порядке** (по ID).
- Используй `SELECT FOR UPDATE` с осторожностью.
- Ставь `statement_timeout` или `lock_timeout`.

## 📊 6. Таблица блокировок в PostgreSQL (sys-представления)

|Представление|Что показывает|
|---|---|
|**`pg_locks`**|Активные блокировки (уровень, режим, объект, транзакция, PID)|
|**`pg_stat_activity`**|Активные сессии (включая ожидающие блокировки)|

**Полезный запрос:**
```sql
SELECT
    pid,
    locktype,
    relation::regclass AS table_name,
    mode,
    granted,
    transactionid
FROM pg_locks
WHERE NOT granted;

```

## 🎤 Короткий ответ на собеседовании

> _«В PostgreSQL есть несколько уровней блокировок: табличные (`ACCESS SHARE`, `ROW EXCLUSIVE`, `ACCESS EXCLUSIVE` и др.), строчные (`FOR UPDATE`, `FOR SHARE`, `FOR NO KEY UPDATE`, `FOR KEY SHARE`), а также advisory блокировки (по числовым ключам) для синхронизации в приложении. Самые агрессивные — `FOR UPDATE` и `ACCESS EXCLUSIVE`. Система автоматически детектирует дедлоки и откатывает транзакции. Для наблюдения за блокировками есть представление `pg_locks`.»_

## 🧠 Шпаргалка для запоминания

|Если нужно|Блокировка|
|---|---|
|**Читать строку и потом обновить**|`SELECT FOR UPDATE`|
|**Просто прочитать и защитить от изменений**|`SELECT FOR SHARE`|
|**Заблокировать всю таблицу для ALTER**|`LOCK TABLE ... ACCESS EXCLUSIVE`|
|**Заблокировать операцию в коде (вне таблиц)**|`pg_advisory_lock(key)`|
|**Посмотреть, кто кого блокирует**|`pg_locks` + `pg_stat_activity`|
