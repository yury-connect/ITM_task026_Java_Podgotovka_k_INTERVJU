# Вопросы и ответы на собеседовании по Redis ⚡

---
### 🟢 Основы и базовые концепции

#### ❓ Что такое Redis и для чего он используется?

**Redis (Remote Dictionary Server)** — это NoSQL СУБД с открытым исходным кодом, работающая в оперативной памяти (In-Memory Data Store).

- 🛠️ **Роли в архитектуре:** Кэш, брокер сообщений, основная БД / Key-Value хранилище.
    
- ⚡ **Главный плюс:** Чрезвычайно высокая скорость чтения и записи (доли миллисекунд) благодаря работе в RAM.
    

#### ❓ Чем Redis отличается от традиционных РСУБД (PostgreSQL, MySQL)?

- **Хранение данных:** Redis держит всё в оперативной памяти (с опциональным сбросом на диск), а РСУБД хранят данные на диске.
    
- **Структура:** Redis — это Key-Value хранилище (с поддержкой сложных структур), а РСУБД — табличная модель с жесткой схемой (Schema) и SQL.
    
- **Сложность операций:** Redis оптимизирован для точечного доступа по ключам за **O(1)**, а РСУБД — для сложных JOIN-запросов и построения аналитики.
    

#### ❓ В чём разница между Redis и Memcached?

- 📦 **Типы данных:** Memcached поддерживает только простые строки/бинарники (`String`). Redis поддерживает множество структур: Hashes, Lists, Sets, Sorted Sets, Streams, Bitmaps, HyperLogLog.
    
- 💾 **Персистентность:** Memcached полностью теряет данные при перезапуске. Redis имеет механизмы сохранения на диск (RDB, AOF).
    
- ⚙️ **Возможности:** В Redis из коробки есть Pub/Sub, репликация, транзакции, Lua-скрипты, кластеризация и TTL.
    

### 📦 Структуры данных и команды

#### ❓ Какие типы данных поддерживает Redis и где они применяются?

- 🔤 **String:** Сессии пользователей, токены, обычный кэш строк и чисел (`INCR`/`DECR` для счетчиков).
    
- 🗂️ **Hash:** Объектные структуры (например, профиль пользователя `user:1000` с полями `name`, `age`).
    
- 📋 **List:** Очереди и стеки (списки строк, упорядоченные по порядку добавления).
    
- 🎯 **Set:** Неупорядоченные уникальные значения (теги, уникальные IP, подписки).
    
- 🏆 **Sorted Set (ZSET):** Уникальные элементы, отсортированные по числу `score` (идеально для рейтинговых таблиц / Leaderboards).
    
- 🌊 **Stream:** Лог событий с поддержкой групп потребителей (аналог Kafka).
    
- 🗺️ **Geospatial:** Координаты (широта/долгота) и поиск «ближайших объектов».
    
- 📊 **HyperLogLog:** Вероятностная структура для приблизительного подсчета уникальных элементов (с экономией 99% RAM).
    

#### ❓ Как работают команды `SET` и `GET`?

- `SET key value` — записывает значение по указанному ключу (перезаписывает, если ключ существовал).
    
- `GET key` — возвращает значение по ключу (или `nil`, если ключа нет).
    

#### ❓ Что такое TTL и как управлять временем жизни ключей?

**TTL (Time To Live)** — время, по истечении которого ключ автоматически удаляется из памяти.

- `EXPIRE key seconds` — задает время жизни ключа в секундах.
    
- `SETEX key seconds value` — атомарно устанавливает значение и TTL.
    
- `TTL key` — возвращает оставшееся время жизни ключа (-1 — бессрочно, -2 — ключ не существует).
    

### ⚙️ Архитектура, Потоки и Выполнение

#### ❓ За счет чего Redis однопоточный и как он обрабатывает параллельные запросы?

Основной движок выполнения команд в Redis **однопоточный (Single-Threaded)**.

- ⚡ **Мультиплексирование I/O:** Использует событийно-ориентированный цикл (Event Loop) и системные вызовы (`epoll`/`kqueue`), что позволяет одному потоку обслуживать десятки тысяч одновременных сетевых соединений.
    
- 🛡️ **Без блокировок:** Однопоточность исключает Race Conditions, необходимость в Mutex/Locks и контекстные переключения процессора.
    
- 🛠️ **Замечание:** В современных версиях Redis (6.0+) для сетевого I/O (чтение/запись сокетов) могут привлекаться вспомогательные потоки, но сам стек команд исполняется строго в 1 поток.
    

#### ❓ Поддерживает ли Redis транзакции?

Да, через блок команд:

1. `MULTI` — начало транзакции (команды встают в очередь).
    
2. `EXEC` — последовательное и атомарное выполнение всех команд очереди.
    
3. `DISCARD` — отмена транзакции.
    
4. `WATCH` — оптимистичная блокировка (если отслеживаемый ключ изменился другой сессией, `EXEC` отменит транзакцию).
    

⚠️ **Важный нюанс:** В Redis **НЕТ отката (Rollback)** при ошибке внутри транзакции! Если одна из команд упадет, остальные все равно выполняятся.

#### ❓ Что такое Pipelining (Конвейеризация)?

Принцип отправки клиентом пакета из нескольких команд **без ожидания ответа на каждую из них**.

- **Плюс:** Сокращает сетевую задержку (Round Trip Time — RTT) в десятки раз при массовой отправке команд.
    

### 💾 Персистентность (Сохранение данных)

#### ❓ Как Redis обеспечивает сохранение данных на диск?

Использует два независимых механизма:

1. 📸 **RDB (Redis Database / Snapshots):**
    
    - Создает точечный снимок всей БД в файл (`dump.rdb`) через заданные интервалы времени (через `fork()` процесса).
        
    - _Плюсы:_ Быстрый запуск сервера, компактный файл.
        
    - _Минусы:_ Потеря данных, накопившихся между снимками при аварийном падении.
        
2. 📜 **AOF (Append Only File):**
    
    - Логирует каждую операцию записи (`SET`, `HDEL` и т.д.) в конец файла-журнала.
        
    - _Плюсы:_ Минимальная потеря данных (настраиваемый `fsync`: каждый сек или при каждой записи).
        
    - _Минусы:_ Файл быстро разрастается (требуется регулярная процедура `AOF Rewrite`).
        

💡 **Best Practice:** Использовать комбинацию **RDB + AOF** одновременно.

### 🔄 Масштабирование и Отказоустойчивость

#### ❓ В чем разница между Репликацией, Sentinel и Cluster?

- 👥 **Репликация (Master-Replica):**
    
    - Один Master (запись) копирует данные на несколько Replicas (чтение).
        
    - Позволяет масштабировать чтение, но при падении Master переключение происходит вручную.
        
- 🛡️ **Redis Sentinel:**
    
    - Система мониторинга и автоматического аварийного переключения (Failover).
        
    - Следит за Master-нодой. Если она упала — Sentinel автоматически выбирает из реплик новый Master и перенаправляет клиентский трафик.
        
- 🧱 **Redis Cluster:**
    
    - Полноценное горизонтальное шардирование + отказоустойчивость.
        
    - Все данные автоматически распределяются по **16384 хэш-слотам (Hash Slots)** между несколькими Master-узлами.
        

#### ❓ Что такое Вытеснение данных (Eviction Policies)?

Когда оперативная память упирается в лимит `maxmemory`, Redis начинает удалять ключи по выбранной стратегии:

- `noeviction` — возвращает ошибку на операции записи.
    
- `allkeys-lru` — удаляет наименее давно использованные ключи (**LRU**).
    
- `volatile-lru` — удаляет наименее давно использованные ключи **только среди тех, у которых задан TTL**.
    
- `allkeys-lfu` — удаляет наименее часто использованные ключи (**LFU**).
    
- `allkeys-random` — случайное удаление ключей.
    

### 🔒 Распределенные блокировки и Кэширование

#### ❓ Что такое Распределенная блокировка и как работает алгоритм Redlock?

Нужна для предотвращения конкурентного доступа разных сервисов к одному ресурсу.

- Простая блокировка: `SET resource_key my_random_token NX PX 30000` (флаг `NX` — вставить только если не существует).
    
- 🏰 **Redlock:** Алгоритм от авторов Redis для распределенных кластеров. Клиент запрашивает блокировку у 5 независимых Master-узлов. Блокировка считается успешной, если её выдало **большинство** узлов (минимум 3 из 5) за определенный таймаут.
    

#### ❓ Что такое Cache Stampede (Лавина за кэшем) и как её предотвратить?

Ситуация, когда популярный ключ в кэше одновременно истекает, и тысячи параллельных запросов пробивают кэш и идут нагружать основную БД.

- 🛠️ **Решения:**
    
    1. Распределенные блокировки (только первый поток идет в БД, остальные ждут).
        
    2. Случайный TTL (Probabilistic Early Expiration).
        
    3. Прогрев кэша (Cache Warming) фоновым процессом до его истечения.
