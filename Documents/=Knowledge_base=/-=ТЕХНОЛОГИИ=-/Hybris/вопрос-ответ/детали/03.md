### Что такое Headless-архитектура простыми словами

В веб-разработке интернет-магазин традиционно делится на две части:

- **Backend (Тело):** База данных, логика скидок, корзина, управление заказами, интеграция с WMS/ERP.
    
- **Frontend (Голова):** Кнопки, баннеры, шрифты, верстка — всё, что видит пользователь в браузере.
    

В **традиционном монолитном Hybris** «голова» пришита к «телу». Бэкенд-разработчик на Java сам формировал готовые HTML-страницы (через JSP-шаблоны) и отдавал их в браузер.

В **Headless-архитектуре** «голову» (фронтенд) полностью отрезают от «тела» (бэкенда Hybris).

**Аналогия с рестораном:**

- **Монолит:** Повар (Hybris) сам принимает заказ, сам готовит, сам раскладывает по тарелкам и сам несёт на стол клиенту. Если повар захочет поменять форму тарелки, ему нужно менять весь процесс на кухне.
    
- **Headless:** Повар (Hybris) только готовит еду и отдает её на выдачу в стандартных контейнерах. А официант (отдельный фронтенд на React/Angular) сам берет эти контейнеры, сам красиво раскладывает еду по тарелкам любой формы и приносит клиенту. Повар даже не знает, на какой посуде подадут его блюдо.
    

**Зачем это нужно:**

1. **Свобода фронтендеров:** Они могут менять дизайн сайта, делать его сверхбыстрым, не прикасаясь к тяжелому Java-коду Hybris.
    
2. **Мультиканальность:** Один и тот же бэкенд Hybris может одновременно отдавать данные на сайт, в мобильное приложение, на умные часы или в кассовый терминал.
    

### Подробный разбор терминов из ответа №3

Вот детальная расшифровка того, как технически происходит рендеринг страницы в Headless-архитектуре.

#### 1. Spartacus / Composable Storefront (на Angular / React / Vue)
- **Что это:** Это готовый фреймворк для создания "головы" (витрины магазина).
    
- **Разбор:** SAP написал официальный открытый шаблон фронтенда на Angular под названием **Spartacus** (сейчас переименован в _SAP Commerce Composable Storefront_). Он уже из коробки умеет запрашивать данные у Hybris. Однако компания может отказаться от Spartacus и написать свой фронтенд на React или Vue.js.    

#### 2. REST-запрос через OCC API на эндпоинт `/cms/pages`
- **OCC API (Omni Commerce Connect):** Это стандартный набор REST-эндпоинтов (ссылок), встроенный в Hybris.
    
- **Как это работает:** Когда пользователь заходит на `[myshop.com/](https://myshop.com/)`, фронтенд (Angular/React) отправляет фоновый HTTP-запрос на бэкенд Hybris: `GET [https://api.myshop.com/occ/v2/electronics/cms/pages?pageLabelOrId=homepage](https://api.myshop.com/occ/v2/electronics/cms/pages?pageLabelOrId=homepage)` Фронтенд как бы спрашивает: _«Эй, Hybris, дай мне структуру и наполнение для Главной страницы!»_    

#### 3. JSON со структурой страницы: слоты (Slots) и компоненты (CMS Components)
Hybris в ответ не присылает готовые картинки и красивую верстку. Он присылает **JSON** (*простой структурированный текст с данными*).

Struktur JSON-ответа выглядит так:
- **Слоты (Slots):** Это размеченные в админке зоны на странице. Например: `Section1` (верх), `Section2A` (середина), `Footer` (низ).
    
- **Компоненты (CMS Components):** Это содержимое, которое менеджер вставил в эти слоты.    

**Пример того, что возвращает Hybris в JSON:**
```JSON
{
  "slots": [
    {
      "position": "TopHeaderSlot",
      "components": [
        {
          "typeCode": "SimpleBannerComponent",
          "mediaUrl": "/images/promo_banner.jpg",
          "linkUrl": "/sale"
        }
      ]
    },
    {
      "position": "MiddleSlot",
      "components": [
        {
          "typeCode": "ProductCarouselComponent",
          "title": "Хиты продаж",
          "productCodes": ["prod_100", "prod_200", "prod_300"]
        }
      ]
    }
  ]
}
```

#### 4. Динамическая сборка UI и SSR (Server-Side Rendering) на базе Node.js
Получив этот JSON, фронтенд переходит к отрисовке:

1. **Динамическая сборка UI:** Фронтенд видит в JSON блок `"SimpleBannerComponent"` — и рисует баннер. Видит `"ProductCarouselComponent"` — и рисует красивый слайдер с товарами.
    
2. **Зачем нужен SSR (Server-Side Rendering):**
	    
    - Обычно приложения на Angular/React (SPA) работают прямо в браузере пользователя. Браузер сначала скачивает пустой файл `index.html`, потом загружает скрипты, потом делает запрос к Hybris за JSON и только потом рисует страницу. Это занимает 2–3 секунды белого экрана. К тому же поисковые роботы (Google, Yandex) не могут нормально проиндексировать такой пустой HTML.
        
    - **Решение (SSR):** Между браузером пользователя и Hybris ставят легкий промежуточный сервер **Node.js**. Когда пользователь открывает сайт, Node.js быстро делает запрос к Hybris, получает JSON, сам на своей стороне собирает из него готовый HTML-код с текстом и картинками и **мгновенно выдает пользователю и поисковикам уже готовый HTML**. Сайт открывается моментально, а SEO работает идеально.
