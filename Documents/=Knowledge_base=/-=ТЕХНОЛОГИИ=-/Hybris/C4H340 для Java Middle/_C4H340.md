## Раздел 1. Hybris с нуля

SAP Commerce Cloud (Hybris) — это enterprise-платформа электронной коммерции, написанная на Java и построенная вокруг фреймворка Spring Framework. Для Java Middle разработчика это готовый набор модулей (каталоги, корзина, заказы, клиенты, скидки), расширяемый с помощью Java-кода, конфигурационных XML-файлов и Spring-бинов.

### Архитектура системы

Архитектура Hybris состоит из четко разделенных слоев, где платформа управляет жизненным циклом данных, сервисов и веб-интерфейсов.

|**Слой**|**Назначение**|**Технологический стек**|
|---|---|---|
|**Storefront (Presentation)**|Отображение данных пользователю. Бывает монолитным или Headless.|OCC REST API, Angular (Spartacus), React или JSP (Legacy)|
|**Commerce / Service Layer**|Бизнес-логика, транзакции, правила валидации и конвертация данных.|Spring Framework (DI/IoC, Transactions), Interceptors, Populators|
|**Platform Core**|Ядро системы: ORM-движок, кэширование, управление сессиями, безопасности и кластеризации.|Hybris Persistence Engine, FlexibleSearch Engine, Spring Core|
|**Database & Storage**|Физическое хранение моделей данных и медиа-файлов.|Oracle, PostgreSQL, SAP HANA, Azure Blob / AWS S3|

### Platform (Платформа)

**Platform** — это фундамент Hybris, расположенный в директории `hybris/bin/platform`. Она предоставляет инфраструктуру для запуска приложения:

- Встроенный сервер приложений (Apache Tomcat).
    
- Контекст Spring, объединяющий все подключенные модули.
    
- Движок ORM для работы с БД (Persistence Layer).
    
- Системную веб-консоль администрирования **HAC** (Hybris Admin Console).
    
- Набор Ant-скриптов для сборки и управления проектом.
    

### Extensions (Расширения)

Вся функциональность Hybris разделена на **Extensions (расширения)**. Расширение — это изолированный модуль, который может содержать бизнес-логику, модели данных, веб-сервисы или статичный контент.

**Типовая структура расширения:**

- `extensioninfo.xml` — манифест расширения, где указываются его имя, веб-контекст и зависимости от других расширений.
    
- `resources/<extname>-items.xml` — объявление структуры сущностей БД, типов данных и связей.
    
- `resources/<extname>-spring.xml` — конфигурация Spring-бинов модуля.
    
- `src/` — Java-исходники (сервисы, популяторы, интерцепторы).
    
- `gensrc/` — автоматически сгенерированный Ant-скриптами Java-код моделей данных на основе `items.xml`.
    
- `web/` — веб-модуль (REST-контроллеры, Servlets), если расширение должно отвечать на HTTP-запросы.
    

### localextensions.xml

Файл `localextensions.xml` находится по пути `hybris/config/localextensions.xml` и является главным конфигуратором состава вашей системы. Он указывает платформе, какие именно расширения нужно подключить при сборке.

XML

```
<hybrisconfig xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
    <extensions>
        <!-- Базовые платформенные модули -->
        <path dir="${HYBRIS_BIN_DIR}/modules/commerce-services" />
        
        <!-- Кастомные расширения проекта -->
        <extension name="myprojectcore" />
        <extension name="myprojectfacades" />
        <extension name="myprojectocc" />
    </extensions>
</hybrisconfig>
```

**Особенность порядка вычисления:**

Порядок записи расширений в `localextensions.xml` **не влияет** на порядок их компиляции. Hybris самостоятельно строит граф зависимостей (Directed Acyclic Graph) на основе тегов `<requires-extension>` из файла `extensioninfo.xml` каждого модуля и выполняет топологическую сортировку перед сборкой.

### Build Framework & Apache Ant

Hybris не использует Maven или Gradle для сборки платформы ввиду исторической архитектуры и специфики генерации кода из XML. Вместо них применяется **Apache Ant**.

Все команды сборки выполняются из папки `hybris/bin/platform`.

**Ключевой сценарий работы с Ant:**

1. **Настройка окружения:**    
```Bash
# Загружает переменные среды и подтягивает утилиту ant из состава Hybris
source setAntEnv.sh
```
    
2. **Основные таргеты (команды):**
    

- `ant clean` — очищает скомпилированные `.class` файлы, директорию `gensrc` и временные сборки во всех подключенных расширениях.
    
- `ant all` — запускает полный цикл сборки:
    
    1. Парсит файлы `items.xml`.
        
    2. Генерирует Java-классы моделей данных в папки `gensrc`.
        
    3. Компилирует Java-код (`src` + `gensrc`).
        
    4. Собирает web-артефакты и инжектит аддоны.
        
- `ant initialize` — выполняет жесткий сброс базы данных: удаляет текущую схему SQL, заново создает таблицы на основе `items.xml` и накатывает стартовые данные из ImpEx-скриптов.
    
- `ant updatesystem` — бессрочно обновляет структуру БД (добавляет новые колонки, таблицы и индексацию из `items.xml`), **не удаляя** существующие данные.
    
- `ant extgen` — запуск интерактивного мастера для генерации нового кастомного расширения на базе стандартных шаблонов (templates).
