### **2. Что такое [`extension`](Documents/JAVA/5-Мои_вакансии/INNOWISE/INNO_заметки/2026-09-14_Hybris/_Extension-пример) в `SAP Commerce`? Что обычно находится внутри `extension`?**

**[Extension](Documents/JAVA/5-Мои_вакансии/INNOWISE/INNO_заметки/2026-09-14_Hybris/_Extension-пример) (Расширение)** — это независимый строительный **модуль** приложения. Вся платформа *Hybris* собирается из таких модулей как из конструктора *Lego*.

**Что внутри:**
- `resources/<extname>-items.xml` — описание сущностей базы данных.    
- `resources/<extname>-spring.xml` — объявление Spring-бинов.    
- `extensioninfo.xml` — манифест с зависимостями от других модулей.    
- `src/` — Java-код (сервисы, контроллеры, популяторы, интерцепторы).    
- `gensrc/` — сгенерированные платформой Java-классы моделей.    
- `web/` — REST API эндпоинты (*если модуль отвечает за веб-слой*).    

### **3. Вы пишете, что занимались `Data Modeling`. Где в `SAP Commerce` описывается модель данных?**

Модель данных описывается в *XML*-файле конфигурации конкретного расширения:

**`resources/<extension-name>-items.xml`**

В нем разработчик задает сущности (`<itemtype>`), их поля, типы данных, перечисления (`<enumtype>`) и связи между ними (`<relationtype>`).

### **4. Чем `ItemType` в *Hybris* отличается от `JPA Entity`?**

| **Критерий**       | **ItemType (Hybris)**                                                               | **JPA Entity (Hibernate)**                                   |
| ------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Как создается**  | Описывается в `items.xml`, код классов генерируется автоматически в `gensrc`.       | Пишется вручную на Java с аннотациями (`@Entity`, `@Table`). |
| **Жизненный цикл** | Управляется платформенным `ModelService` и `Persistence Layer`.                     | Управляется `EntityManager` / Hibernate.                     |
| **Динамика**       | Поддерживает локализацию, автоподгрузку атрибутов и runtime-расширение моделей.     | Строго статическая структура таблицы.                        |
| **Идентификатор**  | У всех типов автоматически есть глобальный `PK` (Primary Key), генерируемый Hybris. | Первичный ключ `ID` настраивается вручную через `@Id`.       |

### **5. Что произойдёт после изменения `items.xml`? Нужно делать `Initialization` или `Update`?**

После изменения `items.xml` нужно выполнить **два шага**:

1. **Сборка (`ant all`):** Платформа перечитает `items.xml` и сгенерирует обновленные Java-классы моделей в папке `gensrc`.
    
2. **Обновление системы (`Update System`):**	    
    - **Делаем `Update System` (ant updatesystem / через HAC):** Добавляет новые таблицы, колонки и индексы в БД **без потери существующих данных**.        
    - **`Initialization` делать НЕЛЬЗЯ (только на чистой dev-среде):** Инициализация полностью стирает схему БД и создает её с нуля.


### **6. Что такое [`ImpEx`](Documents/=Knowledge_base=/-=ТЕХНОЛОГИИ=-/Hybris/Вопрос-ответ/_ImpEx) и для чего вы его использовали?**

**[ImpEx](Documents/=Knowledge_base=/-=ТЕХНОЛОГИИ=-/Hybris/Вопрос-ответ/_ImpEx) (Import/Export)** — это текстовый инструмент и язык скриптов в *Hybris* (*на базе CSV*) для массовой работы с базами данных.

**Для чего использовали:**
- Первичная заливка каталогов товаров, категорий, цен и картин.    
- Накат конфигураций и CMS-страниц при релизах на продакшн.    
- Загрузка тестовых данных и пользователей на локальных средах.    

**7. В чём разница между INSERT, UPDATE и INSERT_UPDATE в ImpEx?**
	
- **`INSERT`:** Только создает новые записи. Если запись с таким ключом уже есть — выбрасывает ошибку.
    
- **`UPDATE`:** Только обновляет существующие записи. Если запись не найдена — проигнорирует или выведет предупреждение.
    
- **`INSERT_UPDATE` (Upsert):** Универсальный режим. Создает новую запись, если её нет в БД, или обновляет существующую.    

### **8. Как `ImpEx` понимает, какую запись нужно обновить при `INSERT_UPDATE`?**

`ImpEx` ищет запись по атрибуту с модификатором **`[unique=true]`**.

Фрагмент кода
```sql
INSERT_UPDATE Product; code[unique=true]; name[lang=ru]
; prod_100; Кофемашина
```
_Движок делает внутренний запрос к БД: «Найди мне товар с `code = 'prod_100'`. Если нашел — обнови `name`, если не нашел — создай новый товар»._

### **9. Можно ли через `ImpEx` импортировать `relation` между объектами?**

**Да, можно.** Это делается двумя способами:

1. **Прямо в заголовке сущности** (через указание родительского объекта по уникальному ключу):
    
    Фрагмент кода    
```sql
INSERT_UPDATE Product; code[unique=true]; unit(code)
; prod_100; pieces
```
    
2. **Через явное заполнение таблицы связей (Relation):**
    
    Фрагмент кода    
```sql
INSERT_UPDATE CategoryProductRelation; source(code)[unique=true]; target(code)[unique=true]
; electronics_cat; prod_100
```
    

### **10. Что такое `FlexibleSearch`? Чем это отличается от `SQL`? Пример `FlexibleSearch`-запроса**

**FlexibleSearch** — это объектный язык запросов Hybris (*аналог HQL в Hibernate*).

- **Отличие от SQL:** Запросы пишутся к **объектам и типам Hybris** (`{Product}`), а не к физическим таблицам базы данных. Hybris сам транслирует FlexibleSearch в нативный SQL с учетом мультиязычности и прав доступа.

**Пример:**
```SQL
SELECT {p.pk}, {p.code} FROM {Product AS p} WHERE {p.approvalStatus} = ?status
```

**11. Почему плохо делать SELECT * в FlexibleSearch и вытаскивать тысячи объектов?**

В FlexibleSearch правилом хорошего тона является выборка только первичных ключей: **`SELECT {pk}`**.

**Почему плохо выбирать много объектов сразу:**

1. При выборке всех полей Hybris поднимает из БД не просто строки, а тяжелые Java-объекты моделей (`ProductModel`).
    
2. Выборка тысяч моделей переполняет оперативную память (JVM Heap), вызывает зависания из-за `Garbage Collector` и забивает кэш платформы (`Region Cache`).
    

**12. Если FlexibleSearch стал медленным, как искать проблему?**

1. **Открыть HAC (`Console -> FlexibleSearch`):** Вставить запрос и нажать _Translate_. Посмотреть, в какой нативный SQL-код транслируется запрос.
    
2. **Проверить План Выполнения (`EXPLAIN PLAN`):** Запустить сформированный SQL в консоли БД (Oracle/PostgreSQL) и проверить наличие _Full Table Scan_.
    
3. **Проверить индексы:** Убедиться, что в `items.xml` для полей, участвующих в `WHERE` и `JOIN`, прописана индексация (`<index>`).
    
4. **Проверить проблему N+1:** Убедиться, что в Java-коде данные не дозапрашиваются поштучно в цикле.
    

**13. Что такое HAC? Чем вы реально пользовались там?**

**HAC (Hybris Administration Console)** — веб-консоль администрирования для технических специалистов (`/hac`).

**Чем реально пользовались:**

- `Platform -> Init/Update`: Обновление схемы базы данных.
    
- `Console -> FlexibleSearch`: Отладка и замер скорости запросов.
    
- `Console -> ImpEx Import`: Ручная загрузка и проверка скриптов.
    
- `Console -> Scripting Languages`: Выполнение **Groovy**-скриптов для оперативного анализа данных.
    
- `Monitoring -> Cache`: Ручной сброс кэша платформы.
    

**14. Что такое Backoffice и чем он отличается от HAC?**

- **HAC:** Инструмент **разработчиков и DevOps**. Отвечает за техническое состояние платформы, логи, сборку, базы данных и скрипты.
    
- **Backoffice:** Бизнес-интерфейс для **менеджеров и контент-команды**. Служит для управления товарами (PIM), обработкой заказов (OMS), наценками, скидками и клиентами.
    

**15. WCMS. Объясните структуру: page → content slot → component**

Это трехслойная иерархия управления контентом витрины в Hybris:

1. **Page (`CMSPage`):** Сама страница (например, Главная страница или Карточка товара). Определяет общий каркас и макет.
    
2. **Content Slot (`ContentSlot`):** Выделенная именованная область на странице (например, `HeaderSlot`, `FooterSlot`, `SidebarSlot`).
    
3. **Component (`AbstractCMSComponent`):** Конкретный UI-блок с данными, вставляемый внутри слота (например, `BannerComponent`, `ProductCarouselComponent`, `ParagraphComponent`).

**16. Что такое Staged и Online catalog version в WCMS?**

В Hybris используется версионирование каталогов для безопасности разделения черновиков и боевого сайта:

- **Staged (Черновик):** Рабочая версия каталога. В ней контент-менеджеры создают товары, меняют тексты, баннеры и цены. Посетители сайта её **не видят**.
    
- **Online (Боевая):** Публичная версия каталога. С этой версии витрина магазина читает данные и показывает их покупателям.
    
- **Синхронизация:** Когда изменения в `Staged` готовы, запускается процесс `CatalogVersionSyncJob`, который переносит измененные объекты в `Online`.
    

**17. Как добавить собственный CMS component?**

1. **Описать модель в `items.xml`:** Создать новый `<itemtype>`, унаследовав его от `SimpleCMSComponent` (или `AbstractCMSComponent`), и добавить кастомные поля (например, заголовок, картинка, ссылка).
    
2. **Собрать проект:** Выполнить `ant all` и `ant updatesystem`.
    
3. **Создать Populator / Controller (для Accelerator/JSP) или DTO (для Headless/OCC):** Маппить данные из модели в витринный формат.
    
4. **Зарегистрировать в системе:** Написать ImpEx-скрипт, который создаст экземпляр компонента и привяжет его к нужному `ContentSlot` на `CMSPage`.
    

**18. Что такое AddOn в старом SAP Commerce Accelerator? Чем AddOn отличается от обычного extension?**

- **Extension:** Базовый модуль backend-логики, моделей и API.
    
- **AddOn:** Специальный тип расширения, содержащий UI-ресурсы (JSP, CSS, JS, теги, контроллеры), созданный для расширения функциональности Storefront **без изменения исходного кода самой витрины**.
    
- **Главное отличие:** При сборке ресурсы AddOn-а автоматически инжектятся (копируются) внутрь целевого веб-расширения (`yacceleratorstorefront`).
    

**19. При выполнении ant addoninstall что происходило? Действительно ли выполняли?**

**Да, выполняли.** Эта команда запускалась единоразово при подключении нового AddOn-а к проекту.

**Что происходило под капотом:**

1. Команда прописывала AddOn в зависимости целевого Storefront-модуля в файле `extensioninfo.xml`.
    
2. Регистрировала AddOn в файле `project.properties` витрины (`yacceleratorstorefront.additional.webmodules=...`).
    
3. Настраивала Ant-скрипты так, чтобы при каждом последующем `ant all` ресурсы из папки AddOn автоматической копировались в папку `web/webroot` витрины.
    

**20. Как в SAP Commerce устроен Solr?**

Solr в Hybris — это отдельный полнотекстовый поисковый движок, интегрированный через модуль `solrfacetsearch`.

**Схема устройства:**

- **Solr Server:** Запускается как отдельный процесс (standalone или SolrCloud).
    
- **Indexed Type (`SolrIndexedType`):** Конфигурация в Hybris, описывающая, какую сущность индексируем (например, `Product`).
    
- **Value Providers:** Java-классы (`IndexedPropertyValueProvider`), которые извлекают данные из `ProductModel` (цену, категории, остатки) и превращают их в поля документа Solr.
    

**21. Что такое full index и update index? Когда какой нужен?**

- **Full Index (Полная индексация):** Полностью очищает индекс Solr и пересоздает его с нуля, заново считывая все товары из БД.
    
    - _Когда нужен:_ Изменилась структура полей в Solr, добавился новый Value Provider, либо индекс был поврежден.
        
- **Update / Incremental Index (Частичная индексация):** Обновляет только те товары, которые изменились с момента последнего запуска.
    
    - _Когда нужен:_ Регулярный запуск по расписанию (CronJob) в течение дня для актуализации цен, остатков и статусов товаров.
        

**22. Что именно вы подразумеваете под “прогревом индекса перед пиковой выдачей”?**

**Прогрев индекса (Index Warm-up)** — это автоматический прогон серии поисковых запросов по новому индексу Solr **до того**, как на него переключат реальный трафик пользователей.

**Зачем это нужно:** При первом поиске Solr строит внутренние кэши (`filterCache`, `fieldValueCache`). Если пустить пиковый трафик на "холодный" индекс, сервер ляжет от высокой нагрузки и таймаутов. Прогрев заполняет кэши Solr заранее.

**24. Что такое Search & Navigation?**

Это изкоробочный E-commerce функционал Hybris на базе Solr, отвечающий за:

- **Поиск по сайту:** Полнотекстовый поиск с поддержкой синонимов, опечаток (fuzzy search) и автокомплита.
    
- **Навигацию и фасеты (Facets):** Фильтрация товаров в категориях по бренду, цвету, размеру, цене.
    
- **Сортировки и бустинг:** Настройка правил продвижения товаров (например, поднимать вверх товары с высокой маржой).
    

**25. Где вообще в SAP Commerce может храниться цена?**

1. **PriceRowModel (Европа-1 / Europe1 Price Factory):** Стандартная таблица цен Hybris. Поддерживает привязку цены к товару, валюте, единице измерения, группам клиентов, диапазонам количеств (градация цен) и датам действия.
    
2. **Внешняя ERP (на лету):** В B2B-сегменте цена часто не хранится в Hybris, а запрашивается по REST/SOAP из SAP S/4HANA в момент открытия страницы или корзины.
    

**26. Почему комиссия финансового инструмента была реализована именно через Commerce Pricing?**

Реализация комиссии через **Commerce Pricing (`CalculationService` / `Europe1`)** позволяет гармонично встроить её в стандартный жизненный цикл расчета корзины:

- Комиссия учитывается как скидка/наценка (`DiscountRow` или кастомный `TaxRow/PriceFactoryHook`).
    
- Сумма автоматически пересчитывается при любых изменениях корзины.
    
- Это исключает ошибки разбега итоговых сумм при передаче заказа в эквайринг и ERP, так как не приходится переписывать итоговую сумму вручную "поверх" системы.
    

**27. Чем Promotions отличаются от Coupons?**

- **Promotions (Промо-акции / Rule Engine):** Логика и правила предоставления скидки (например: _"Скидка 10% на все ноутбуки при покупке от 50 000 руб"_). Рассчитываются автоматически при выполнении условий.
    
- **Coupons (Купоны):** Буквенно-цифровой код (например, `SALE2026`), который пользователь вводит вручную. Купон сам по себе не дает скидку — он служит **триггером (условием)** для активации привязанной к нему Promotion.
    

**28. Как технически работает B2B Promotions “под условия договора”?**

1. **Учет структуры:** У B2B-клиента есть привязка к компании (`B2BUnit`) и контракту (`ContractModel`).
    
2. **Кастомное условие в Rule Engine (Drools):** Создается кастомный `RuleConditionDefinition`, который умеет извлекать атрибуты договора текущего авторизованного `B2BCustomer`.
    
3. **Выполнение правила:** При расчете корзины движок правил (`PromotionEngine`) проверяет: если `cart.user.b2bUnit.contractType == 'PREMIUM'`, применяется соответствующее правило скидки.
    

**29. Как устроен CronJob в SAP Commerce? Что такое Job, CronJob и Trigger?**

- **Job (`ServicelayerJobModel`):** Сам исполняемый Java-код бизнес-логики (реализует интерфейс `ItemJobPerformable`).
    
- **CronJob (`CronJobModel`):** Экземпляр/настройки запуска. Содержит параметры выполнения, статус (`RUNNING`, `FINISHED`), логи и результат.
    
- **Trigger (`TriggerModel`):** Расписание запуска (Cron-выражение, например `0 0 2 * * ?` — каждый день в 2 часа ночи), привязанное к `CronJob`.
    

**30. Как создать свой CronJob?**

1. **Написать Java-класс:** Создать класс, унаследованный от `AbstractJobPerformable<CronJobModel>`, и реализовать метод `perform(cronJobModel)`:
    
    Java
    
    ```
    public class MyCleanupJob extends AbstractJobPerformable<CronJobModel> {
        @Override
        public PerformableResult perform(CronJobModel cronJob) {
            // Логика задачи
            return new PerformableResult(CronJobResult.SUCCESS, CronJobStatus.FINISHED);
        }
    }
    ```
    
2. **Зарегистрировать Spring-бин:** Объявить класс в `*-spring.xml`.
    
3. **Объявить Job и CronJob через ImpEx:**
    
    Фрагмент кода
    
    ```
    INSERT_UPDATE ServicelayerJob; code[unique=true]; springId
    ; myCleanupJob ; myCleanupJob
    
    INSERT_UPDATE CronJob; code[unique=true]; job(code); singleExecutable
    ; myCleanupCronJob ; myCleanupJob ; false
    
    INSERT_UPDATE Trigger; cronJob(code)[unique=true]; cronExpression
    ; myCleanupCronJob ; 0 0 0 * * ?
    ```
